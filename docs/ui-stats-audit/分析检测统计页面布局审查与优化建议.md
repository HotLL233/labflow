# 分析检测统计页面布局审查与优化建议

审查日期：2026-11-09。基线：根 README 指定的正式版本 v2.4.11。

本轮优先参考：[保留现有习惯版](LabFlow-分析检测统计布局参考-保留现有习惯.html)。根据最新要求，保留16个报表卡片的原名称、顺序和进入方式，六张指标卡及其迷你图、入口卡图形、专业图表和工作量三线趋势全部保留。报表仍按“筛选 → 图表 → 表格”查看，图表默认展开，手机常用筛选保持展开。

上一版参考：[LabFlow-分析检测统计布局参考.html](LabFlow-分析检测统计布局参考.html)，继续保留用于对比。以下原审查事实不变；其中分组导航、图表按需展开和手机折叠筛选等建议，已由本轮“保留现有习惯”的要求收窄，不作为当前实施方向。

两版均为单文件离线参考，全部使用虚构数据，未接入实际系统。保留现有习惯版重点整理间距、对齐、控件尺寸和记录卡片，提供折线／柱状／饼图切换、适用指标、趋势周期（日／周／月）、10项分类维度及显示设置预览；专业报表公式、权限和导出内容仍以正式系统为准。入口卡右下角图形是静态标识，六张指标卡的迷你图使用示例汇总数据。

结论：可以优化，重点是让用户更快找到所需报表、确认统计范围并看到数据。目前的主要问题是顶部内容层层堆叠、专业入口难区分，以及部分配置和显示状态未连通。现有统计能力已经比较丰富，不需要再堆更多卡片。

本文件是审查与建议，没有修改应用源码、统计逻辑、权限或业务数据，也不代表已实施和发布。

## 1. 当前结构与已有能力

目前有两条主要路径：

- `/stats`：六张指标卡、16个专业报表入口；进入具体报表后，继续显示顶部六卡，再显示筛选、图表和表格。
- `/stats/workload`：我的工作量／授权范围汇总，包含人员汇总与明细、类型汇总、人员类型矩阵、趋势和来源明细。

已实现的能力应继续使用：人员权限范围、方法／仪器下钻、辅助类别／事项下钻、历史来源追溯、当前条件导出，以及类型和辅助记录的表格／手机卡片样式配置。顶部统计卡片的独立名称、颜色配置也已生效，不属于本轮发现的未接入配置。

工作量继续按数量与系数快照计算；辅助工作保持独立配置和账号归属，不参与金额计算，不分摊检测实验室、项目、方法和仪器。

## 2. 画面核查结果

使用该版本生产静态文件，在虚构接口下核查10个视图，每个分别检查1366×768桌面和390×844手机布局。测量前归零滚动位置，以下坐标均以页面顶部为起点。

| 场景 | 桌面 | 手机 | 对使用的影响 |
| --- | --- | --- | --- |
| 统计门户 | 页面约988px高 | 约3176px高；人员工作量入口标题约在3015px | 常用入口和大量专业报表同级，手机要长距离滚动 |
| 按周统计 | 第一行表格约在1044px | 第一行表格约在1719px | 首屏看不到表格数据 |
| 检测人记录 | 第一行约在1072px | 第一行约在1767px，表格宽约1163px | 核对记录需要纵向滚动，手机还要横向移动 |
| 授权范围汇总 | 第一行分类汇总约在764px，来源明细标题约在1925px | 第一行分类汇总约在1067px，来源明细标题约在2187px | 多组汇总、矩阵、趋势依次叠放，明细位置较深 |

这些是指定视口和虚构数据下的布局测量，不是实际数据库的业务统计结果或响应速度测量。

## 3. 具体问题与建议

| 优先级 | 问题 | 建议 |
| --- | --- | --- |
| 优先 | 指标卡、页面标题、筛选、图表层层占用首屏；六张178px高指标卡在子报表重复出现 | 门户使用紧凑指标；进入报表后切成当前报表的紧凑摘要。图表与明细可切换，或提供整图收起。保留查看完整指标及已有自定义的能力 |
| 优先 | 辅助列表有记录，上方公共图表却显示“当前条件下暂无数据” | 对没有数据适配的辅助视图先不显示公共图表。确需展示时，接入同一授权、时间及筛选范围的完整辅助汇总，不能用本页记录代替全量统计 |
| 优先 | 管理后台可设置统计页标题、统计卡和图表区，但实际统计页没有读取对应的 `layout_stats` | 接通已有配置键和结构，明确每项实际控制范围。保留已保存值及独立 `stats-cards` 配置，避免再新增一套同用途设置 |
| 较高 | 专业门户默认今天，工作量汇总默认本月；门户指标旁没有清楚展示日期，跨入口仅传人员、不带日期 | 在所有视图持续显示当前日期与授权范围；跨入口携带已选条件。先保留当前默认口径，不能借排版整改直接改变统计日期 |
| 较高 | 16个入口同层级；“检测人记录”“检测人-汇总（原始记录）”“检测人汇总表（含系数）”“人员工作量汇总”不易区分 | 按人员工作量、业务分类、专业报表分组；常用查询靠前，每项写清“看什么、按什么统计”。保留原报表、权限和导出映射，仅改善导航 |
| 较高 | 日期、部门、历史范围、业务筛选和导出报表选择混排；窄屏频繁换行 | 分成常用筛选、扩展筛选和导出操作。显示已选条件及重置入口；手机用筛选面板并保留条件摘要，不折叠实际业务记录 |
| 较高 | 点击页面靠下的入口后保留旧滚动位置；刷新回统计门户 | 用路由或查询参数保留报表与筛选状态，进入报表定位标题，返回时恢复入口位置。参数仍必须经过现有权限校验 |
| 一般 | 顶部指标显示可点击，但部分账号没有对应专业报表权限 | 复用已有 `canOpenTab` 控制快捷入口的可点击状态。当前已有无权限视图回退保护，不应把此问题描述成已确认数据越权 |
| 一般 | 检测人记录手机仍使用宽表；其他报表有逐字段长卡片，辅助／类型页则已有三四行配置卡片 | 在适合逐条查看的页面复用已有三四行卡片模式；矩阵保留横向表格。主次字段、操作位置、字号和边框保持可配置 |
| 一般 | 渐变标题、大数字、每卡小图、阴影与悬停效果同时争夺注意；部分入口仅支持鼠标点击 | 默认视觉收敛为现有业务蓝加中性色，重要数字和图表承担强调。卡片使用现有按钮语义或补齐键盘操作、焦点和选中状态；保留用户自定义颜色 |

### 显示与操作中需要特别澄清的地方

- 现有导出支持多张报表，默认选择检测记录明细、检测部门—送样部门汇总，不会自动等于当前打开的报表。这不直接证明导出数据错误；建议把按钮写成“导出所选2张报表”，选择项放进导出设置，避免用户误解。
- 数量、记录数、管理分值、系数分和工作量不能直接改成同一名称。显示标签应结合各报表实际公式说明，保留历史口径。
- 辅助工作应作为独立分组展示，但仍计入允许查看的人员公共工作量；不能为了分组好看把它错误归入液相、气相等检测类型。

## 4. 推荐布局方向

产品：检测人员查个人记录，组长和管理员核对授权范围工作量与业务来源。

气质：严谨、紧凑、便于核对。

场景：实验室统计台账，长时间查看表格和分类数据。

视觉重点：当前工作量数字和正在查看的一组分类／趋势内容。

统一细节：日期范围、授权范围和统计口径始终可见。

### 门户

1. 标题与当前日期、可见范围放在同一区域；“我的工作量／授权范围”靠近标题。
2. 六张指标改成紧凑摘要，默认高度建议80–96px；手机两列排列，减少重复小图占高。自定义字体较大时允许增高，不能截断内容。
3. 常用入口优先展示：我的工作量、人员汇总、类型汇总、检测人记录、辅助工作记录。
4. 其余专业报表按任务分组，保留完整入口与权限过滤。分组不代表合并统计查询或删除旧报表。

### 具体报表

建议从上到下安排为：

```text
返回入口  /  当前报表标题                         导出所选报表
当前日期范围 · 查看范围 · 已选条件
常用筛选                                        更多筛选 / 重置
当前报表紧凑指标
人员汇总 / 类型汇总 / 来源明细 / 趋势等内容导航
当前选中的表格、卡片或图表
分页与当前范围说明
```

内容导航按报表已有功能提供，不为每张报表强加同一组标签。保留检测人记录中已有的辅助工作编辑、删除和来源查看入口，以及各自的权限判断。

工作量汇总目前已有人员／类型两层切换，可在此基础上把矩阵、趋势与来源明细做内容分区，减少整页连续堆叠。分区切换保留筛选、人员和必要的分页状态。

桌面可将图表与小型分类表并列，大表独占宽度；手机以三四行记录卡片为主，矩阵等比较型数据保留可横向滚动的表格。不要用全局缩小字号代替布局调整。

建议验收目标：1366×768下常用明细首屏能看到表头和至少一行记录；390×844下能看到查询范围、关键指标及当前内容入口。具体高度需在保留自定义配置后实测，不作为已完成效果。

## 5. 建议整改顺序与保留要求

第一步，修正有误导的显示状态：辅助空图表、未接入的页面布局配置、无权限仍可点的指标卡。

第二步，调整公共排版：紧凑摘要、筛选分区、明确导出含义、切换后的滚动和刷新状态。

第三步，整理门户分组与工作量汇总内容导航，统一手机记录卡片和键盘交互。

全过程保留：

- 当前后台与服务端权限、人员归属和账号标识；隐藏入口不能代替服务端授权。
- 历史系数快照、业务日期、来源链、历史待确认范围及各类统计公式。
- 辅助工作独立配置、不分摊实验室、不计金额的规则。
- 列显示／宽度、字号、边框、按钮状态配色、排序和手机卡片等已保存配置；无明确理由不另起配置键。
- 现有报表、金额权限及Excel导出内容。导航整理不能改变计算口径。

`StatsCards`、`PreviewTable`等是共享组件。后续实现须先核对其他调用方，控制分析检测的改动范围，并检查研发送样等既有页面，避免全局样式影响正常功能。
