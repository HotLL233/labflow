# 后台布局评估与优化方案

评估日期：2026-11-06。基线：根 README 标识的正式版 v2.4.7。

后续状态：用户已于 2026-11-06 确认本方案并授权实施，开发版本 v2.4.8。下述“仅方案”和113项检查描述的是原型评估阶段；正式页面验证与发布结果以版本安装包说明为准。

本轮仅交付设计评估和离线 HTML，不改正式前端、接口、数据库、权限或版本，不生成安装包、不发布。

打开同目录 [HTML 参考方案](LabFlow-后台布局优化参考方案.html)。菜单可切换管理总览、主数据、方法、辅助事项、角色、通知、字段与备份样例。所有数字、账号与记录均为虚构示例；编辑仅在内存生效，刷新恢复。示例 CSV 仅演示下载，不冒充正式 Excel 模板；文件选择不解析、不上传。

## 1. 结论与设计方向

可以优化，重点是减少重复层级、稳定操作位置和改善窄屏排版。现有后台已具有四组管理导航、权限过滤、侧栏收起和多种自定义能力，适合在此基础上整理，无需更换 UI 框架或重建业务流程。

本次检查同时阅读源码，并将正式版 `backend/static` 在隔离浏览器内打开。所有 `/api` 请求由本地虚构夹具应答，未启动业务服务、未连接现场数据库、未使用真实账号。截图可证明默认配置下的排版，不代表现场自定义主题或真实数据验收。

设计方向：

- 产品：供实验室管理员和获授权人员持续维护主数据、权限与业务配置的管理端。
- 气质：克制、明确、便于扫描。
- 场景：实验室工作台；白色数据区、低饱和灰色边界，保留现有导航蓝色 `#1769aa`。
- 重点：主数据名称、系数和启停状态；通知失败与处理状态。颜色表达业务含义，不装饰所有区域。
- 统一细节：左侧分组顺序不变，页头只保留一个标题，返回按钮始终有边框，工具栏按同一基线对齐。

## 3. 参考稿包含的调整

| 页面 | HTML 中展示的排版 | 保留的业务边界 |
| --- | --- | --- |
| 管理总览 | 两列分组索引；侧栏紧凑且可收起；手机抽屉导航 | 四类分组及各入口关系；最终由权限和已保存菜单配置决定可见性 |
| 主数据预览 | 左侧工作表目录＋右侧筛选及表格；标题不重复 | 只读预览、导入、导出及辅助事项配置均保留 |
| 检测方法 | 对齐名称、仪器、类型、系数和单价；手机三行记录 | 稳定方法身份、改名不换 ID、历史系数不自动更新 |
| 辅助工作 | 事项／区域／分类／系数列；“区域管理”与“新增事项”并列 | 独立配置；不复用检测类型、不分配实验室、不计算金额；前端不展示事项 ID |
| 角色与权限 | 标题与动作分层；手机三行记录与底部动作 | 固定角色、模板、自定义角色、权限矩阵与数据范围均沿用 |
| 通知中心 | 同一后台外壳；页内定位；5列概览；配置入口紧凑化 | 身份绑定、模板动态字段、渠道、规则、事件、发送记录及补发原因不删除 |
| 录入字段 | 宽屏字段表＋预览；小屏上下布局 | 类型级表单／列表／导出／必填规则、顺序、列宽、系统字段保护及自定义能力保留 |
| 数据备份 | 文件列表优先；云端和自动备份有明确入口；恢复走确认窗口 | 既有下载授权、备份校验、恢复权限、凭据隔离与云端任务语义不改变 |

HTML 中状态点与文字同时出现，避免仅靠颜色传达信息；方法和角色在手机显示为紧凑三行记录，减少表格列被挤窄后的逐字换行。需要比较完整字段的主数据只读工作表仍提供局部横向滚动，不强行缩小到看不清。

## 4. 建议尺寸与交互

| 元素 | 建议 |
| --- | --- |
| 桌面页头 | 主标题24px，描述13px；标题与动作同排，空间不足自然换行 |
| 手机页头 | 标题20px；动作独占下一行；不按视口连续缩放字号 |
| 正文与辅助文字 | 业务内容13～14px；说明与元数据12px；继承现有可配置字号 |
| 间距 | 4px基准；控件间8～12px，分组间16～24px |
| 桌面操作控件 | 高36px；同行按钮等高；图标16～18px |
| 触屏操作 | 筛选及主要输入44px；非主要行内文字动作需扩大命中区，正式实施优先44px |
| 边框与圆角 | 浅灰1px边界、4px控件圆角；沿用管理员配置，不覆盖既有自定义边框与状态配色 |
| 表格 | 数据区独立横向滚动；名称优先分配宽度，数值右对齐；不全局强制隐藏溢出 |
| 返回 | 图标＋短文字＋可见边框；手机允许独立一行，保留清晰返回层级 |
| 操作反馈 | 区分未操作、处理中、已完成、失败；失败保留原因，按钮处理中禁用 |
| 字段编辑 | 输入错误在弹窗内提示；未保存草稿离开需确认，正式实施沿用或补足原有防丢失机制 |
| 动效 | 仅保留轻微颜色反馈；尊重减少动态效果设置；不在页面或卡片反复漂浮 |

本稿不新建正式外观配置体系。后续落地应优先复用 `main.tsx` 的 MUI theme、`designTokens.ts`、现有列／按钮配置，再提取最少的管理页头与工具栏样式。不能使用全局 `!important` 抹掉用户设置。

## 5. 落地顺序与防回归

1. 新递增版本中整理管理外壳：导航、页头、返回、窄屏换行；独立管理路由统一外壳，但保持当前 `ProtectedRoute` 与各页面二次权限判断。
2. 整理主数据预览及方法／辅助事项显示：优先改布局，不改导入导出协议，不把只读预览变成直接编辑。
3. 整理通知与字段页：将完整配置放入原编辑流程，保留隐藏字段恢复、刷新时草稿保护、补发原因和独立渠道状态。
4. 在管理员、有部分管理权限的组长、普通用户下检查入口；验证手机、1366px桌面和大屏，补齐空态、加载、长名称及错误态。
5. 完成正式前端检查与相关业务回归后，按现行版本和发布门禁正式交付；该步骤需要后续实施授权，本稿不是已开发版本。

必须保留：所有既有权限与数据范围、历史来源与快照、辅助去重口径、稳定身份、导入引用保护、历史修正预览确认、默认近30天加载与完整授权范围筛选、按钮前后状态配色、列宽／显隐／位置／字号／边框等自定义配置。
