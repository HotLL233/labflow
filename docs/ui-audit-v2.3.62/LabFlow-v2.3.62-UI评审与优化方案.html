总体结论

当前界面不是审美问题，是缺少设计系统。全站 882 处硬编码色值、225 个唯一十六进制颜色、9 档小字号、5 种圆角并存，而主题层只被引用 25 次，后台「主题设置」实际上形同虚设——管理员改品牌色，页面基本不跟。

核心资产要保住：记录表的 Excel 化样式引擎（recordTableStyle.ts，个人视图 → 全局 → 默认三级解析）是这个产品最有价值的界面能力，本次方案不推翻、不重写，只把它接入统一的 token 层。

优化路径按「先止血、再收口、后品牌」三步走，每步可独立发版、独立回退，符合版本隔离口径。

三处关键证据

只列最需要当场确认的三条，其余可在源码中按行号复核。

① 主题层只覆盖 4 个变量

ThemeSettings 声明了 8 个可配字段，但进入 MUI theme 的只有 4 个，且没有任何组件消费它们。

// main.tsx:27-30
const primary = themeSettings?.primaryColor || '#667eea';
const secondary = themeSettings?.secondaryColor || '#764ba2';
const bg = themeSettings?.bgColor || '#f8fafc';
const radius = themeSettings?.cardRadius ?? 2;

// 反差：业务页面里的绝对色值
#2e7d32 × 77   #1976d2 × 54   #f4511e × 21

② 登录页根本不读主题设置

后台可配置 loginBg 与 loginButtonColor，但登录页把两者都写死了，因此这两个设置项永远无效。

// LoginPage.tsx:90
background: 'linear-gradient(135deg,#f0f4f8,#e8f5e9)'

// LoginPage.tsx:195
bgcolor: '#f4511e'

// 该文件全文无 themeSettings 读取
补充一条同类缺陷：ErrorBoundary 与 404 页（App.tsx:35、38）用内联样式写死 #1976d2 蓝，既不随主题，也不符合其他页面配色——错误态恰恰是最不该露出「另一套皮肤」的地方。

05

优化方案：三层 Token

原则是「原始值 → 语义 → 组件」单向引用，业务代码只允许使用语义层。落地方式为新增一个 designTokens.ts 并在 MUI theme 中扩展，不改业务逻辑、不引入新依赖。

层级定义用途
L1 原始值--green-50 … --green-900 / --neutral-0 … --neutral-900 / --amber / --red / --blue只允许在 token 文件出现，页面禁止直接引用
L2 语义brand / brand-hover / brand-soft / surface / surface-sunken / border / text-primary / text-secondary / text-muted / success / warning / danger / info组件与页面唯一可用的颜色名
L3 组件button.primary.* / table.header.* / card.* / chip.status.* / nav.active.*MUI components 覆盖层，统一样式出口

色彩：一个品牌色 + 四语义色

建议品牌主色 #2E7D32（达标 5.12:1、现网出现 77 次、贴合检测/安全语义）。紫蓝 #667eea 退出正文用途，仅可作为渐变辅助。

语义色与品牌色彻底解耦：成功用 #15803D，警告 #B45309，危险 #C62828，信息 #1D4ED8；每个语义色配套 soft 底色用于 Chip/Alert。

橙色 #f4511e 降级为「需要注意」的强调色，不再充当登录主按钮。

字号：6 档阶梯

12 / 13 / 14 / 16 / 20 / 28（px），行高分别 18 / 20 / 22 / 24 / 28 / 36。

现有 0.68–0.875rem 的碎片统一并入 12 与 13 两档；表格辅助字号保留现有可配置能力（auxFontSize 12 起步），不破坏后台调字号的入口。

中文栈补齐 Microsoft YaHei / PingFang SC，避免 Windows 走 sans-serif 兜底导致的行高漂移。

圆角：3 档 + 1 例外

2px 数据面（表格、输入、Chip）；8px 容器面（卡片、弹窗、登录卡）；999px 胶囊（导航 pill、状态徽标）。

删除 6px / 12px / 16px / 24px 四类特例。后台 cardRadius 仍可调，但只在 2–12 区间给出预览约束，防止配出与体系冲突的值。

阴影：2 级

level-1 静止卡片：0 1px 2px rgba(16,32,20,.04), 0 1px 8px rgba(16,32,20,.04)；level-2 浮起/弹窗：0 2px 4px rgba(16,32,20,.05), 0 8px 24px rgba(16,32,20,.07)。

取消彩色阴影（当前 0 8px 32px ${border}1f），阴影只表达高度，不表达品牌。

06

落地路线

三个阶段各自独立发版、独立回退，不合并成一次大改。每阶段结束后按第 07 节的可测指标验收。

S1 止血低风险

修掉三处硬伤，不动视觉语言

  • 放开 viewport 缩放限制，maximum-scale 移除、user-scalable 置 yes
  • 修正三组不达标对比度：#999→#6B7A70；登录按钮改深一档橙 #C2410C；紫蓝仅保留大字号用途
  • 登录页接入 themeSettings，让 loginBg / loginButtonColor 真正生效（这是兑现既有功能承诺，不是新功能）
  • ErrorBoundary / 404 页改读主题色，去掉内联 #1976d2

风险：极低。均为局部替换，不触碰表格引擎与业务逻辑。

S2 收口中风险

建 token 层，按模块替换硬编码

  • 新增 src/theme/designTokens.ts 与 createAppTheme()，扩展 MUI components 覆盖
  • 替换顺序按收益排序：记录表 → 表单页 → 门户与导航 → 管理后台
  • 圆角与字号收敛：'2px' 归入 token、删除 6/12/16px 特例、登录卡 16px→8px
  • 表格样式引擎保留：DEFAULT_RECORD_TABLE_STYLE 的默认值改为引用 token，解析逻辑一行不动

风险：中。每模块替换后需跑该模块既有测试（前端 122 项测试基线），按模块提交便于定位回归。

S3 品牌需决策

统一识别与信息架构

  • 品牌名二选一：对外统一「知微 LabFlow」或统一「样品管理系统」，四处置同名
  • logo 去掉「方正舒体」，改系统黑体 + 字距，或引入 1 个开源中文字体子集（需评估体积）
  • 移动端底栏改 3+1（送样 / 登记 / 记录 / 我的），「关于」并入「我的」
  • 首页卡片升级为带数量的入口列表，或保留卡片但补信息层
  • 预留暗色模式：token 层先行，palette.mode 后续接入

风险：需产品决策（命名、导航结构）。建议先出静态稿确认，再进入编码。

08

明确不做的事

保留

保住 记录表 Excel 化样式引擎（行高/列宽/条件格式/操作色/个人视图三级优先级）——这是产品核心竞争力，只接入 token，不重写。

保住 现有业务交互与权限逻辑、字段与流程一律不动。

不做

不引入新的 UI 组件库（Ant Design / shadcn 等），继续用 MUI，避免双体系。

不做整站改版式重构、不改路由与数据契约、不新增未经确认的功能模块。

复核方式：本报告所有行号对应 source/LabFlow-PostgreSQL-v2.3.62/frontend；色值、圆角、字号统计由正则扫描 src/**/*.ts(x) 得出。本次仅新增评审文档，未修改任何源码。
待确认：品牌主色是否采用 #2E7D32；品牌名统一为哪一个；移动端底栏是否按 3+1 调整。三项确认后即可进入 S1。
