# v2.5.2 AI 授权代办

状态：本地实施、分层验收、Windows两包/Release/GHCR正式发布及正式文件取回核验均已完成。

## 使用方式

管理员在“系统管理 → AI 助手 → 助手与权限”分别启用“本人通知已读”和“预览后确认提交”。新增开关默认关闭；原角色仍需拥有 `ai:use` 及相应业务权限，升级不补授资格。模型仍需通过原 hi 和流式工具测试。

使用者打开头像旁的助手，在“业务授权与范围”允许本次业务辅助，再按需要分别允许本人通知已读、准备确认提交。新会话或账号、模型、权限变化后重新授权；允许查询和草稿不等于允许正式提交。

- 通知：可查询本人通知，按明确通知标记已读，或将调用开始时本人的全部未读通知标为已读。原角标及时刷新。已读不执行取样、检测完成、审批或群消息撤回。
- 填报：说明研发送样、样品信息登记、检测工作量或辅助工作内容。助手检索原权限可用主数据、真实人员与当前字段，信息不完整时继续补充。准备后展示批量摘要，由用户点击一次“确认提交”。每批最多 20 条。
- 来源工作量：明确原送样记录，继续使用研发送样或样品信息登记原记录内的工作量接口，保留原方法、实际计量方法、人员、日期和来源数量限制。
- 原草稿带入表单和原页面手工录入入口继续可用。

## 数据与执行规则

准备预览只读业务库，服务端核对必填项、人员、方法与系数、默认金额倍率和单价；辅助工作独立配置，不分摊实验室和金额。确认时再次按原权限与原业务接口验证，不根据方法名称猜测身份，不改历史快照。

每份预览绑定当前账号、AI 配置修订和固定内容，10 分钟有效。配置、方法、人员或来源绑定变化后需重新准备；来源剩余数量在每条提交时复核，容量足够的同源分批录入可继续，超量拒绝。模型只获得已准备摘要，确认身份只交给当前用户界面；模型没有确认提交工具。

确认使用数据库状态领取，每条保存实际成功、失败或结果未知。重复点击读取同一结果，已成功记录不重复提交；批次不是跨业务记录的整批事务，可能部分成功。连接中断先查询执行结果；进程中断或确实无法判断的条目标注“结果未知”，不能直接自动重试，需在原记录中核对。原业务提交、AI 辅助操作者和真实业务人员分别保留审计。

本次范围不包含删除、修改历史记录、代取样、检测完成、权限维护、主数据导入、备份恢复或直接发送外部通知。正常业务提交仍可触发原来已经配置的通知规则。
