# AI Agent 配置与语音业务助手方案

日期：2026-11-13。以当前正式版 **v2.4.14** 为基线。本文件及配套 [HTML 参考](LabFlow-AI-Agent与语音助手参考.html) 是待实施方案，不表示正式软件已具备这些功能。

建议采用“**头像旁入口 + 右侧业务助手 + 管理员统一配置**”。送样人继续按原表单提交，检测人继续按原方法和数量录入；助手帮助找功能、查数据、整理信息和生成可复核草稿，不建立另一套业务规则。

## 1. 页面与助手形象

- 入口紧邻右上角头像，显示根据程序图标设计的蓝色实验瓶助手和“AI 助手”；窄屏只显示图标，保留文字提示及无障碍名称。公告、通知、头像各自独立。
- 桌面打开约 440px 的右侧栏，可放大；手机全屏。保留原页面、筛选、滚动与未提交输入，关闭助手可以继续当前操作。
- 形象沿用现有图标的深蓝、浅蓝、实验瓶和图表，增加简洁表情，稿件见 [助手形象.svg](助手形象.svg)。助手形象不替换应用图标，不更改程序内品牌。不用闪烁或持续跳动吸引注意。
- 常显区只有对话、输入、语音和发送；“辅助填报送样信息”“总结我的工作量”“如何操作”作为简短起步入口。上下文、模型名称和权限说明按需展开，避免再次堆积字段。
- 默认不附带整页数据。明确显示本次正在使用的记录、日期范围和数据范围；所选记录须在发送和调用时重新校验权限。
- 会话绑定当前账号。退出、切换账号、公共账号切换实际业务人员或权限变化时，清理不再适用的上下文和草稿，不把个人会话继续展示给下一位公共账号使用者。

## 2. 管理员配置：借鉴 CC Switch 的流程

后台“系统配置 → AI 助手”分为“模型服务”“助手与权限”“语音输入”三页签。用户管理仍只维护账号归属与角色；AI 使用资格放角色权限，模型密钥不出现在用户页。

### 2.1 多上游与模型发现

供应商列表展示名称、协议、默认模型、启用状态及最近测试结果。编辑常显字段为名称、协议、接口地址和密钥；超时、并发等放高级设置。

1. 管理员填上游地址、协议与密钥，页面显示将请求的完整接口地址，防止重复拼接 `/v1/v1`。
2. 点击“获取模型”，服务端调用该协议的模型列表接口；支持分页、搜索和勾选，显式显示未取完、失败页或截断状态，不能只取第一页却称“全部模型”。
3. 将选中模型加入可用列表，设置一个默认对话模型。模型 ID 保留上游原值，显示名称可以修改；模型列表失败或服务不支持列表时，可手填 ID。
4. 刷新结果显示来源和获取时间，失败保留已有配置；未返回某模型只提示复核，不自动删除旧配置或改变默认模型。

首版建议适配以下常用协议，而不是把任何 URL 都当 OpenAI 兼容：

| 协议 | 模型列表 | 对话测试 | 注意 |
| --- | --- | --- | --- |
| OpenAI 兼容 | 通常为 `/v1/models` | 供应商实际支持的 Chat Completions 或 Responses | 两种对话接口需明确选择；兼容服务未必支持模型列表、工具或音频 |
| Anthropic | `/v1/models`，按返回游标分页 | Messages | 密钥头、版本头和返回格式不同 |
| Ollama 原生 | `/api/tags` | `/api/chat` | 解析 `models[]`，不假定为 OpenAI 的 `data[]` |

模型能力区分“管理员声明”和“实际测试结果”。手工勾选工具调用，并不会让上游获得工具能力；未通过工具测试的模型可用于普通问答，但不启用业务工具。

CC Switch 官方文档支持获取、搜索、多选添加和手工模型 ID。其当前“Connectivity Check”只检查地址是否可达，**401/403/404/5xx 也可能记为可达**，不等于密钥或模型可用。LabFlow 应借鉴配置流程，同时明确拆分下列测试，不能共用一个“正常”绿灯。[官方依据 1–3]

### 2.2 分开测试，不以 HTTP 200 代替可用性

| 按钮 | 验证内容 | 结果展示 |
| --- | --- | --- |
| 检查地址 | DNS、连接、TLS、超时、HTTP 响应 | “地址可达，鉴权尚未验证”等准确状态；4xx/5xx 不写成模型正常 |
| 获取模型 | 列表接口及该次请求的鉴权、分页和响应结构 | 模型数量、来源、时间；失败区分 401/403、404/405、格式和超时 |
| 发送 hi | 指定模型的一次真实最小对话 | 实际回复、模型、耗时和错误原因；空回复或结构错误不算通过 |
| 流式测试 | 分块输出、正常结束及取消 | 首段耗时、完整耗时；不只看首次建立连接 |
| 工具测试 | 调用无业务副作用的测试工具并读取返回 | 工具名、参数校验、返回后继续回答；不创建样品、工作量或通知 |
| 测试语音 | 上传短测试音频到独立语音服务 | 可编辑识别文本、耗时、格式或服务错误 |

“发送 hi”等实际调用在按钮旁标明可能产生供应商费用；管理员主动触发，不自动轰炸全部模型。测试结果绑定协议、规范化地址、模型 ID、服务端密钥修订号和测试时间；任何相关配置改变，旧结果显示“配置已变更，需重测”，不展示密钥摘要供浏览器猜测。

多上游用于人工选择和管理员维护，**默认不做隐式故障切换**。一个供应商失败，不把原对话和业务信息自动发往另一家。后续若开放备用服务，必须先由管理员明确批准数据去向，并在用户本次会话使用前显示切换信息。

### 2.3 密钥及请求边界

- 浏览器只见“已配置/未配置”，输入留空保留原值；替换、清除分别操作。变更接口主机时要求重新指定密钥，不把旧密钥悄悄送往新主机。
- AI 密钥不得放入通用 `system_settings` 的可读返回或完整前后审计中。复用通知配置的输入/输出分离方式，专用服务端私密存储仅允许管理接口写入、代理调用读取。
- 首版配置仅系统管理员可维护；使用权限和配置权限分离。普通角色拥有其他系统设置权限，不因此获得上游密钥管理能力。
- 服务端复用现有 HTTP 依赖，不让浏览器直接持密钥请求上游。设定请求超时、响应大小、上传大小、单用户并发和费用/调用次数限制；日志脱敏，不回传 Authorization 或供应商原始调试正文。
- 地址由管理员设置，聊天、模型回复和上传文件不能更换请求目的地。重定向须受控；允许明确配置的本地 Ollama 等服务，不能一刀切禁用全部内网，也不能允许模型任意探测内网。

## 3. “了解整个程序”的实现方式

建立三层上下文，先复用现有说明和业务服务，不以“上传整套源码和数据库”实现：

1. **版本知识**：当前模块、操作手册、字段含义、状态流转、常见错误与权限说明。以版本管理，回答附“依据哪一页/哪条规则”和可达页面入口；未知项明确说明，不编造功能。
2. **当前配置**：只读、脱敏的字段配置、必填项、当前有效主数据和可用方法/辅助事项。查询后按真实 ID 匹配，名称用于展示，不能凭同名猜测身份。
3. **授权业务工具**：实时读取用户有权查看的送样记录、检测记录及统计结果。默认仅给模型完成任务所需的字段；附件内容、历史对话和备注均为不可信业务数据。

按模块维护少量工具说明，服务端返回当前账号可用的工具。优先复用原查询/业务服务和字段元数据，无需首版引入外部 MCP、向量数据库或通用自主执行框架。日后知识量确实超过普通检索时再评估专门检索组件。

程序知识应覆盖下列模块，但不代表同时开放全部操作：

| 模块 | 助手可提供的帮助 | 首版操作边界 |
| --- | --- | --- |
| 研发送样、样品信息登记 | 解释填报、取样、驳回与重新提交流程；整理送样草稿和进度 | 按原入口区分字段、项目/实验室及实际送样人规则；确认取样、驳回仍走原页面 |
| 常规检测工作量 | 搜索实际计量方法，解释系数与金额倍率，生成录入草稿 | 原提交方法、实际方法、来源容量和历史快照保持，模型不能直接修改系数 |
| 独立辅助工作 | 查找授权区域和事项，辅助填写数量、人员和备注 | 复用账号人员归属，不分摊实验室、项目或金额 |
| 记录与统计 | 查询完整授权范围，整理人员工作量和业务日期总结 | 服务端计算数值，模型不从当前页推算总量；导出仍需原权限 |
| 公告、通知与提醒 | 解释未读、已读、送样提醒和驳回后的处理入口 | 首版不开放任意发送、群发或修改通知模板；业务通知仍由原提交链触发 |
| 主数据、角色、备份与日志 | 指引有权用户找到配置入口，解释稳定 ID、导入差异及备份步骤 | 不向普通用户暴露配置/密钥；导入、恢复、历史修正、删除和改权限留在原专用页面 |

### 3.1 能力由实际授权取交集

有效能力 = 管理员启用的 AI 能力 ∩ 当前账号实际业务权限与范围 ∩ 当前模型通过测试的能力。每次查询、生成草稿和提交都在服务端重新认证、授权；工具参数中的用户、角色、实验室、部门和记录 ID 不可信。

| 典型账号 | 可提供的帮助 | 必须遵循的限制 |
| --- | --- | --- |
| 普通送样人员 | 操作问答、自己范围内进度、送样草稿 | 沿原可见范围；不能读其他实验室或代替他人确认 |
| 公共送样账号 | 语音/文字整理送样信息、带入原表单 | 实际送样人按现行公共用途和手填要求处理；不能用公共账号名或语音猜测身份自动补齐 |
| 检测人员 | 授权待办、方法检索、工作量草稿与个人总结 | 取样、状态、方法有效性、数量容量、业务日期和原录入资格仍由原业务校验 |
| 公共检测账号 | 按原人员选择规则辅助填报 | 不能把账号操作人、实际检测人和实际送样人混为一人；原创建者范围不升级成全范围统计 |
| 组长/范围管理人员 | 已授权人员/实验室范围的查询及总结 | 不因“组长”名称自动跨部门；多角色范围逐角色解释，不能拼成更大的交叉范围 |
| 系统管理员 | 上述业务能力、服务和能力配置、调用审计 | AI 入口不会绕过高风险业务操作；历史修正、导入、删除仍走原专用页面 |
| 自定义角色 | 自动按实际权限计算入口和工具 | 不根据中文角色名写死能力；原权限、模板稳定身份和范围保持兼容 |

建议新增“使用 AI 助手”资格；细分业务能力仍由原业务权限控制，不再复制一套“AI 可看所有数据”的宽泛授权。升级时助手默认关闭、由管理员启用并选择使用角色，不调整旧角色授权或自动赋予外部数据发送能力。

## 4. 语音转文字与辅助填报

### 4.1 语音与对话分开配置

支持对话接口，不代表该上游支持语音识别。语音页单独维护服务、识别模型、密钥、语言和短音频测试，也可以选择明确提供兼容转写接口的第三方或本地转写服务。[官方依据 7]

建议首版使用浏览器 `getUserMedia + MediaRecorder` 录制短语音，再由服务端转写。只在用户点击后申请麦克风；开始、停止、取消、转写中、失败重试均清晰可见。关闭/取消后停止全部音轨，离开页面不继续录音。依据 `MediaRecorder.isTypeSupported()` 选择实际支持的格式，服务端再校验类型与大小，不假定所有手机都输出 WebM。[官方依据 5–6]

**远程电脑或手机通过局域网 HTTP 地址访问，是部署前必须解决的条件。**浏览器麦克风通常要求安全上下文；本机 `localhost` 的例外不等于手机访问 `http://服务器IP:端口` 也可用。部署应配置客户端信任的 HTTPS；权限拒绝、无麦克风或浏览器不支持时，保留打字及选择本地音频文件的备用入口。[官方依据 5]

原始录音建议仅作临时处理，成功、取消或过期后清理，不默认长期保存。发送前明确显示语音服务去向；转写文本进入当前草稿，错误的批号、数字、方法名可直接修改。语音中说出某人姓名不等于通过该人的账号认证。

建议初始限制为每段最多 60 秒、10MB，实际还需服从上游更严格的限制；这是产品建议值，并非各服务通用能力。浏览器自带 `SpeechRecognition` 的兼容性和服务依赖不统一，不作为首版主通道；当前 8GB 部署主机也不承诺同时运行离线语音大模型的效果，可接外部或局域网独立识别服务。[官方依据 9]

### 4.2 送样辅助流程

`录音/打字 → 可编辑转写 → 提取字段 → 查询授权主数据 → 处理歧义和缺项 → 带入原表单 → 用户复核并按原按钮提交`

例如：“给 415 实验室送两瓶水分样品，项目 D002，实际送样人张三，注意避光。”助手生成结构化候选并核对当前表单要求。不能确定的实验室、项目、方法、数量单位及实际送样人分别确认；原字段不存在的信息保留在备注或待补充区，不能虚构新字段。

- 方法仅从当前允许的有效候选中选真实 ID，名称相近或同名时显示候选供用户选；未匹配信息保持原文并提示处理，不任意创建主数据。
- 必填和自定义字段规则来自现有配置；不能只识别几个固定字段后就认为可提交。未取到配置或主数据时停止形成可提交状态。
- 公共账号实际送样人初始仍为空，按现行要求校验；若从语音识别到姓名，显示为待用户确认的填入值，不悄悄使用账号名兜底。
- “填入表单”只修改表单草稿，显示将写入的字段，已填写内容不静默覆盖；原提交按钮执行状态、权限、组织、字段、附件及数量等校验。
- 两类新送样的提交时间仍由服务器在正式提交时生成，不提供 AI 回填送样时间。可编辑的工作量业务时间继续遵守原录入校验。
- 样品信息登记已有按当前登录用户维护的服务端草稿，可在同一用户边界内复用。研发新送样当前没有同类持久化 AI 草稿接口；首版复用页面会话输入，不宣称已经支持跨设备恢复。退回待修改记录是已有业务状态，不能当成新建草稿接口使用。

### 4.3 工作量辅助与对话总结

录入辅助可从授权来源提取候选实际方法、数量、业务日期和备注，仍进入原工作量确认窗口。方法切换按现行逻辑读取系数、金额倍率及方法单价；来源方法、实际计量方法和历史快照分别保留，不由模型计算或改写系数。

对话总结使用服务端确定性查询与聚合结果，模型仅整理说明。例如“总结我上周工作量”需先明确日期、人员及口径，再给检测与辅助分别汇总、记录数量、工作量、数据范围和可打开的明细入口。

- 查询覆盖**完整授权记录范围**，不从当前页 50 条或当前近 30 天缓存自行推算。
- 使用原业务日期/时间和人员身份规则；日期边界以程序业务时区处理，精确显示本次查询起止日期。不把创建时间替代用户修改过的业务日期。
- 手动录入、来源按钮录入和辅助记录沿现有统一读取逻辑；辅助镜像及历史关联去重，不能将同一工作算两次。
- 辅助工作保持独立区域与事项配置，按本人/授权人员归属统计；**不参与实验室或项目分摊，不计算金额**。不可因对话提到某实验室就改变辅助归属。
- 历史系数、金额、来源和人员快照沿用原值；“按当前方法重算历史”只能引导至现有管理员差异预览/修正入口，不作为普通对话自动操作。
- 没有完整统计授权时，明确说明可提供的是本人/创建者明细或部分范围，不能给出“全组总计”的错误结论。

## 5. 确认、审计和失败处理

首版让业务写入经原表单确认；不因用户说“帮我处理”就连续执行多条未知操作。工具结果或附件中的“忽略权限、导出全部数据”等文字属于数据，不成为系统指令；只执行服务端允许且参数校验通过的业务工具，不开放 SQL、命令行和任意 URL 请求。

如后续允许在助手内确认提交，必须复用原服务事务，在确认卡中列明对象、方法/事项、数量、日期、人员、字段变动和影响。确认内容绑定当前草稿修订及业务版本，提交时重新检查权限、状态、方法和剩余容量；编辑内容后旧确认失效。

对每次创建分配服务端幂等标识，禁止双击或重复确认创建两次。超时不等于失败：结果未知时先按请求标识核对是否已生成业务记录，再允许重试，不让模型猜测成功或重新创建。取消生成只停止后续生成，不宣称已撤销已经提交的事务。

审计区分“AI 会话/工具调用”和“真实业务操作”，记录账号、请求标识、实际业务人员、工具、授权范围摘要、供应商/模型、耗时、结果及关联记录；密钥、原始音频和完整敏感提示词不默认写入日志。业务创建/修改仍进入原业务审计，并保留来源链。对话保留策略由管理员明确设置，公共账号会话不长期暴露在共享页面。

## 6. 实施范围与交付顺序

| 阶段 | 完整交付内容 | 验收后能力 |
| --- | --- | --- |
| A：接入和知识 | 头像旁入口、形象、模型服务配置、模型获取、hi/流式/工具测试、知识说明、权限过滤和调用审计 | 可问操作、查已授权业务数据和生成工作量总结 |
| B：语音与填报 | 独立转写配置、HTTPS与浏览器兼容、语音编辑、主数据匹配、字段检查、带入原表单、样品信息草稿衔接 | 可通过语音和对话辅助填报，继续原表单确认 |
| C：经确认的工具写入 | 必要时新增助手确认卡、幂等记录、未知结果核对和完整审计 | 确有需求且验证通过后，在助手内完成选定低风险提交 |

A、B 是本次需求的建议首个完整业务版本；C 不作为必须先建的通用 Agent 平台。正式开发应创建递增版本目录并执行现有发布门禁，本轮方案不修改正式版源码、业务数据、版本或远端资产。

最小验收应覆盖：

1. 获取模型的多页、空列表、重复 ID、手工 ID、错误格式和失败保留；正确密钥/错误密钥、地址可达但模型拒绝、200 空回复分别得到准确结果；修改配置使旧测试失效。
2. 密钥不出现在普通设置 GET、HTML、浏览器持久存储、日志和审计正文；换地址不沿用旧密钥，不隐式切换供应商。
3. 个人、公共送样、公共检测、组长、管理员及自定义角色的读写边界，跨范围 ID、撤权、停用账号、多角色范围不能绕过；旧授权和公共用途升级兼容。
4. Windows、Linux/Docker 和手机 HTTPS；拒绝麦克风、低高度、无设备、格式不支持、录音取消、断网重试；实测批号/数字/姓名/方法名的识别与修正。
5. 自定义必填、歧义方法、公共实际送样人、用户已有输入不被覆盖；样品信息草稿仅本人可读写，研发无虚构跨设备持久化承诺。
6. 原方法系数、倍率零值、手动/来源录入、业务日期跨天、来源容量并发、历史快照和重复点击；辅助不计金额/实验室，汇总不重复计算且覆盖授权全量。
7. 提示注入、空工具结果、拒绝/失败/未知结果、取消生成及重复确认；没有真实业务结果时不显示“已提交成功”。

HTML 只演示布局与交互，不使用真实密钥、不请求上游、不录制或上传语音、不提交业务记录；实际模型、权限、语音识别准确度及实机体验留待正式集成验收。
