# 后台全页面 UI 复检与整改方案

日期：2026-11-07。基线：本地正式版 v2.4.9；程序来源 `6cf426be625581baa337b78e0beb2dbfa02ea7e1`，主线交付文档提交 `f44d1a3b2a74632ff72aa81536d2e583478db457`。

**结论：B 方案的管理导航可以继续保留，但内容页和内部编辑器尚未形成一致的使用方式。整改重点应从外壳转向保存反馈、配置草稿、内部响应布局和信息密度。**

本轮仅检查和制定方案。未修改正式源码、数据库、配置、应用版本或发布状态，未提交或推送本轮报告。

从同目录《后台全页面UI复检与整改总览.html》查看可筛选清单和代表性截图；《整改清单.json》保存23项入口与18项整改的对应关系。

## 1. 本次检查范围与证据边界

### 1.1 按真实入口追踪

- 四组管理导航共23项，另检查管理工作区总览，共24个一级视图。
- 对一级视图使用1440×960、1024×960、390×844三种视口，共72个页面快照。
- 展开45组二三级操作场景，在桌面和手机分别检查；另做8个针对保存拒绝、草稿切换、加载失败和菜单配置的定向检查。
- 三轮共190个快照记录；去重并用修正夹具后的结果替换早期记录，保留170个现行检查记录。不能将重复截图计成不同功能。
- 管理及公共外壳的 JSX 引用树涉及43个页面/组件文件、60处弹层定义。定义中包含共享包装器、辅助工作非管理模式和兼容分支，**不等于60个独立且全部已点开的后台页面**。
- 额外核对了API响应处理、相关类型，以及后台跳转的三个统计门户所用`from=manage`返回逻辑。三个前台统计门户的完整图表、明细及导出不是本轮后台布局运行检查范围。

### 1.2 实际运行方式

浏览器加载正式构建静态文件，摘要为：

`42396533d4c3ff069720e4020814f3a376cce2fa2e7ccd5e34fc077fc11c3e42`

全部API由隔离的虚构数据夹具应答，所有业务写入均被夹具拒绝。没有访问现场服务、8000、真实账号或数据库，没有执行归档、删除、恢复、导入、历史修正或真实通知发送。

首轮样品记录/统计夹具缺少契约字段，产生4条脚本错误；修正夹具后对应场景已重新检查，不能将这些错误算作产品故障。早期回收站定位误选了禁用的批量按钮，布局页夹具也曾缺少区块配置，均已修正定位或夹具后复检。最后一轮无脚本错误，所有轮次均无外部网络请求。

详细过程位于私有`test-artifacts/admin-ui-audit-20261107/`，不上传源码库。判定分为：

- **已复现**：实际构建的浏览器界面及对应源码互相支持。
- **结构确认**：源码能确认结构，但未执行该流程的真实业务结果。
- **待专项验证**：大文件、真实Excel/PDF、权限后端、云端授权、手机软键盘、实机触控、浏览器缩放和性能。

## 2. 先保留已经合理的部分

不建议再次更换整套导航，也不建议迁移前端框架。

1. 保留64px模块栏与当前模块菜单、手机单一菜单入口及带边框的返回按钮。
2. 保留方法页已经分开的页头、筛选和数据区；主数据对象选择器继续使用。
3. 保留通知中心任务页签、通知字段搜索、模板草稿与刷新确认，不再重复提出“新增这些功能”。
4. 保留角色和辅助事项已有的手机摘要、辅助区域管理不丢事项草稿的行为。
5. 保留现有审计字段差异组件、原生字段保护、导出计算列锁定及回收站确认链。
6. 常规Dialog/编辑抽屉多数已经把操作区与滚动内容分开，不应笼统认定“所有弹窗底部都不固定”。
7. 已有表单内部切换确认、通知草稿等保护继续保留；只补齐缺少保护的上下文切换。
8. 不将源码中`false`分支的退役统计矩阵，或不在现行路由中的旧`theme/home`分支，误当成当前正常入口。

## 3. 第一批必须整改的操作与反馈问题

### F01 / P0：业务保存失败，界面仍提示成功

项目一览和实验室一览的部分失焦保存，直接`await updateProject/updateGroup`后显示“已保存”，没有检查业务返回码。

本次模拟**HTTP 200、业务code=1**，项目和实验室一览都显示了“已保存”。客户端API包装返回响应数据，全局拦截器主要处理会话失效和HTTP错误，没有替这些调用点抛出全部业务错误。因此这是明确的调用链缺口，而非仅凭截图猜测。

整改：

- 复用既有`requireApiSuccess`等成功检查方式，补齐遗漏调用点。
- 服务端确认成功后才更新已持久化状态。
- 保存失败保留编辑值、显示原因并允许重试；不能只留下成功提示。
- 默认列表只读，进入编辑时明确标识。不要直接把可失焦保存的一览表当作日常浏览页。

范围：`ManagePage.tsx`项目一览、实验室一览；关联API见`api/masterData.ts`、`api/http.ts`。本次未证明现场已经发生数据丢失，确认的是上述失败条件下的错误反馈。

### F05 / P1：长配置切换对象时丢草稿

已复现：

- 页面布局填写“未保存布局草稿”，切换页面对象再回来，字段恢复为空。
- 导出模板修改文件命名，切换业务模板再回来，恢复为`样品管理_{s}_{e}`。

整改：

- 区分“即时保存”“应用到待保存配置”“保存到系统”。
- 长配置切换对象、离开模块时提供保存、放弃、继续编辑；已有草稿隔离与保护继续使用。
- 简单新增表单明确点击取消可以放弃，不需要每次再弹确认。
- 不只保护内部页签，需覆盖管理菜单跳转和浏览器离开。

### F06 / P1：错误、空数据和加载中混淆

已复现：

- 项目读取失败后仍显示“暂无研发项目”，没有区分查询失败。
- 日志维护状态读取失败时有外层错误提示，但模块内容仍为旋转图标，模块内没有可用重试入口。

整改采用统一状态：

`首次加载 → 成功有数据 / 成功为空 / 筛选无结果 / 失败可重试`

刷新失败可保留旧数据与条件，标明刷新失败。不要为了隐藏错误自动写入配置、自动修正记录或重算历史。

### F07 / P1：自定义导航配置在不同页面不一致

同一账号、同一`manage-tabs`夹具下：

- 用户管理的导航不显示“角色与权限”。
- 独立角色页的导航又显示该项。

原因是`ManagePage`传入`enabledKeys`，独立页面未使用同一配置输入。

整改应共享同一份经过配置和权限过滤的导航数据，同时保留必须可达的维护入口。**菜单隐藏、页面准入、编辑权限和数据范围仍是不同的判断，不能以菜单过滤代替授权。**

## 4. 已确认的关键排版问题

### F02 / P1：页面布局编辑器的内层固定目录

外层B导航已经统一，内层仍是：

- 横向flex。
- 左侧220px固定目录。
- `height: calc(100vh - 200px)`，同时`minHeight: 500`。

390px截图中右侧编辑区被挤成窄条，“显示业务编号”逐字排列。继续缩小字号不能解决这个结构问题。

整改：

- 手机以页面对象选择器替代常驻目录，编辑区占满内容宽度。
- 桌面按内容可用宽度决定是否并排，不按整台显示器宽度强行分栏。
- 取消内部重复的视口补偿；长表单与列表使用明确的滚动职责。
- 保留区块、字段和全局业务编号各自配置作用范围。

### F03 / P1：导出模板编辑器固定三栏

当前内部网格固定为：

`220px minmax(460px, 1fr) 286px`

390px检查中页面`scrollWidth=979px`。手机能看到工作表和部分预览，属性区落在屏外；业务页签也未使用可滚动配置。

整改：

- 宽屏保留三栏；窄屏使用模板、工作表、列的逐层选择，属性编辑占满可用宽度。
- Excel预览保持局部横向滚动，不能拖着整页寻找属性和保存按钮。
- 预览明确标注为样式示例，不是当前业务统计。
- 保留系统计算列、真实字段、Sheet启停、标题、颜色、列宽和显隐规则。不得仅在前端开放后端未支持的换列或公式编辑。

### F04 / P1：用户列表手机逐字竖排

390px截图中“可承担业务部门”等表头，以及姓名、部门和角色，都被拆成过多行。页面总宽度未溢出，仍然难以阅读。

整改：

- 手机使用账号摘要与详情；桌面保留完整列和筛选。
- 组织归属、业务部门、实验室、角色继续独立维护，不合并成新的权限字段。
- 正常字号下不能逐字竖排，也不能把编辑和状态挤到无法发现的位置。

### F08 / P1：项目卡片承载了全部关联详情

截图和虚构数据复检都显示：39个进行中与2个归档项目分别占半屏，每张卡片将全部方法渲染为蓝色标签。

整改：

- 默认进入进行中，归档单独页签；启用/停用与进行中/归档保持不同语义。
- 桌面以项目、实验室、方法摘要、门户范围、状态、操作组织列表；手机三至四行摘要。
- 关联方法可按真实类型、仪器和通用属性查看完整列表；不按显示名称猜分类。
- 列表摘要不是删关联，更不能把这套摘要方式套到要求完整展示的工作量原始信息窗口。

## 6. 二三级页面的统一组织规则

### 6.1 列表与详情

统一顺序：对象标题与主操作 → 查询条件 → 数据及计数 → 分页/选择范围。

- 高频操作直接可见，低频维护放“更多”；危险操作保持含义、确认和权限。
- 实验室、方法、权限、字段范围等关联信息分区，不混成同色标签墙。
- 备注、错误原因和长名称可以换行或查看详情，不能以省空间为由不可恢复地截断。
- 对确需二维查看的表格保留局部横滚；手机不强行塞下全部桌面列。
- 方法、角色等多处同时保留桌面/手机两份DOM，仅用CSS隐藏另一份，存在重复渲染成本。可评估只挂载当前布局，但本次没有证明它是现场卡顿根因，不能宣称性能提升比例。

### 6.2 编辑器

统一展示对象身份、分组字段、关联选择、当前状态和底部操作。

- 简单实体复用现有Dialog/抽屉；复杂配置按任务组织，不新增一套编辑引擎。
- 已有固定底部操作区保留；手机应能访问全部字段和保存/取消，不能只修一级列表。
- 项目已有按方法类型筛选，继续保留；补关键词、已选数量和回看，不重复造已有功能。
- 权限检索仅过滤展示，不得丢失未显示的已选权限或改变通配含义。
- 新增用户密码标签与编辑场景分开，不能同时说“留空不修改”和“新用户必填”。
- 抽屉补足对话框语义、关联标题及焦点返回；遮罩/软键盘行为需专项实测。

### 6.3 预检与历史核对

统一步骤：范围与来源 → 预检/差异 → 明确确认 → 完整结果。

- 选择数、筛选范围、目标对象和差额在确认阶段仍可看清。
- 系数修正、历史方法关联和旧辅助迁移仍是不同动作，不能合成一个“同步全部”按钮。
- 全筛选跨页选择、分批提交、原因、签名时效、冲突检查、已完成批次和结果不确定提示继续保留。
- 系数、数量、工作量、金额和倍率按原精度展示与计算，合法零值不回退为1。
- 不折叠掉关键金额影响、原值/新值和历史来源，不自动重算。
- 数据导入的merge/skip/覆盖语义、引用保护、稳定ID及恢复规则不变。

### 6.4 配置的作用范围

每个编辑器需回答：

1. 配哪个业务、检测类型、页面或导出工作表？
2. 当前修改是立即生效、仅本地草稿，还是已经保存？
3. 哪些是只读标识，哪些可以改名？
4. 预览使用示例数据还是真实数据？
5. 停用/隐藏后如何恢复？

辅助事项页底部的`RecordActionSettings`配置的是辅助工作**记录**显示，而非当前事项管理表的普通按钮，应明确标注作用对象。

### 6.5 视觉默认值

- 保留当前程序内品牌及主题，继承已配置主色、字号、圆角、边框和按钮前后配色。
- 普通管理控件采用统一默认高度和间距；不能覆盖业务记录按钮已有独立尺寸配置。
- 标题、正文、辅助说明形成少量清楚的层级，减少固定蓝/绿/青与高字重争抢注意力。
- 状态色表达状态；普通关联摘要用低强调色。
- 采用4px节奏，普通按钮、筛选、列表信息的对齐规则统一。
- 数量、系数、金额采用相应精度与对齐；存储和统计不因视觉格式改变。
- 不新增无用途KPI、装饰图、营销式首页或复杂动效。

## 7. 实施顺序

## 8. 验收矩阵

### 页面和状态

- 23个入口、总览，以及每个改动涉及的页签、编辑器、选择器、预检与确认链。
- 正常有数据、成功为空、筛选无结果、加载失败、保存失败、草稿、处理中、无权限。
- 长项目名、长方法名、大量通用方法、多实验室/多角色、停用项和合法零值。
- 窄屏按钮、表头和必要内容不逐字竖排，控件不能落到不可访问的屏外。
- 真正需要的局部滚动可发现；不能用根页面无溢出代替可用性验收。

### 权限与自定义

- 管理员、部分管理权限、只读能力账号、配置隐藏入口。
- 菜单、路由、编辑、导出和数据范围分别验证；不恢复旧部门角色层。
- 列显隐/宽度/顺序、内外边框、字号、操作顺序/位置/尺寸/状态颜色按原作用范围保留。
- 辅助区域独立，人员关联沿用账号；辅助不计实验室或金额。
- 字段标识、方法/事项稳定身份和历史来源不改变；一种类型的配置不覆盖其他类型。

### 视口与实机

本次运行检查使用三种CSS视口。实施验收补齐1440×960、1366×768、1024×768、768×1024、390×844和360×800。

手机软键盘、实际触控、浏览器100%/125%缩放需单独实测；1024px视口不能冒称125%真实缩放测试。真实Excel/PDF、备份恢复、云盘授权、钉钉、权限后端及性能按对应改动另做验收，不套用本轮截图结果。

## 9. 方案边界

这是整改方案，不是实施完成声明。当前正式版仍为v2.4.9。

涉及真实文件、云端授权、生产数据、历史关联/系数确认及统计口径的结果，本轮没有实际执行。预检和危险确认中未能用安全夹具完整展开的动态分支，按源码列入整改清单，不能称已经逐项实机通过。

设计方向：实验室主数据和业务台账；克制、明确、耐读；强调对象身份、异常及变更差额；一个对象摘要贯穿列表、编辑和确认。
