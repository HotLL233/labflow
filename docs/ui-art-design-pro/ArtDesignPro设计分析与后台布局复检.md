# Art Design Pro 设计分析与 LabFlow 后台布局复检

日期：2026-11-06。项目基线：正式版 v2.4.8，业务源码提交 `6171bea009e06322c4c47b50a7f51abc5f481d50`。

本轮仅研究、评估和制作 HTML 参考。未修改正式页面、业务代码、数据库、权限、应用版本或发布状态；未提交、推送或发布本轮原型。上一轮 v2.4.8 的正式交付结论保持原样。

从 [三版对比入口](LabFlow-ArtDesignPro-后台布局对比.html) 打开。每版可切换六类核心页面，并有管理入口总览。其他菜单保留信息架构位置，明确标注未展开完整业务页。

## 1. Art Design Pro 值得参考什么

本次核验官方开源仓库 `Daymychen/art-design-pro`：

- 本次 API 核验的主线快照：`f3aaf58eec1a0e988f162352c33862327a484f95`，提交日期2026-06-01。
- 官方 Latest Release 在本次核验时返回 `v3.0.2`，发布日期2026-03-15。主线快照和正式标签是不同对象，不将主线 SHA 直接当成该 Release。
- 研究对象是官方开源配置与组件源码，没有将商业版页面说明当成开源版保证，也未在官方演示站操作真实业务。
- Art 使用 Vue / Element Plus 等前端体系；本项目使用 React / MUI。建议借鉴信息架构和交互组织，继续复用本项目现有组件与接口。

| 可参考的设计 | 官方依据 | 适配 LabFlow 的方式 |
| --- | --- | --- |
| 导航结构可按使用场景选择 | 开源配置提供左侧、双栏、顶部及混合菜单；本快照默认左侧、展开宽230px | 制作三种结构比较，不把四类管理模块和23个功能一律平铺 |
| 搜索区有统一组织方式 | `ArtSearchBar` 集中组织字段、搜索、重置与展开 | 同一行统一标签、控件高度与对齐；手机保留搜索，将次要条件放入筛选窗口 |
| 业务操作与表格工具分开 | `ArtTableHeader` 分左右区域，并提供刷新、密度、列显示等工具 | “新增/导入”放页头；类型、状态放筛选区；刷新、列设置、显示设置靠近表格 |
| 数据区稳定占用剩余高度 | 表格页面样式围绕可用高度组织，表格、分页职责清楚 | 使用明确的外壳网格和一个主要数据滚动区，避免继续叠加多个高度补偿值 |
| 工作标签页适合跨页面维护 | 开源配置默认启用工作标签页 | 在C版单独演示并说明成本；A/B不增加这一行，不把标签页当成所有后台的必需品 |
| 视觉强调有层次 | 官方组件把操作、搜索、表格和设置分区 | 白色数据区、低饱和边界、一种主色；状态色只表示启用、失败、待处理等含义 |

不建议照搬：营销式首页、无实际用途的KPI卡片、全部区域的大圆角、无业务用途的勾选列/批量操作、复杂动效，以及与本项目无关的商业版组件。侧栏从232px改到230px本身收益有限，重点应是菜单层级和数据区组织。

## 2. 对 v2.4.8 的重新评价

v2.4.8 已经解决了共享外壳不一致、主数据大标题重复、手机角色页逐字换行、部分权限直达误拦截等问题。新的问题主要集中在操作、搜索、数据三层之间，以及窄屏的空间分配。

| 优先级 | 当前观察 | 源码位置 | 本轮建议 |
| --- | --- | --- | --- |
| P1 | 手机全局菜单下又有“管理导航＋当前栏目”一行，再出现标题与返回，导航上下重复 | `Layout.tsx`、`ManageNav.tsx`、`ManageWorkspace.tsx` | 把手机管理导航整合进一个明确入口；栏目只保留一次主标题，返回保留边框 |
| P1 | 方法页将搜索、类型、范围、方法一览、仪器、导入、新建等放在同一工具区域；手机有两个强制100%宽的次要按钮 | `ManagePage.tsx` 检测方法面板 | 高频新增留页头；仪器/类型管理进入可发现的更多菜单；筛选靠近数据 |
| P1 | “管理类型”是计数文字中的按钮，仍继承管理主题的36/44px最低高度，抬高整条计数行 | `ManageWorkspace.tsx` 的按钮规则及方法计数行 | 计数行只放元数据；管理命令进入独立操作菜单，不让行内文字链接继承大按钮尺寸 |
| P1 | 主数据既有管理菜单，又有操作页签和152px工作表目录；表格最低宽度按每列约132px扩张 | `MasterDataPanel.tsx` | 数据对象用选择器；预览、导入、导出明确分开；名称、数值、状态、操作采用不同宽度策略 |
| P1 | 通知中心仍按身份、模板、概览、渠道、规则、事件、投递记录纵向铺开，查异常要滚动较多 | `NotificationPage.tsx` | 将运行查询与低频配置分成任务页签；事件、投递、模板、渠道、身份各有入口 |
| P2 | 管理总览完整重复侧栏。两列中的7项主数据与3项人员权限高度差较大，出现成片空白 | `ManagePage.tsx` 管理工作区 | 总览改为按组的横向索引；日常维护直接进入有上下文的功能页 |
| P2 | 外壳扣固定104px，表格又设最大620px/手机视口补偿，存在多层滚动和高度耦合 | `ManageWorkspace.tsx`、`MasterDataPanel.tsx` | 外壳明确分配页头与内容；数据区独立滚动；长配置页自然滚动，不增加第三个纵向滚动区 |
| P2 | 部分页面同时用主题按钮、固定蓝色、青色边框和较亮的仪器标签，视觉优先级不够统一 | `ManagePage.tsx`、主题及各面板样式 | 一个主操作色，普通元数据用中性色，危险操作与状态保留语义色；已配置颜色不被新默认值覆盖 |
| P2 | 字段配置需同时看字段范围、编辑入口和预览；目前预览在部分宽屏阈值内才并排显示 | `ManageFormConfig.tsx`、`AdminRdRecordColumns.tsx` | 宽屏并排、窄屏上下；不把所有字段硬压进手机宽度；完整配置继续走原编辑流程 |

“104px高度耦合”等属于结构风险，不意味着已复现滚动卡死。当前问题与数据量、网络等待也应分开；本轮没有做性能分析或生产压测。

## 3. 三版怎么选择

三版使用相同的虚构数据、操作逻辑、字号和颜色，让差异主要来自布局。

| 项目 | A 经典紧凑侧栏 | B 双栏模块导航 | C 顶部混合导航 |
| --- | --- | --- | --- |
| 入口 | [打开A](方案A-经典紧凑侧栏.html) | [打开B](方案B-双栏模块导航.html) | [打开C](方案C-顶部混合导航.html) |
| 一级结构 | 一条208px侧栏，四组可收起 | 64px模块栏＋168px当前模块菜单 | 顶部四模块＋176px当前模块菜单 |
| 同时显示的功能 | 可展开全部23项 | 当前模块3～8项 | 当前模块3～8项 |
| 工作标签 | 不增加 | 不增加 | 桌面演示36px工作标签行 |
| 主要收益 | 迁移较少，保留使用习惯 | 模块边界清楚，扩展管理功能更容易；左右合计仍为232px | 数据横向空间更大，跨页切换清晰 |
| 主要代价 | 展开所有组后仍需侧栏滚动 | 用户需要先理解四个模块 | 多一行标签；需额外实现草稿、查询状态与关闭保护 |
| 适合 | 希望稳妥小步改版 | 管理功能持续增加，长期维护 | 桌面跨页操作多的管理员 |
| 评估实施量 | 低 | 中 | 较高 |

优先建议B。它利用现有四个分组，菜单和业务权限仍来自当前定义，主要调整导航的展示方式。希望尽量少动结构时选A。C应在确有跨页维护需求时再实施，工作标签可以作为可关闭的选项。

手机端三种桌面布局都收敛成一个抽屉导航和紧凑记录，避免把双栏硬塞进窄屏。手机相似是有意保持一致，并不是只换配色的三份稿。

## 5. 原型里能操作什么

- 方法：搜索覆盖全部32条示例后再分页，查看详情，编辑名称/系数/倍率/单价，零值合法，方法身份保持不变。
- 主数据：九种数据对象的只读预览，导入文件选择与预检表格结构，导出虚构CSV；不解析真实Excel、不调用导入接口。
- 辅助事项：独立区域/类别/系数，区域管理打开时保留事项草稿，新增区域后原绑定不会被自动替换；不展示事项ID、实验室或金额字段。
- 角色：角色列表、权限范围入口和手机紧凑记录；只展示布局，不写权限。
- 通知：事件/发送记录/配置/模板/身份分组，模板草稿关闭再打开保留，补发原因必填，前后状态可区分；不发送真实消息。
- 字段：分业务、分样品登记检测类型保存示例范围，“状态”停用后仍可在配置表找到并恢复；不覆盖其他类型。
- 显示：列显示、字号、密度、内外边框颜色及粗细独立演示；只影响原型本页。
- 删除/恢复：仅是虚构数据的状态演示；正式逻辑仍使用现有依赖预检、软删除与回收站，不因原型增加新的恢复接口。

其他管理入口只展示原有信息架构和本稿范围，不伪装成已经实现完整业务。导出文件有“布局示例”前缀，包含虚构稳定身份；不能用作生产主数据回导文件或正式Excel模板。

三版共用`assets/`中的脚本、样式与图标。可直接从本地打开，无需启动服务；转发时保留同目录资源。

## 6. 后续实施时不能丢的规则

1. 继续使用React/MUI和现有管理组件，先整理页面结构，不整体迁移到Vue/Element Plus。
2. 菜单显示、页面准入、数据范围、编辑和导出权限分别保留。模块切换或工作标签不扩大授权；缓存必须按账号、权限及来源隔离。
3. 方法与事项身份只在原有协议中流转，更名不换身份；辅助事项ID不在日常前端显示，Excel仍保留回导识别字段。
4. 辅助区域独立于检测类型，人员关联沿用账号归属；不把辅助工作分摊实验室或计入金额。
5. 既有字段标识、来源、检测类型级范围、列宽/顺序/字号/边框、按钮前后状态配色、位置与尺寸继续保留；原型的12～16px示例选项不反向限制正式9～24px等既有配置。
6. 主数据导入合并/跳过/覆盖语义、稳定ID定位、引用保护和预检确认保持不变；不自动重算历史工作量。
7. 原型数组筛选不能替代正式服务端的完整授权范围筛选；业务记录近30天优先加载、按需历史策略不变。
8. 录入工作量弹窗的源信息继续完整、紧凑展示；本稿的菜单折叠或手机筛选窗口不用于折叠业务源信息。
9. C版必须验证标签关闭、草稿、查询、分页、权限变更和账号切换；不能只增加一排看似可点击的标签。

这些是参考方案，不是对正式UI的再次实施授权。选定方向后再按现行版本规则进入下一递增版本。

## 7. 验证与交付范围

最终三版通过303项离线浏览器检查，覆盖六种视口：1440×960、1366×768、1024×768、768×1024、390×844、360×800。

检查包含页面宽度、按钮文字、手机搜索可见性、全示例范围搜索和分页、零值与稳定身份、文本转义与CSV公式保护、状态恢复、辅助区域管理保留草稿、通知草稿/补发、导入预检示意、按类型字段独立保存、边框与字号、手机抽屉和编辑窗口。最终未发生浏览器脚本错误或外部HTTP请求。

截图发现的手机搜索输入被样式隐藏已修正，并新增可见性检查；测试脚本的语法/选择器错误也保留过程记录，最终结果以`references-accepted/verification.json`为准。原型与基线截图、校验脚本和源码快照元数据保存在私有`test-artifacts/ui-art-design-pro-20261106/`。

本次没有真实业务API、数据库、权限后端、手机实机、部署或性能验收，也没有重新编译或发布正式软件。当前应用版本仍为v2.4.8。
