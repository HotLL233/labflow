日期：2026-11-12。基线：根 README 指定的正式版 v2.4.12。

**建议复用现有检测方法管理：管理员新建独立方法，例如“水分-特殊处理”；送样人仍提交“水分”，检测人录入时默认使用原方法，也可搜索、确认其他授权可用的实际计量方法。** 不新增下级处理方式表，不要求送样人了解具体计量规则。

本稿取代此前“方法下关联处理方式”的设计。文件名保留以兼容已有引用；本稿及 HTML 仅为待开发方案，不表示正式软件已支持改选。

## 2. 使用流程与计量规则

送样人沿用当前项目、实验室、方法、数量等字段，继续提交“水分”，或原来的“通用理化 / 通用液相”。原字段、项目方法关联、通知和取样习惯保留，不新增必填项。

管理员在现有“主数据管理 → 检测方法”新建“水分-特殊处理”，独立维护系数、默认金额倍率、单价、仪器、检测类型和启用状态。它与“水分”是独立方法；相似名称仅方便查找，不形成父子关系。

检测人点击原“录入工作量”按钮，默认按原方法 ID 预选。无需改变时直接填数量确认；需要改变时输入“水分”“特殊”“通用”“液相”等关键词，从候选明确选定实际方法再录入。源为通用方法时也能搜库中具体方法，或继续用原通用方法，不能只支持“水分”这种固定原方法。

以下系数、倍率及单价均为功能示例，不代表实际计量或收费标准：

| 原提交方法 | 实际计量方法 | 数量 | 系数 | 实际倍率 | 工作量 | 单价 | 金额 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 水分 | 水分 | 2 | 1 | 1 | 2 | 10元 | 20元 |
| 水分 | 水分-特殊处理 | 3 | 3 | 2 | 9 | 10元 | 60元 |
| 同一来源合计 | 分别保留两个独立方法 | 5 | 各自快照 | 各自保存 | 11 | 各自单价 | 80元 |

- `工作量 = 数量 × 实际方法系数`，提交时保存系数快照。
- `金额 = 数量 × 实际方法当前单价 × 实际金额倍率`。取实际选中方法单价，方法默认倍率填入原倍率框，不重复相乘。
- 系数、倍率和单价须有限、非负；0合法。数量沿用正整数规则。
- 同一来源的所有人员、日期和实际方法共用累计数量上限。来源5份可“原方法2份＋特殊3份”，第6份拒绝；不能给每种方法独立5份额度。
- 本方案用于同一份样品择一计量方法。一份样品两道工序均需重复计次时，应另定多工序容量规则，本轮不取消原容量约束。

## 3. 全库搜索与授权

“全部方法”指**当前账号、当前执行项目和实验室范围内允许计量的全部有效检测方法**。搜索不被来源方法、来源仪器或来源类型锁定；无权使用、停用、已删除及非本入口可计量的数据不能被选择。

| 关系 | 用途与规则 |
| --- | --- |
| 原项目方法关联 | 继续控制送样可提交方法和手录原项目方法行；不自动增删关联 |
| 实际计量方法准入 | 在明确计量入口新增服务端准入：目标项目/实验室/部门及来源均有权操作，方法属于授权有效检测方法库时可用，不要求再次关联当前项目 |

第二行是**计划中的规则变更，当前源码还没有**。实施时将送样关联选择与实际计量可用性分开校验，同步调整手录前端关联判断和仓储校验；不能只删掉全局 `validate_record_bindings` 约束，也不能把前端候选当授权结果。不自动为特殊方法创建项目关联，因此不会改变送样列表。

1. 服务端候选和正式提交都检查当前账号权限、项目/实验室/部门范围、来源可执行状态、方法及绑定仪器状态。跨仪器/类型搜索不等于跨部门或来源授权。
2. 绑定仪器须有效；无仪器方法沿用该入口明确支持的计量规则，不绕过停用检查。通用方法按真实主数据标志及部门规则识别，不以名称含“通用”推断。
3. 关键词只筛选和推荐。原方法及相关名称优先，但不会自动改选；提交真实方法 ID。名称不能判断身份、来源、辅助工作属性或权限。
4. 有来源时，原项目、原实验室和原方法为只读来源信息。执行归属及人员仍走现有授权逻辑；改实际方法不改原送样记录，不自动移动实验室或人员归属。
5. 原方法失效时仍保留来源名称和身份，不按同名替代、不默选相近方法，需明确选有效实际方法才能录入。
6. 现有 `create_sample_workload` 放宽路径校验 `sample_info_records` 来源，不能直接用于研发来源；需保留 RD 状态、来源锁、范围及数量验证，避免误查相同数字 ID 的别类来源。
7. 辅助工作继续独立事项配置与统计。实际方法候选仅含本检测入口可用数据，不因名称相似混入辅助事项。

## 4. UI 与现有习惯

- **手录：**保留项目方法行卡、标签、系数、右侧金额倍率、数量、圆勾。默认原方法直接录入，只加轻量“更换计量方法”入口，需要时展开搜索；切方法保留数量、日期及人员。
- **来源窗口：**沿用样品登记的全库关键词搜索习惯，原方法常驻只读，实际方法默认按原 ID 预选。仪器仅作可清除筛选，不强锁来源仪器。未确认关键词不能提交。
- **倍率保护：**未手改时随方法联动默认倍率；已手改保留原值，提示“保留手动倍率X；当前方法默认Y”，提供“恢复方法默认倍率”。工作量系数与单价始终来自实际方法，不把手工倍率当系数。
- **配置变化：**服务端预览返回实际方法的系数、默认倍率、当前单价及配置修订或指纹；确认时若配置已变，保留数量、日期、人员及手工倍率，重新展示计量差异后再确认，不用过期预览静默保存新价格。此项为待开发契约，离线原型未模拟并发修改主数据。
- **草稿：**按账号授权会话、项目、来源及行保留实际方法 ID、数量、时间、倍率及来源（方法默认/手动）。不能凭数值等于默认值猜标志，不能把所有恢复草稿都当手改。失效方法待重新确认，账号或授权变化清理草稿，不持久存私人信息。
- **保存状态：**沿用行卡完成态，提交中禁重复操作；拒绝保留输入及原因，未知结果先查询是否已保存，避免重复写。原型仅同步内存演示，不冒充真实服务异常验证。
- **记录：**实际方法是主要计量列，来源详情对照原提交与实际计量方法。手录无来源标“手动录入”，不伪造原送样方法。

HTML 没有独立“处理方式”框、子配置或必选关联项。普通液相示例仍按原行卡录入。ID用于程序识别，日常录入只显示名称、仪器和类型，不将内部 ID 附在名称后。

HTML 顶部的“示例来源方法”仅用于原型演示，不是生产录入允许编辑原方法。无分量时可切水分/通用理化/通用液相；录任一分量后锁定，刷新重置，不引入多来源容量模型。

## 5. 保存、统计与历史

复用 `work_records.method_id` 作为**实际计量方法 ID**，现有系数快照、金额倍率及执行归属保留。`source_type/source_record_id` 继续指向原送样来源，不改写成新方法来源。

补齐可追溯数据，具体字段位置在实施时结合已有快照契约确定，避免重复同义字段：

| 数据 | 保存原则 |
| --- | --- |
| 原提交方法 ID / 名称快照 | 从可信来源读取，不接受客户端任意覆盖；手录无来源为空 |
| 实际方法 ID / 名称快照 | 取确认的授权有效 ID，名称保留当时含义 |
| 系数快照 | 事务内从实际方法读取、校验，不相信客户端显示值 |
| 实际倍率 / 倍率来源 / 默认倍率快照 | 保存实际值及默认或手改来源，后续切方法不静默覆盖 |
| 类型及仪器快照 | 按实际方法捕获；原来源、账号、项目、执行归属和业务时间不丢失 |

方法统计、仪器、检测类型及导出按实际方法和原快照口径归类。独立 ID 的水分与水分-特殊处理分开显示，不按名称后缀或原方法自动合并；实验室、项目和人员总工作量仍汇总范围内的所有实际记录。

原提交方法是来源追溯信息，若提供其统计维度需明确标识，不能替代实际方法维度。以后若要业务族汇总，应显式配置分组；本轮不新增分组模型，不凭相似名称建隐性关系。

历史不批量改绑或重算：

- 原 `method_id=水分` 且无可信其他证据的记录保留原 ID 与系数。不能因系数2、3或备注“特殊”换成新方法。
- 实际方法身份不清楚时待核对；来源链可证明原提交方法时展示来源原文，不能证明时不猜填。
- 系数复核按**实际方法 ID**比较当前配置与快照。差异仅提示，管理员继续先预览、再选择确认；不把所有差异当错误。
- 系数修正不连带改实际方法、日期、人员、数量或手工倍率。倍率差异单独人工确认。
- 金额沿用当前方法单价口径，本轮不宣称已有历史单价快照。固定历史收费需要另外确认单价快照迁移，不暗改历史金额规则。

## 6. 主数据及接口范围

复用现有检测方法导入导出，不新增子处理方式模板。稳定方法 ID 有值时按 ID 更新，新增空 ID 自动生成；改名、换仪器、改系数保持身份。“跳过已有”仍不更新系数，覆盖/更新按当前模式执行，不重定义导入语义。未在表内的历史引用方法不能未经确认删除。

| 调整位置 | 必要改动 |
| --- | --- |
| `EntryPage` / `WorkloadEntryRow` | 保留原行，增加实际方法搜索及草稿，发送实际 ID，调整仅以项目关联阻断实际计量的旧判断 |
| `SampleWorkloadDialog` / `sampleWorkload` | 原方法与实际方法分开，授权有效候选跨仪器类型，保护手改倍率及草稿来源标志 |
| `rd.ts` / RD请求模型、预览与确认 handler | 加实际方法 ID及候选/默认契约；使用确认的 ID，不再固定写来源原 ID；原方法只读快照 |
| `RdRecordsPage` / `SampleEntryPage` / `SampleInfoEntry` | 同步所有回调/API透传，尤其样品登记逐字段构造请求，防止新字段丢失 |
| 服务/仓储准入 | 实际计量与送样关联分开；保留项目、实验室、部门、来源、方法/仪器、事务锁和累计容量；只在明确计量入口用新规则 |
| 记录/查询/导出/诊断 | 保留原方法及实际方法身份与快照；按实际方法统计及复核，历史不猜补 |
