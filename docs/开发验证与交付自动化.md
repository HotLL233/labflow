# 开发验证与交付自动化

共享工具位于仓库根目录，不修改已发布版本业务源码，不自动提交、推送、打标签、安装应用或连接生产数据库。统一使用 PowerShell 7；相对 SourceDir 按仓库根解析，OutputDir 按调用目录解析。请从仓库根执行以下命令。

## 1. 完整版本检查

```powershell
pwsh -NoProfile -File scripts/check-version.ps1 -SourceDir source/LabFlow-PostgreSQL-v2.3.70 -ExpectedTag v2.3.70
```

只读检查 VERSION、Cargo.toml、Cargo.lock（只定位 workload-tool）、前端两个 JSON 的根应用版本、两份 Inno Setup 的展示及四段数字版本、两份 Compose 的镜像默认版本，并核对版本目录名。ExpectedTag 只接受 vX.Y.Z；不修改依赖版本或历史数据库迁移。

## 2. 统一验证入口

```powershell
# 开发快速检查：全量发现前端 src/scripts 中的 *.test.mjs，类型检查，Rust 格式/编译检查
pwsh -NoProfile -File scripts/verify.ps1 -SourceDir source/LabFlow-PostgreSQL-v2.3.70 -Profile Quick -OutputDir test-artifacts/automation/quick

# 构建验证：再执行前端生产构建、gzip完整性检查、Rust Release；不自动运行数据库测试
pwsh -NoProfile -File scripts/verify.ps1 -SourceDir source/LabFlow-PostgreSQL-v2.3.70 -Profile Build -OutputDir test-artifacts/automation/build

# 可选只验证一侧：-Component Frontend 或 Backend（默认 All）
# 新设备无依赖时可显式加 -InstallDependencies；已有共享node_modules应使用原准备脚本，不对链接执行npm ci
pwsh -NoProfile -File scripts/prepare-local-build.ps1 -SourceDir source/LabFlow-PostgreSQL-v2.3.70 -InstallDependencies
```

前端构建在报告目录下创建独立 static-* 目录，不覆盖源码 backend/static。前端类型检查只执行一次，Vite 构建后复用现有压缩脚本，逐字节解压核对 gzip，并检查首页本地资源存在。Rust 复用 Cargo 配置和 CARGO_TARGET_DIR 指向的缓存，验证后将可执行文件快照到独立报告目录，避免后续共享缓存构建覆盖交付输入。

Integration 在 Build 基础上执行 cargo test --locked --lib，必须预先由操作者准备一次性隔离测试库，通过环境注入 WORKLOAD_TEST_DATABASE_URL，并显式加 -AcknowledgeIsolatedDatabase；本工具不创建、删除数据库，也不证明所填连接串确属隔离库。禁止填入生产连接串，禁止将连接串写进命令记录/报告。Integration 不能只选择 Frontend。

每次运行输出 verification.json 和逐步骤日志。passed 仅表示所选 profile/component 执行通过；浏览器、HTTP/Excel专项、现场覆盖安装、容器运行等未执行项均为 not_run，不代表完整验收。早期失败同样留下 failed 报告和未执行项，不复用旧 passed。日志不写入交付清单，但测试程序自身可能输出敏感信息，分享前检查脱敏。

## 3. 复用验证结果制作两种安装包

```powershell
pwsh -NoProfile -File scripts/build-installers.ps1 -SourceDir source/LabFlow-PostgreSQL-v2.3.70 -VerificationReport test-artifacts/automation/build/verification.json -OutputDir test-artifacts/automation/packages -IsccPath 'D:/APP/Inno Setup 6/ISCC.exe'
```

仅 Windows，必须提供当前 All + Build/Integration 报告。将已验证的前端产物与 Release 可执行文件复制到独立 staging，使用根共享运行库，两种安装器复用一次编译。每次 ISCC 调用单独检查退出码；不以旧包充当新输出。输出目录已有同名安装包时拒绝覆盖。

事前需准备 Inno Setup 6、根 build-resources 的 PDF/PostgreSQL/语言运行资源及 VC++ redistributable。本地入口不联网下载这些资源。INNO_SETUP_ISCC 可替代参数。原 build-resources/build_full_installer.ps1 改为兼容入口，可自动先验证，也可传入报告复用。

打包前后检查源码指纹、Git修订和产物哈希。源码或根自动化脚本改变后，旧报告失效，必须重新验证；仅更改文档不使报告失效。指纹为受控构建输入集合，不是整个仓库或运行配置快照，包含示例配置，不读取真实配置或凭据。报告/清单不是数字签名，不能防御有权限篡改文件的攻击者。

## 4. 自动交付清单

```powershell
# 只记录当前验证，不冒充已经出包
pwsh -NoProfile -File scripts/write-delivery-manifest.ps1 -SourceDir source/LabFlow-PostgreSQL-v2.3.70 -VerificationReport test-artifacts/automation/build/verification.json -OutputDir test-artifacts/automation/delivery

# 已有正式安装包：-ArtifactPath 支持数组，-RequireWindowsInstallers 强制检查两种包名称和内嵌版本
# 镜像可提供 -ImageReference 和 -ImageDigest，记录 CI 返回的摘要；不自行声明远端拉取/运行成功
```

固定输出 manifest.json、SHA256SUMS、交付清单.md，包含版本、Git提交、限定输入范围的 dirty 状态、输入指纹、工具链、文件大小/SHA-256、Windows文件/产品版本、验证范围和未完成验收。未提供验证报告时为 not_run；过期/失败/不完整报告会拒绝生成。两种安装包必须精确匹配 LabFlow-vX.Y.Z.exe 与 LabFlow-vX.Y.Z-HotUpdate.exe，且内嵌文件及产品版本均为 X.Y.Z.0。

清单 status=recorded 表示事实已记录，不等于所有验收通过；Quick 不能充当可打包报告，Build 不等于数据库测试通过。验证范围和完整报告嵌入清单，未执行事项不得改写为成功。

## 5. CI 与测试

标签发布和手动发布都走完整版本校验；手动必须明确填写三段版本号，不按最大目录猜测。Windows 调用同一验证及打包入口，上传安装包和交付清单；Docker 先验证/重建前端，再把独立静态产物放入临时 CI checkout 的镜像上下文，并保存镜像摘要清单。数据库和现场验收仍须专项执行。旧标签没有新增脚本，因此重跑历史 tag 不会自动获得本工具；需在包含工具的提交上显式手动选版本。

```powershell
pwsh -NoProfile -File scripts/test-automation.ps1
```

以上仅执行自动化脚本自身隔离测试，不调用 ISCC、不编译真实应用、不触碰数据库或服务。既有共享缓存准备测试需单独执行 scripts/tests/prepare-local-build.Tests.ps1（Windows junction专项）。CI上线需实际执行工作流后验收，本地通过不代表GitHub已发布。
