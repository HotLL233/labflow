LabFlow 记录表改版预览

研发送样记录 / 样品信息登记记录 · 列标题与字段取自 v2.3.19 数据库最新配置（postgres_seed.sql、v1.1.5-beta.2、v2.3.5、v2.3.12），示例内容为真实业务数据样式。

目标 一页显示全部列，且列内容尽量完整显示。两张表都不新增横向滚动条。

改后列宽是怎么算出来的

  • 列宽 = 内容测量：max(表头宽度, 当前页内容 P90 宽度) + 内边距，后台配置的 px 从「固定宽度」降级为「权重参考 + 上下限」。
  • 可扩展列吸收富余：样品批号 / 样品主要成分 / 注意事项 优先吃剩余空间，最多放到自然宽的 2.2 倍。
  • 长文本两行换行：超出一行时纵向展开到两行，去掉单元格内滚动条，悬停显示全文。
  • 操作列封顶：按容器宽度取文字档 / 图标档 / 收纳档三档之一，不再按按钮宽度累加。
  • 表头允许两行：直接使用库里的 label 原文，不另造简称；表格宽度固定为 1360px 以便对照。

三、两张表共用的交互

  • 表头两行折行：直接使用库里 label 原文（下次再评估是否给「实验室/车间」配简称），排序箭头与筛选漏斗跟随文字换行，不占额外列宽。
  • 长文本两行 + 悬停看全文：样品主要成分、注意事项、方法、样品批号 超出一行时展开到两行，鼠标悬停显示完整内容（title）。
  • 列设置：可勾选显示哪些列，按「用户 + 表名」记住；不勾选时列宽自动重新分配。
  • 表头筛选：多选 + 搜索，作用范围标注为「本页 N 条」；已选条件以标签形式汇总，可单独移除。
  • 固定表头 + 冻结前两列（可选）：表头在 72vh 内滚动时固定；横向空间极窄时可冻结序号与送样人列。
  • 操作列三档：≥1400px 文字档（主操作 + 次操作 + 更多）／1024~1400px 主操作 + 更多（本次预览形态）／<1024px 仅更多菜单。

四、窄屏（1280px / 1024px）降级顺序

级手段省下触发
L1表头两行折行（已含在本次预览）20~40px始终
L2单元格内边距 12 → 8px、字号 13 → 12.5px、行高 36 → 32px约 6%总需求 > 容器宽
L3长文本列两行换行（已含在本次预览）长列 30%~45%内容超自然宽
L4「所属部门 / 实验室/车间 / 所属项目」竖排合并为一列「组织」2 列宽仍不足（仅这两张表可配）
L5数量/时间列切紧凑，时间保留「MM-DD HH:mm」约 4%仍不足
L6隐藏最低优先级列，表尾提示「N 列未显示 · 点此展开」按列计> 14 列且容器 < 1280px
L1~L5 全程保持全部列在一页内，不产生横向滚动；只有 L6 会隐藏列并明确提示。两张表在 1440px 与 1280px 下均可完整显示全部列，1024px 需启用 L2 + L4。

五、列宽配置机制：默认值 + 可修改 + 可恢复默认

现状：可配置，但只有一个真值 页面上那些数字不是写死的——它们来自后台配置。但目前只有「一个真值」：后台把 px 写进 sample_info_columns.width / rd_record_columns.width，前端再归一化成百分比。缺三样东西：
  • 没有「未配置」状态：每列必有值，所以内容测量永远没有机会接管，这也是 getAdaptiveColumnWidths 里那套测量逻辑变成死代码的原因。
  • 没有默认值兜底：某个值被改坏（例如误填 500）后，没有任何参照可以回退。
  • 没有「恢复默认」入口：想还原只能凭记忆手工改回去。

级别存储位置谁维护生效条件
① 系统默认代码常量 DEFAULT_WIDTH_BOUNDS（不入库）开发者永远存在的兜底值
② 内容测量运行时计算（不入库）系统该列处于「自动」模式

优先级：④ 用户覆盖 > ③ 管理员覆盖 > ② 内容测量 > ① 系统默认。
默认落在哪一级：新装库与老库升级统一默认走「自动」（②），升级即生效，无需管理员逐列开启。管理员原有的 width 值保留在字段里不删除，随时切回「自定义」（③）即可复用；列管理页另设「全部列改为自定义」作为整体回退。

1. 数据层：两个新字段 + 一个系统开关

-- 列级：宽度模式。默认 auto，升级后立即按内容测量生效
ALTER TABLE rd_record_columns   ADD COLUMN IF NOT EXISTS width_mode TEXT   NOT NULL DEFAULT 'auto';
ALTER TABLE sample_info_columns ADD COLUMN IF NOT EXISTS width_mode TEXT   NOT NULL DEFAULT 'auto';
-- 升级时保留原有 width 值不动，切回 custom 时可直接复用

-- 列级：可选的自定义区间（0 表示沿用系统默认区间）
ALTER TABLE rd_record_columns   ADD COLUMN IF NOT EXISTS min_width BIGINT NOT NULL DEFAULT 0;
ALTER TABLE rd_record_columns   ADD COLUMN IF NOT EXISTS max_width BIGINT NOT NULL DEFAULT 0;
ALTER TABLE sample_info_columns ADD COLUMN IF NOT EXISTS min_width BIGINT NOT NULL DEFAULT 0;
ALTER TABLE sample_info_columns ADD COLUMN IF NOT EXISTS max_width BIGINT NOT NULL DEFAULT 0;

-- 操作列收纳开关（本次决策新增）
--   auto = 按容器宽度三档自动收敛（默认）
--   full = 始终显示全部按钮，维持升级前体验
INSERT INTO system_settings(key, value) VALUES ('record_table_action_mode', 'auto')
ON CONFLICT DO NOTHING;

「未配置」的三种等价写法：width_mode='auto'、width=0、width=NULL。命中任意一种即走内容测量；width_mode='custom' 时 width 才作为固定宽度参与归一化。

已确认：老库升级默认走「自动」。升级后两张表立即按内容测量排布；管理员原有的 width 值保留在数据库里但不生效，若某列想改回固定宽度，切到「自定义」即可直接沿用原值。如果整体不满意，列管理页的「全部列恢复自动宽度」旁边提供一个反向按钮「全部列改为自定义」，一键回到升级前的固定宽度模式。

5. 顺带修正一处把缺陷写成说明的文案

ManagePage.tsx:2277 现有提示是「记录列表按宽度比例铺满页面，长内容在单元格内滚动」。建议改为：「自动模式按内容计算宽度，长内容两行展开；自定义模式按设定宽度固定，可在列设置中恢复自动」。

请重点确认四件事：
  • 操作列收纳为「主操作 + 更多 ▾」是否可接受？如果不接受，样品信息登记表就只能走 L4 合并列来腾空间。
  • 表头是否要保留库里 label 原文（「实验室/车间」「样品主要成分」会占两行）？还是允许配置简称（如「实验室」「主要成分」）缩短表头？
  • 改后把「实验室/车间 65→60、所属项目 78→60、注意事项 116→170」这类此消彼长的调整是否符合预期优先级？
