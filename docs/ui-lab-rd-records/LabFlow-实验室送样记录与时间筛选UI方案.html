实施方案说明

仅方案，不修改代码

入口与默认行为

实验室详情页在原“工作量录入”旁增加“本实验室送样记录”。首次进入仍显示工作量表单；主动切换后展示研发记录，顶部切换持续保留。分析检测入口的实验室卡片保留原进入工作量按钮，并增加“查看送样记录”次按钮。

记录入口复用现有研发送样列表，不复制一套业务页面。全局研发记录页可以选择实验室；从实验室页面或卡片进入时固定当前实验室，重置、时间切换、分页都不能解除实验室限制。建议新增 /entry/:groupId/sample-records 路由，复用同一记录组件并使用分析入口的独立授权范围。

切换两项功能保留实验室与公共账号所选人员上下文，并可恢复记录时间条件、页码和滚动位置；切回工作量不会改变录入日期或数量。未提交表单草稿应保留，无法保留时离开前明确确认。本原型在页内切换时保留表单值，但不实现持久草稿保存。

保留已有配置与业务操作

项目方案
列宽、顺序、显示开关复用管理员现有全局列配置；同一个研发记录组件在两个入口使用同一规则。
字段边框、卡片、按钮复用现有内外边框颜色/粗细、手机分组、按钮顺序/大小/位置配置。本原型只是当前样式示意，不新增独立覆盖规则。
记录操作待取样显示取样、编辑、退回送样；退回待修改保留编辑与查看原因；已取样保留录入工作量和服务器允许时的撤回取样。可以查看记录不会自动开放编辑或删除，各操作仍检查原权限。示例中显示“已录入”的记录明确作为全部录入完成示意；真实状态须使用后端录入结果及剩余数量，不能仅凭工作量数值非空判断。原型不模拟保存。
人员与工作量归属保留公共分析账号所选人员上下文，切页不清空。subject_user_id 只作为取样身份上下文，不能误当成送样人筛选；工作量仍归属于实际登录录入账号。记录页面可见不等于自动获得工作量录入权限。

权限、时间与数量口径

  • 当前研发接口权限与普通分析账号并不等同：旧入口需要研发录入或研发范围权限，且研发实验室范围可能强制为用户所属实验室。新分析入口必须建立独立授权 scope，不修改原研发 scope，也不给分析用户授予 rd:view-all。
  • 建议在角色管理中新增最窄的“查看本实验室送样记录”权限。是否补入默认角色模板，实施时确认；查看权限与编辑、删除和录入工作量权限分开。
  • 后端固定 group_id，并将分析账号获准实验室/部门范围与固定实验室求交。每条记录还要按检测执行部门快照及现有回退规则授权，不能仅凭实验室当前所属部门放行历史记录。前端锁定标签只说明范围，不能替代后端授权。
  • 默认以送样时间 recorded_at 筛选；默认全部时间、所有状态，不先过滤待取样或只显示本周。现有 getRdRecords 已支持 start/end/group_id，可复用现有 ISO 周 DateRangePicker。
  • 本周和上周以周一至周日为界，近7天包含示例当天，自定义结束日包含全天。实施需校验合法日期，并将现有结束日拼接 T23:59:59 改为“结束日下一天零点”的排他上界，避免漏掉最后一秒的小数秒记录。
  • 新的实验室与时间条件由服务端在全部可见记录中筛选，再分页和计数；列表、总条数和分页共用条件。现有表头列筛选仅影响当前页，应保留这一行为并明确区分，不能宣称旧列筛选已变成全量。
  • 现有研发记录入口没有导出，本次不增加额外导出按钮。今后若接入现有导出能力，应使用相同后端权限、实验室及时间条件。
  • 时间筛选不改变记录、金额、系数快照、历史归属，也不影响工作量表单和原业务流程。

上线前验证

核对管理员、部门范围人员、普通人员与公共账号的可见记录；核对跨实验室请求拒绝、空权限范围、周日/周一边界、自定义结束日、无结果、多页计数。检查桌面一页显示全部列、仅单元格内部滚动，以及手机四组字段与 40px 操作按钮。列配置修改应同时影响原研发记录页和新实验室入口。
