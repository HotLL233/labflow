间距为什么重要

MUI 的间距单位是 8px，法律值只有 0 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64。实际用到的 32 档里，出现频次最高的边缘值暴露了问题：

值实际像素次数性质
0.252px31违反最小档 4px
0.32.4px12目测微调残留
0.352.8px8目测微调残留
0.43.2px8目测微调残留
0.756px122合法但应与 4 / 8 二选一
1.2510px46合法但夹在 8 / 12 之间

2.4 / 2.8 / 3.2px 这三个值没有任何视觉意义，它们是「看起来差一点，手动推两个像素」的产物。这类值会指数级增长——每改一次界面就可能多一个。

07结构性判断：这个产品的 UI，是配出来的

这一条决定了方案形态，比前面任何一条都重要。

系统里有大量「管理员可配外观」的能力，且它们直接写色值：

配置入口可配内容落盘形式
表格样式栏 TableStyleBar行高 24–90、表头高、边框色、斑马纹、辅助字号、按钮宽十六进制 + 数值
建议默认表 DEFAULT_RECORD_TABLE_STYLE38/36px、#d9dfe7 边框、#e0e0e0 卡片边、#fafbfd 斑马常量
布局设计器 LayoutDesigner / PageLayoutAdmin页面区块、字段顺序JSON
字段库 FieldLibrary / FieldPropertyPanel字段类型、样式JSON
条件格式 ConditionalFormatDialog按值上色十六进制
主题设置主色、辅色、背景色、圆角十六进制
这就是 896 处硬编码的真正来源。 不是开发者随手写死，是配置系统的数据模型里，「颜色」这个字段的类型就是十六进制字符串。每配一次表格样式、每设一条条件格式，就新增一个游离色值，它们不进主题、不受约束、不会被人统一。

所以：再改一轮颜色，数字也不会降。 只要配置层还能写 hex，它就会自己生产新的。

反过来说，这套配置能力本身是这个产品最值钱的界面资产——recordTableStyle.ts 的三级解析（个人视图 → 全局 → 默认）配合 safeNumber 的范围钳制（行高 24–90、字号 9–24、边框 0–3），工程质量明显高于界面其它部分。它是资产，不该被推翻；它缺的是一层能托住它的语义层。

08方案：给配置系统加一层语义，而不是再改一轮颜色

目标不是「统一好看的色板」，而是让配置层从「填十六进制」变成「选语义」。

L0
原始值
唯一真源。只允许在这里出现十六进制。约 24 个灰阶 + 4 个语义各 5 阶 = 44 个值封顶，替代现在的 219 个。
L1
语义令牌
brand success warning danger info text-1/2/3 surface-1/2/3 border。每个语义只有一个正文达标值 + 一个 soft 底，对比度在定义时就验过五种底色。
L2
组件令牌
chip.success btn.primary table.header card.border。组件只引用 L2，不碰 L0。状态色从此只有一处定义，样品登记页 / 统计页 / 记录页自动一致。
L3
配置层
后台与样式栏只允许选 L1 语义名，不提供 hex 输入框。存量配置在读取时把旧 hex 映射到最接近的语义名，写回时只写语义名。这是止血的关键一步。

落地约束（必须同时满足，否则会退回去）

  • 表格引擎不重写。 recordTableStyle.ts 的解析顺序、钳制范围、版本号全部保留，只把默认值里的 hex 换成 L1 令牌引用。
  • 不只验白底。 每个语义色必须同时给出在 #ffffff / #fafafa / #f5f5f5 / 语义 soft 底 上的对比度，全部 ≥4.5 才算通过。v2.3.63 的 #757575 就是漏了这一步。
  • 字号收敛到 6 档。 20 / 16 / 14 / 13 / 12 / 12 — 把 0.70–0.80 那 5 档合成 12px 与 13px 两档，视觉差异靠字重和颜色做。 改动面大，需单独评估
  • 间距回到 4px 网格。 2.4 / 2.8 / 3.2px 一律就近归到 2 或 4px。这一项风险最低、收益直观。

09明确不建议动的

资产原因
recordTableStyle.ts 样式引擎三级解析 + 范围钳制 + 版本号迁移，是全站工程质量最高的部分。只接令牌，不重构
表格 38/36px 行高、1px 描边高密度是这类工具的正当选择，不是缺陷。密度问题靠字号与留白解决，不靠加高行

10需要你拍板

1
品牌主色到底是哪个现在是三套并存：主题 #667eea、界面最大宗 #2e7d32、Material 蓝 #1976d2。不选定，L1 层就没法建。
从数据看，#2e7d32 是唯一「既达标（5.13）又已是最高频（77 次）」的候选，改造成本最低。
2
配置层的 hex 输入能收掉吗S1 的成败取决于这一条。如果必须保留自由配色（比如客户要求按自己 VI 配），那方案要改成「自由配色 + 语义默认值」，治理效果会明显打折，需要提前知道。
3
字号要不要动18 档收敛到 6 档，视觉收益明显，但会触及大量页面布局细节。是放进 S1 一起做，还是单独开一版专门处理。
4
移动端底栏是否改四格这一项不在配色范围内，属于 IA 调整。改了会影响现场人员的使用习惯，需要你判断接受度。
