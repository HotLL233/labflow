# LabFlow v2.3.51 交付包

本包可用于在另一台 Windows 电脑继续开发、重建完整安装包或直接测试安装包。

当前迭代为 `v2.3.51`，源码隔离自正式 v2.3.50；开发验证与本地两种安装包构建完成，GitHub/GHCR 发布准备中。

记录页默认按北京时间加载今天及前29天，研发送样按送样时间 recorded_at，样品信息登记按 submitted_at 查询。点击“全部历史”或应用自定义日期后才请求对应范围，原本的今日记录与统计日期口径不扩大。取样等操作以服务端成功响应更新单行，再后台校正当前筛选、排序、计数和分页；旧请求不得覆盖新查询。手机只挂载当前布局，详情首次展开才创建，保留全部自定义列、按钮、配色、摘要、字号和边框配置。

减少重复初始请求与同键配置在途请求；时钟单独更新；实验室工作量面板首次访问才挂载且访问后保留草稿。统计切表复用相同条件的公共聚合，成功编辑/删除及返回页面仍刷新；预览分页仅限制渲染，完整汇总与导出保持。数据库复用真实 PreparedStatement，归还连接不再探活，用户/角色关联整批读取，会话每请求即时校验，不缓存权限。记录查询、取样和工作量确认的完整同步调用链移入阻塞线程；取样事务锁源记录并保留审计，默认列表来源工作量每行单次聚合，操作筛选仍需范围聚合，实验室访问检查不再读取全部门户卡片。静态资源提供预压缩 gzip 和哈希文件缓存，HTML重新验证，主题请求设超时。

验证：最终前端62项回归、类型检查与生产构建通过；首轮后端完整测试189通过、3项备份测试跳过，SQL及错误映射最终定稿后23项相关真实PostgreSQL回归全部通过；PostgreSQL兼容层10项测试通过。Rust fmt/check（console）及默认非console Release构建通过。上述测试数量不相加为唯一测试数量，历史版本结果不计入本版。

大表验证：专用测试库新建bm51隔离schema，研发送样/样品各5万条跨730日及日期边界，1121项SQL断言、20组查询测量通过；原模板/public记录与迁移数量和哈希不变。暖查询中位数：研发送样近30天列表237.099ms、计数234.252ms，全量列表208.806ms、计数33.492ms；样品近30天列表2.436ms、计数2.513ms。研发日期安全解析与编号窗口仍有成本，不能宣称日期筛选必然更快；数据仅为数据库执行，不含权限链、网络、JSON与浏览器，不报旧版提速百分比。普通分页来源SUM每页仅50次，操作筛选/候选仍按当前范围聚合。

## 开发续接与记忆惯例

- 开始开发或更换设备后，必须先阅读仓库根目录的 `PROJECT_MEMORY.md`。
- `PROJECT_MEMORY.md` 是项目唯一、跨版本、跨设备的长期记忆与开发惯例来源；后续确认的业务规则、技术决策、问题根因、环境约定和发布经验只更新该文件，并随 Git 提交。
- 不再新增或维护按日期记忆、`历史记忆_*.md`、`开发交接_*.md`、`续接提示词_*.md` 或 `HANDOFF.md`；旧版本目录中的同类文件只作历史归档，不得作为当前规则来源或复制到新版本。
- 版本 `更新说明.md` 和专项文档仍按用途维护，但不得复制一套长期记忆。规则冲突时以当前用户要求、当前源码与工作流、`PROJECT_MEMORY.md` 的顺序为准。

1. 当前源码目录（发布准备中）：`source/LabFlow-PostgreSQL-v2.3.51/`。行为、验证与交付状态见本版 `更新说明.md` 与根 `PROJECT_MEMORY.md`。
2. Gitee 源码仓库：`https://gitee.com/HotLL233/labflow`（自 v2.3.18 起暂停向 Gitee 推送，仅保留历史仓库）。
3. Docker 部署使用 `docker-compose.deploy.yml`，推荐执行 `scripts/pull-labflow-image.ps1`（Windows）或 `scripts/pull-labflow-image.sh`（Ubuntu）。
4. 脚本按 `LABFLOW_IMAGE_PRIORITY` 依次尝试已配置的镜像地址，成功后再启动 Compose；Gitee 镜像地址未配置时跳过，目前发布仅使用 GHCR。
5. v2.3.19 起 JWT 签名密钥由部署自动生成并保存在数据目录 `jwt_secret`；如需集中管理，可用环境变量 `JWT_SECRET` 覆盖（长度需 ≥16 位）。数据库会话时区跟随程序所在机器，容器部署默认 `TZ=Asia/Shanghai`。
6. 从 v2.3.18 升级到 v2.3.19 后所有已登录会话会失效一次，用户需重新登录，之后重启与升级不再失效。

本包不含任何生产数据库、附件、备份、实际服务器配置、登录凭据或用户本机数据。

打包口径（v2.3.13 起固化为发布规范）：

- 安装包文件名沿用 `LabFlow-v<版本>.exe`（完整服务器版）与 `LabFlow-v<版本>-HotUpdate.exe`（热更新升级包）。
- 发布流程根据 tag `v<版本>` 自动构建，并**自动提交到仓库根 `installers/` 目录**，同时上传 GitHub Release。
- 本地留档副本放在对应版本目录的 `installer/` 中；该目录被 `.gitignore` 忽略，不进入版本库。
- Docker 镜像由发布工作流推送到 GHCR（`ghcr.io/hotll233/labflow:<版本>` 与 `latest`）；向 Gitee registry 的同步自 v2.3.18 起暂停。
