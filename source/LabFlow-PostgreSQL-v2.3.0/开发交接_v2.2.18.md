## 2. 本版完成内容

本版实现统一的 Excel 式导出模板编辑器，入口为：

`管理中心 -> 导出模板配置`

覆盖三类导出：

1. 分析检测统计：设置键 `export_template_workload`，13 张工作表。
2. 研发送样统计：设置键 `export_template_rd`，11 张工作表。
3. 样品信息登记：设置键 `export_template_sample_info`，明细和 6 张维度汇总表。

每张工作表可配置：

- 是否导出
- 工作表名称和标签颜色
- 列表头文字
- 列宽
- Excel 中显示或隐藏列

配置会实际传入 Excel 写入器，不是仅前端预览。保存前会校验至少保留一张工作表、名称非空、31 字符限制、Excel 非法字符和重复名称。

## 4. 历史模板兼容

旧版本部分模板字段键与当前 Excel 物理列不一致。前端加载时由 `normalizeTemplate()` 执行以下规则：

- 保留仍存在的工作表名称、颜色、启停状态。
- 仅保留仍映射到当前物理列的表头、列宽和显示状态。
- 丢弃退休字段键，补齐当前导出真实列。
- 管理员打开模板配置并点击保存后，系统设置会被更新为当前结构。

不要恢复旧字段键，也不要直接把历史 JSON 复制回 `system_settings`。

## 5. 有意保护的结构

以下不允许由模板编辑器修改：

- 列顺序。
- 工作量、金额、合计等 Excel 公式。
- 字段数据来源和统计 SQL。
- 研发送样 Sheet6 的按检测类型动态列。

原因是导出写入器的合并单元格、公式引用和统计列位置依赖固定物理列。若后续需要“拖拽换列”，必须先把全部导出写入器改为按模板字段定义输出，不能只开放 UI 排序。

样品信息“记录明细”的动态业务字段仍由既有的样品信息列配置管理；本版模板编辑器负责该 Sheet 的名称、颜色和匹配字段的展示配置。

## 7. 构建完整安装包惯例

完整服务器安装包必须包含：

- `target/release/workload-tool.exe`
- `backend/static/*`
- `pdf-runtime/*`
- `postgres-runtime/bin/*`
- `postgres-runtime/lib/*`
- `postgres-runtime/share/*`
- `postgres-runtime/installer/vcredist_x64.exe`
- `installer-languages/ChineseSimplified.isl`

构建在临时目录中进行，禁止把运行时、`target`、`node_modules` 或安装包留在干净源码目录。当前参考命令：

```powershell
# 在临时构建目录
New-Item -ItemType Junction -Path frontend\node_modules -Target <已有依赖目录>
Set-Location frontend
npm run build
Set-Location ..
cargo build --release
& 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe' .\build_server_installer.iss
```

前端 Vite 配置将生产文件直接输出到 `backend/static`。完整安装包用 `build_server_installer.iss`；已有完整服务器安装后的小范围升级可用 `build_hot_update_installer.iss`，但首次安装或跨电脑测试必须使用完整服务器安装包。

版本号必须同步修改：

- `VERSION`
- `Cargo.toml`
- `frontend/package.json`
- `build_server_installer.iss`
- `build_hot_update_installer.iss`
- 本版本的更新说明文件和两个安装包文件名

完整安装包输出后必须校验：

```powershell
$file = Get-Item '<安装包路径>'
$file.VersionInfo | Format-List FileVersion,ProductVersion,ProductName
Get-FileHash $file.FullName -Algorithm SHA256
```

## 9. 后续开发约束

- 每个版本必须新建仅用版本号命名的源码目录。
- 只复制源码，不复制 `target`、`node_modules`、`backend/static`、安装包或本地数据。
- 先阅读涉及的导出写入器和调用方，再修改；禁止只改前端造成配置不生效。
- 修改导出统计必须区分：工作量 = 数量 x 系数；金额 = 数量 x 单价 x 单价倍率。
- 本项目没有需要恢复的“部门角色”逻辑，使用角色和权限范围管理数据可见性。
- 完成功能和测试后主动构建安装包，不等待提醒。
- 编码任务遵循 `ponytail`：复用现有模式，最小改动，禁止无需求的抽象和依赖。
