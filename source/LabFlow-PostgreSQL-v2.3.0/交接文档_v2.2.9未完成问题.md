## 二、未完成的重要问题（需优先解决）

### 问题1: 辅助工作系数错误 🔴 高优先级

**问题描述：**
分析检测导出中，辅助工作（如"辅助工作-流动相1"）的系数错误地使用了pH=1，而不是检测方法本身的系数。

**举例：**
- 检测方法：液相色谱（系数1.7）
- 辅助工作：流动相配制
- **错误**：辅助工作系数显示为 1（pH方法的系数）
- **正确**：辅助工作系数应该是 1.7（液相色谱的系数）

**根本原因：**
数据库查询时，辅助工作关联到了错误的方法。需要修改查询逻辑，让辅助工作使用其所属检测方法的系数。

**需要修改的文件：**
- `src/api/export_data.rs` - Sheet 5和Sheet 6的查询函数
  - `query_sheet5_data()` 
  - `query_sheet6_data()`

**修改思路：**
1. 查询辅助工作记录时，需要JOIN到主检测方法
2. 使用主检测方法的系数，而不是辅助工作本身记录的系数
3. 可能需要在`work_records`表中找到辅助工作与主检测方法的关联关系

**问题描述：**
当前Sheet 6（检测人员汇总表）显示了大量辅助工作的详细列，导致表格极宽，难以查看。

**当前显示（错误）：**
```
检测人员 | 总工作量 | 个人工作量汇总 | 理化数量 | 理化系数 | 理化工作量 | 
辅助工作-pH计校验数量 | 辅助工作-pH计校验系数 | 辅助工作-pH计校验工作量 |

辅助工作-流动相2数量 | 辅助工作-流动相2系数 | 辅助工作-流动相2工作量 |
```

**应该改成（正确）：**

- **辅助工作量** = 所有辅助工作的工作量汇总（一个数字）

**需要修改的文件：**

```sql
-- 当前可能的查询（错误）
SELECT wr.user_name, m.name, m.coefficient, ...
FROM work_records wr
LEFT JOIN methods m ON wr.method_id = m.id
WHERE ...

-- 应该改成（正确）
SELECT wr.user_name, m.name, 
       CASE 
         WHEN m.name LIKE '辅助工作%' 
         THEN (SELECT parent_m.coefficient 
               FROM work_records parent_wr
               JOIN methods parent_m ON parent_wr.method_id = parent_m.id
               WHERE parent_wr.id = wr.parent_work_record_id)
         ELSE m.coefficient
       END as coefficient,
       ...
FROM work_records wr
LEFT JOIN methods m ON wr.method_id = m.id
WHERE ...
```

### 问题2修复步骤（Sheet 6辅助工作汇总）

**步骤1：修改`write_sheet6()`表头生成**
在`src/api/export_write.rs`中：
```rust
pub fn write_sheet6(...) -> Result<()> {
    // 过滤掉辅助工作类型
    let detection_types: Vec<&str> = types
        .iter()
        .filter(|t| !t.starts_with("辅助工作"))
        .map(|s| s.as_str())
        .collect();
    
    // 列顺序：检测人员(0) | 总工作量(1) | 检测工作量(2) | 辅助工作量(3) | 理化...(4+)
    let grand_total_col = 1;
    let detection_workload_col = 2;
    let auxiliary_workload_col = 3;
    
    // 表头
    ws.write_with_format(HR, 0, "检测人员", &fmt.fh)?;
    ws.write_with_format(HR, grand_total_col, "总工作量", &fmt.fh)?;
    ws.write_with_format(HR, detection_workload_col, "检测工作量", &fmt.fh)?;
    ws.write_with_format(HR, auxiliary_workload_col, "辅助工作量", &fmt.fh)?;
    
    // 只显示非辅助工作的检测类型
    for (index, label) in detection_types.iter().enumerate() {
        let base = 4 + index as u16 * 3;
        ws.write_with_format(HR, base, format!("{}数量", label).as_str(), &fmt.fh)?;
        ws.write_with_format(HR, base + 1, format!("{}系数", label).as_str(), &fmt.fh)?;
        ws.write_with_format(HR, base + 2, format!("{}工作量", label).as_str(), &fmt.fh)?;
    }
    
    // ... 数据写入逻辑
}
```

```rust
pub struct AuxiliaryWorkRow {
    pub user_name: String,
    pub auxiliary_method: String,  // 辅助工作方法名
    pub quantity: i64,
    pub coefficient: f64,
}
```

**步骤2：编写查询函数**
```rust
pub fn query_auxiliary_work_details(
    conn: &Connection,
    start: &str,
    end: &str,
    subject_user_id: Option<i64>,
    scope_group_id: Option<i64>,
    allowed_division_ids: Option<&[i64]>,
) -> Result<Vec<AuxiliaryWorkRow>> {
    let sql = "
        SELECT wr.user_name,
               m.name as auxiliary_method,
               SUM(wr.quantity)::BIGINT,
               m.coefficient  -- 这里需要使用主检测方法的系数
        FROM work_records wr
        LEFT JOIN methods m ON wr.method_id = m.id
        WHERE wr.deleted_at IS NULL 
          AND m.name LIKE '辅助工作%'
          AND wr.recorded_at >= ?1
          AND wr.recorded_at <= ?2
          AND (?3 IS NULL OR wr.subject_user_id = ?3)
          AND (?4 IS NULL OR wr.group_id = ?4)
        GROUP BY wr.user_name, m.name, m.coefficient
        ORDER BY wr.user_name, m.name
    ";

}
```
