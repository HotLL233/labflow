# 分析检测工作量导出表统一与辅助工作量修复方案

## 1. 当前问题结论

### 1.1 导出表格式没有统一

当前分析检测导出包含 13 张 Sheet，但同一概念在不同表中使用了不同名称和顺序：

| 表 | 当前定位 | 主要问题 |
|---|---|---|
| Sheet1 | 实验室-项目-方法明细 | 同时混入检测数量、项目合计、高项，列顺序与其他明细表不同 |
| Sheet2 | 仪器按日汇总 | 日期、仪器、实验室、项目、方法顺序与人员明细不一致 |
| Sheet3 | 项目金额汇总 | 金额字段存在，但没有与工作量字段形成统一口径 |
| Sheet4 | 实验室金额汇总 | 与 Sheet3 的维度顺序不同，数量合计和金额合计命名不一致 |
| Sheet5 | 检测记录明细 | 是原始记录，但缺少统一的来源、工作量字段说明 |
| Sheet6 | 人员工作量明细 | 第一列实际写入检测人，模板却标为“项目”；查询层的 project 字段为空 |
| Sheet7/8 | 实验室/项目总表 | 以检测类型动态展开，适合金额查看，但不适合与明细逐行核对 |
| Sheet9/10/11 | 仪器、理化、事业部汇总 | 汇总粒度和列命名各自独立，无法快速追溯到明细 |
| Sheet12 | 辅助工作明细 | 查询的是 `work_records` 中类型为“辅助工作”的旧兼容记录，不是新辅助工作表 |
| Sheet13 | 人员工作量汇总 | 仍只查询 `work_records`，新辅助工作记录不会进入人员总工作量 |

### 1.2 辅助工作量不同步的根因

2.2.15 的辅助工作功能使用独立数据表：

- `auxiliary_work_items`：公共辅助工作定义和系数。
- `auxiliary_work_records`：人员、辅助工作名称、系数快照、数量、时间等记录。

但当前 2.2.16 的 `query_auxiliary_work_details` 仍然：

```sql
FROM work_records wr
LEFT JOIN method_type_links ...
WHERE ... method_types.name = '辅助工作'
```

这会造成两个结果：

1. 通过新辅助工作入口录入的数据不出现在 Sheet12。
2. Sheet6、Sheet13 也不会统计新辅助工作，导致“辅助明细”和“人员总工作量”不一致。

另外，辅助工作是公共工作量，不属于任何实验室；当前旧查询仍带有项目/实验室兼容字段，容易让用户误以为辅助工作属于某个实验室。

## 2. 统一设计原则

不把 13 张表强行做成完全相同的列，而是统一四类报表契约：

### A. 原始明细类

统一顺序：

`日期 | 来源 | 检测人 | 实验室 | 项目 | 检测类型 | 方法/辅助工作 | 仪器 | 数量 | 系数 | 倍率 | 工作量 | 金额`

- 辅助工作：实验室、项目、仪器、倍率、金额为空或显示“-”。
- 工作量只计算 `数量 × 系数`。
- 金额只计算 `数量 × 单价 × 倍率`。

### B. 工作量汇总类

统一顺序：

`人员 | 来源 | 检测类型/辅助工作 | 数量 | 系数 | 工作量`

- 来源为“检测”或“辅助工作”。
- 按人员分组，人员总工作量使用 Excel `SUM` 公式。
- 同一人员、同一来源、同一类型/工作、同一系数合并为一行。

### C. 金额汇总类

统一顺序：

`实验室/项目 | 检测类型 | 方法 | 数量 | 单价 | 倍率 | 明细金额 | 汇总金额`

- 仅检测记录进入金额表。
- 辅助工作不得进入金额、单价、倍率统计。

### D. 维度汇总类

统一公共格式：

- 第一行：导出标题和统计期间。
- 第二行：字段表头。
- 第三行开始：数据。
- 固定字体、边框、冻结表头、自动筛选、数字格式和合计行。
- 所有名称优先显示快照，没有快照时才回退到主数据名称。

## 3. 辅助工作修复方案

### 3.1 建立统一统计事实视图

新增一个只读统计视图或等价的查询层 `workload_facts`，使用 `UNION ALL` 合并两类来源：

1. 检测记录：来自 `work_records`，`source_type='检测'`。
2. 辅助记录：来自 `auxiliary_work_records`，`source_type='辅助工作'`。

统一字段：

`recorded_at, source_type, user_name, group_name, project_name, type_name, work_name, instrument_name, quantity, coefficient, multiplier, unit_price, workload, amount`

辅助记录固定规则：

- `group_name/project_name/instrument_name` 为 NULL，不伪造实验室归属。
- `type_name='辅助工作'`。
- `coefficient` 使用记录快照。
- `workload=quantity*coefficient`。
- `multiplier/unit_price/amount` 为 NULL 或 0，且不参与金额汇总。

### 3.2 三张相关表统一改用事实视图

- Sheet12：只筛选 `source_type='辅助工作'`，按人员、辅助工作名称、系数汇总。
- Sheet6：按人员、来源、类型/工作名称、系数汇总，检测和辅助工作都进入。
- Sheet13：按人员和来源类型汇总，人员总工作量必须等于 Sheet6 同人员工作量之和。

旧 `work_records` 中的“辅助工作”兼容数据保留读取，但要明确标记为 `source_type='检测记录兼容辅助'`，并提供一次性迁移/核对脚本，避免新旧记录重复计算。

### 3.3 导出字段修正

- Sheet6 第一列从“项目”改为“检测人”。
- Sheet12 第一列从“项目”改为“检测人”。
- Sheet12 增加“来源”或在标题说明“公共辅助工作量”，不再显示实验室字段。
- Sheet12、Sheet13 的工作量列全部写 Excel 公式：`数量*系数`。
- 合计列使用 `SUM`，不写死后端计算结果。
- 导出空数据时保留表头和合计行，明确显示“暂无辅助工作记录”。

## 4. 统一导出结构建议

建议保留现有 Sheet 编号以兼容权限和用户习惯，但调整名称和字段契约：

| Sheet | 建议名称 | 定位 |
|---|---|---|
| 1 | 检测明细-实验室项目方法 | 检测记录明细 |
| 2 | 检测明细-仪器日期 | 检测按日、仪器汇总 |
| 3 | 金额汇总-项目 | 项目金额 |
| 4 | 金额汇总-实验室 | 实验室金额 |
| 5 | 检测记录原始明细 | 可追溯原始记录 |
| 6 | 人员工作量明细 | 检测+辅助统一明细 |
| 7 | 金额总表-实验室 | 动态检测类型金额 |
| 8 | 金额总表-项目 | 动态检测类型金额 |
| 9 | 检测量-仪器 | 仪器检测数量 |
| 10 | 检测量-检测类型 | 检测类型数量 |
| 11 | 检测量-事业部 | 事业部数量和金额 |
| 12 | 辅助工作量明细 | 仅公共辅助工作 |
| 13 | 人员工作量汇总 | 人员、来源、类型汇总 |

Sheet 名称可以在界面显示中文业务名称，但后端继续使用 `sheet1` 至 `sheet13`，避免权限、预览和历史模板失效。

## 5. 实施步骤

### 第一阶段：口径和查询修复

1. 增加事实视图/统一查询结构。
2. 将 Sheet12、Sheet6、Sheet13 改为读取统一事实视图。
3. 增加新旧辅助记录去重规则和迁移校验。
4. 修复模板中 Sheet6、Sheet12 的错误列名。

### 第二阶段：写入和样式统一

1. 统一标题行、表头行、冻结窗格、筛选、字体和数字格式。
2. 明细表统一使用公式计算工作量和金额。
3. 按稳定排序输出：人员 → 来源 → 类型/工作 → 方法 → 日期。
4. 合并人员分组单元格，但不合并需要筛选的明细字段。

### 第三阶段：预览和导出一致性

1. 预览接口与 Excel 导出复用同一查询结果结构。
2. 前端显示“检测工作量”“辅助工作量”“总工作量”三个独立指标。
3. 增加逐人员核对：Sheet6 明细合计 = Sheet13 汇总 = 页面统计。
4. 增加辅助工作专用筛选：日期、人员、辅助工作名称。

## 6. 验收条件

- 新增一条辅助工作记录后，Sheet12 能看到该记录。
- 同一记录同时计入 Sheet6 和 Sheet13，且只计一次。
- 辅助工作不出现在实验室、项目、仪器和金额报表中。
- 数量 5、系数 20、倍率 350 时，工作量为 100，金额字段为空或 0；不得出现 35000。
- 检测记录仍按数量×系数计算工作量，金额按数量×单价×倍率计算。
- 所有人员的 Sheet6 工作量合计与 Sheet13 总工作量一致。
- 空数据、跨月日期、同名人员、同名辅助工作均能稳定导出。
- 旧版导出模板、权限键和 Sheet 编号继续可用。

## 7. 网络检索结论

公开网络上没有找到可以直接套用到本项目的中文 LIMS 工作量 Excel 模板；GitHub 公开仓库检索到的项目多为实验室运营分析示例，缺少“检测数量、系数工作量、金额倍率、辅助公共工作量”同时存在的模型。因此不建议引入外部模板作为系统口径。

可参考的公开方法论：

- WHO Laboratory Quality Management System handbook：
  https://www.who.int/publications/i/item/9789241548274
- ISO 15189 医学实验室质量与能力管理框架：
  https://www.iso.org/standard/76677.html
- GitHub 公开仓库检索入口（laboratory workload management）：
  https://api.github.com/search/repositories?q=laboratory+workload+management

这些资料共同强调：统计必须能追溯到原始记录、人员能力/资源维度要独立、汇总口径要固定。结合本项目，最合适的是“统一事实视图 + 四类报表契约”，而不是继续为每张 Sheet 单独维护一套 SQL 和字段规则。

## 8. 版本建议

本方案建议作为 `2.2.17` 的独立迭代，基线为当前 `2.2.16`。不回退 `2.2.16` 的检测类型可见性修复，不恢复已删除的部门角色逻辑；辅助工作只新增统计事实层和导出适配，不改变现有登录、权限、检测录入和金额计算功能。
