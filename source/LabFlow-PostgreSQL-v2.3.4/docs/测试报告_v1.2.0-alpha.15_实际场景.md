## 4. 重点问题

### P1：实验室所属部门在 UI 保存后未持久化

实验室创建页面显示成功，但 `project_groups.division_id` 为空，直接阻断研发送样提交和执行部门快照。建议优先修复所属部门选择控件的值绑定/提交载荷，并增加“保存后刷新仍保持所属部门”的场景回归。

### P1：用户管理新建成功提示与持久化结果不一致

新建 `sender_alpha` 后页面提示成功，但数据库未生成用户。建议检查用户创建事务、角色关联写入和成功提示触发时机，成功提示必须以后端事务提交为准。

### P1：样品信息登记部门下拉无候选项

隔离库中存在启用部门且 `show_in_sample_info=1`，但登记页无法选择部门，导致 alpha.15 的附件补传、退回待修改和状态流转场景无法在 UI 继续验证。建议在前端显示加载失败原因，并核对 `/divisions?portal=sample_info` 的返回处理。

### P1：测试 PostgreSQL 连接耗尽

连续真实页面操作后，端口 `55445` 的测试库达到 `max_connections=20`，出现“连接数过多”；已停止临时服务、重启测试库并恢复原参数。建议检查连接池上限、页面并发请求和连接释放，避免将该现象带入生产部署。

## 5. 结论

alpha.15 的构建、Rust 测试和部分核心真实业务链路通过；但实验室部门持久化、用户创建持久化、样品信息登记组织选择以及测试库连接耗尽均属于阻断性问题。当前不建议将本版本判定为“全部功能通过”或直接作为生产验收通过版本。附件兼容与补传修复本身已有代码测试覆盖，但由于样品登记主流程被阻断，本轮没有完成真实附件上传、删除、旧附件预览和退回待修改闭环。
