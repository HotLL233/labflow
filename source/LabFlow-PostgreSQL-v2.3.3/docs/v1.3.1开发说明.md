# v1.3.1 开发说明

## 范围

本版本在 v1.3.0 人员变动通知独立功能上迭代。原 v1.2.0 源码目录不修改；旧样品信息登记、送样、分析检测、统计、用户和角色流程不改变。

## 数据边界

人员反馈业务明细写入 `personnel-change-data/notices-YYYY-MM.jsonl`，项目及人员基线写入 `项目及人员汇总表.xlsx`，审批通过时先备份再更新汇总表。人员反馈明细不写 PostgreSQL 业务表。通知中心的规则、发送队列和个人收件箱继续使用现有通知基础设施，仅用于发送提醒。

## 权限

- 系统管理员、分析检测组长：查看和导出全部实验室，可审批。
- 系统管理员、研发送样组长：发起通知。
- 研发送样组长：查看和导出用户关联实验室。
- 人员反馈字段配置：系统管理员编辑，系统管理员和分析检测组长查看。

## 业务规则

员工加入默认不勾选项目；员工离职、实验室内调动、跨实验室调动显示已有项目并默认勾选，取消勾选表示取消关联。实验室内调动的候选项目为关联实验室全部项目；跨实验室调动不填写目标实验室和目标项目，项目为空表示取消当前人员全部项目关联。检测方法逐条输入，服务端拒绝分隔符和换行。汇总表页面及 Excel 对检测方法完整换行显示。

## 通知中心

新增 `personnel_change_feedback` 事件和 `personnel_change_feedback` 内容模板，字段候选合并固定字段、人员反馈字段和样品信息登记自定义列。人员反馈通知中明确提示实际人员变动仍需管理员或分析检测组长手动调整。

## 验证与打包

发布前执行 `cargo fmt --check`、`cargo check`、人员变动单元测试、`npm run typecheck`、`npx vite build`、`cargo build --release` 和两个 Inno Setup 脚本。安装包必须包含 release 程序、`backend/static`、PostgreSQL runtime、PDF runtime、VC++ 运行库、配置示例和 v1.3.1 更新说明。
