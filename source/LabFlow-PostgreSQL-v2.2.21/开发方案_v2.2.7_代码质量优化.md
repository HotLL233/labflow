# LabFlow v2.2.7 开发方案 - 代码质量优化

## 版本信息
- **目标版本**: v2.2.7
- **基于版本**: v2.2.6
- **方案类型**: 代码质量优化（不改变功能）
- **方案日期**: 2026-08-27

## 方案概述

基于代码评审反馈，本版本聚焦三个核心改进点：
1. **权限标签语义优化** - 引入分层结构，支持简短和完整两种显示模式
2. **版本号统一管理** - 单一数据源避免手动同步
3. **前端变量命名规范化** - 提升代码可读性和可维护性

**核心原则**: 确保不影响任何现有功能，所有修改向后兼容。

## 优化点一：权限标签语义优化

### 现状问题

当前权限定义（v2.2.6）：
```typescript
{
  key: 'sample:collect',
  label: '分析检测-对研发送样取样',
  group: '门户入口'
}
```

**存在的问题**：
- 标签过长，在权限矩阵界面拥挤
- 不符合自然语言习惯（"对XX取样"）
- 缺少灵活性，无法根据场景选择显示模式

### 优化方案

#### 1. 扩展权限定义结构

**后端** (`src/models/role.rs`):
```rust
#[derive(Debug, Serialize, Clone)]
pub struct PermissionDef {
    pub key: &'static str,
    pub label: &'static str,           // 简短标签（新增）
    pub full_label: &'static str,      // 完整标签（原 label）
    pub group: &'static str,
    pub portal: Option<&'static str>,  // 所属门户（新增）
    pub actor: Option<&'static str>,   // 操作主体（新增）
}
```

**前端** (`frontend/src/constants/permissions.ts`):
```typescript
export interface PermissionDef {
  key: string;
  label: string;           // 简短标签（新增）
  fullLabel: string;       // 完整标签（原 label）
  group: string;
  portal?: string;         // 所属门户（新增）
  actor?: string;          // 操作主体（新增）
}
```

#### 2. 权限标签示例

| 权限 Key | 简短标签 (label) | 完整标签 (fullLabel) | 门户 (portal) | 主体 (actor) |
|---------|-----------------|---------------------|--------------|-------------|
| `entry:sample` | 研发送样门户 | 研发送样门户 | - | 送样人 |
| `sample:collect` | 取样（研发送样） | 分析检测-对研发送样取样 | 分析检测门户 | 检测人员 |
| `sample:complete` | 完成检测（研发送样） | 分析检测-完成研发送样检测 | 分析检测门户 | 检测人员 |
| `sample-info:create` | 创建送样记录 | 样品信息送样-创建送样记录 | 样品信息登记门户 | 送样人 |
| `sample-info:collect` | 取样（样品信息） | 分析检测-对样品信息取样 | 分析检测门户 | 检测人员 |
| `records:rd:edit-subject` | 编辑本人送样 | 研发送样-编辑本人作为送样人的记录 | 研发送样门户 | 送样人 |

#### 3. 前端显示策略

**角色管理页面**（空间宽裕）:
```typescript
// AdminRolesPage.tsx
<FormControlLabel
  control={<Checkbox ... />}
  label={p.label}  // 使用简短标签
/>

// 鼠标悬浮显示完整信息
<Tooltip title={`${p.fullLabel} | 门户：${p.portal || '-'} | 主体：${p.actor || '-'}`}>
  ...
</Tooltip>
```

**权限选择对话框**（需要详细信息）:
```typescript
// 可以通过开关切换显示模式
const [showFullLabel, setShowFullLabel] = useState(false);

<FormControlLabel
  label={showFullLabel ? p.fullLabel : p.label}
/>
```

#### 4. 兼容性处理

**向后兼容**：
- API 返回的权限定义同时包含 `label` 和 `fullLabel`
- 前端组件优先使用 `label`，如不存在则回退到 `fullLabel`
- 数据库中的权限 key 完全不变

**迁移策略**：
```typescript
// 前端兼容代码
function getPermissionLabel(perm: PermissionDef, preferFull = false): string {
  if (preferFull) {
    return perm.fullLabel || perm.label;
  }
  return perm.label || perm.fullLabel;
}
```

## 优化点二：版本号统一管理

### 现状问题

当前需要手动更新 4 个文件：
1. `Cargo.toml` → `version = "2.2.6"`
2. `frontend/package.json` → `"version": "2.2.6"`
3. `build_server_installer.iss` → `#define MyAppVersion "2.2.6"`
4. `build_hot_update_installer.iss` → `#define MyAppVersion "2.2.6"`

**风险**：容易遗漏某个文件，导致版本不一致。

### 优化方案

#### 1. 创建版本号文件

**新增文件**: `VERSION`
```
2.2.7
```

单行纯文本，无其他内容。

#### 2. 创建版本同步脚本

**新增文件**: `scripts/set-version.sh`
```bash
#!/usr/bin/env bash
# 版本号统一更新脚本
# 用法: ./scripts/set-version.sh <version>
# 示例: ./scripts/set-version.sh 2.2.7

set -e

if [ $# -ne 1 ]; then
    echo "用法: $0 <version>"
    echo "示例: $0 2.2.7"
    exit 1
fi

VERSION=$1
VERSION_NUM="${VERSION}.0"

echo "更新版本号到: $VERSION"

# 1. 更新 VERSION 文件
echo "$VERSION" > VERSION

# 2. 更新 Cargo.toml
if [ -f "Cargo.toml" ]; then
    sed -i.bak "s/^version = \".*\"/version = \"$VERSION\"/" Cargo.toml
    rm -f Cargo.toml.bak
    echo "✓ Cargo.toml"
fi

# 3. 更新 frontend/package.json
if [ -f "frontend/package.json" ]; then
    sed -i.bak "s/\"version\": \".*\"/\"version\": \"$VERSION\"/" frontend/package.json
    rm -f frontend/package.json.bak
    echo "✓ frontend/package.json"
fi

# 4. 更新服务器安装包脚本
if [ -f "build_server_installer.iss" ]; then
    sed -i.bak "s/#define MyAppVersion \".*\"/#define MyAppVersion \"$VERSION\"/" build_server_installer.iss
    sed -i.bak "s/#define MyAppNumericVersion \".*\"/#define MyAppNumericVersion \"$VERSION_NUM\"/" build_server_installer.iss
    rm -f build_server_installer.iss.bak
    echo "✓ build_server_installer.iss"
fi

# 5. 更新热更新安装包脚本
if [ -f "build_hot_update_installer.iss" ]; then
    sed -i.bak "s/#define MyAppVersion \".*\"/#define MyAppVersion \"$VERSION\"/" build_hot_update_installer.iss
    sed -i.bak "s/#define MyAppNumericVersion \".*\"/#define MyAppNumericVersion \"$VERSION_NUM\"/" build_hot_update_installer.iss
    rm -f build_hot_update_installer.iss.bak
    echo "✓ build_hot_update_installer.iss"
fi

echo ""
echo "版本号已更新为: $VERSION"
echo "请检查 git diff 确认修改正确，然后提交。"
```

#### 3. Windows 批处理版本

**新增文件**: `scripts/set-version.bat`
```batch
@echo off
setlocal enabledelayedexpansion

if "%~1"=="" (
    echo 用法: %~nx0 ^<version^>
    echo 示例: %~nx0 2.2.7
    exit /b 1
)

set VERSION=%~1
set VERSION_NUM=%VERSION%.0

echo 更新版本号到: %VERSION%

REM 1. 更新 VERSION 文件
echo %VERSION%> VERSION
echo ✓ VERSION

REM 2. 更新 Cargo.toml
powershell -Command "(Get-Content Cargo.toml) -replace 'version = \"[^\"]*\"', 'version = \"%VERSION%\"' | Set-Content Cargo.toml"
echo ✓ Cargo.toml

REM 3. 更新 frontend/package.json
powershell -Command "(Get-Content frontend/package.json) -replace '\"version\": \"[^\"]*\"', '\"version\": \"%VERSION%\"' | Set-Content frontend/package.json"
echo ✓ frontend/package.json

REM 4. 更新服务器安装包脚本
powershell -Command "(Get-Content build_server_installer.iss) -replace '#define MyAppVersion \"[^\"]*\"', '#define MyAppVersion \"%VERSION%\"' | Set-Content build_server_installer.iss"
powershell -Command "(Get-Content build_server_installer.iss) -replace '#define MyAppNumericVersion \"[^\"]*\"', '#define MyAppNumericVersion \"%VERSION_NUM%\"' | Set-Content build_server_installer.iss"
echo ✓ build_server_installer.iss

REM 5. 更新热更新安装包脚本
powershell -Command "(Get-Content build_hot_update_installer.iss) -replace '#define MyAppVersion \"[^\"]*\"', '#define MyAppVersion \"%VERSION%\"' | Set-Content build_hot_update_installer.iss"
powershell -Command "(Get-Content build_hot_update_installer.iss) -replace '#define MyAppNumericVersion \"[^\"]*\"', '#define MyAppNumericVersion \"%VERSION_NUM%\"' | Set-Content build_hot_update_installer.iss"
echo ✓ build_hot_update_installer.iss

echo.
echo 版本号已更新为: %VERSION%
echo 请检查文件变更确认修改正确，然后提交。
```

#### 4. 使用方式

```bash
# Linux / macOS / Git Bash
./scripts/set-version.sh 2.2.7

# Windows CMD
scripts\set-version.bat 2.2.7

# PowerShell
.\scripts\set-version.bat 2.2.7
```

#### 5. 版本验证脚本

**新增文件**: `scripts/check-version.sh`
```bash
#!/usr/bin/env bash
# 检查版本号是否一致

VERSION_FILE=$(cat VERSION 2>/dev/null || echo "未找到VERSION文件")
CARGO=$(grep '^version = ' Cargo.toml | head -1 | sed 's/version = "\(.*\)"/\1/')
PACKAGE=$(grep '"version":' frontend/package.json | head -1 | sed 's/.*"version": "\(.*\)".*/\1/')
SERVER_ISS=$(grep '#define MyAppVersion' build_server_installer.iss | sed 's/#define MyAppVersion "\(.*\)"/\1/')
HOTFIX_ISS=$(grep '#define MyAppVersion' build_hot_update_installer.iss | sed 's/#define MyAppVersion "\(.*\)"/\1/')

echo "版本号检查:"
echo "  VERSION 文件:              $VERSION_FILE"
echo "  Cargo.toml:                $CARGO"
echo "  frontend/package.json:     $PACKAGE"
echo "  build_server_installer:    $SERVER_ISS"
echo "  build_hot_update_installer: $HOTFIX_ISS"

if [ "$VERSION_FILE" = "$CARGO" ] && [ "$CARGO" = "$PACKAGE" ] && [ "$PACKAGE" = "$SERVER_ISS" ] && [ "$SERVER_ISS" = "$HOTFIX_ISS" ]; then
    echo ""
    echo "✓ 版本号一致: $VERSION_FILE"
    exit 0
else
    echo ""
    echo "✗ 版本号不一致，请运行 ./scripts/set-version.sh 更新"
    exit 1
fi
```

## 优化点三：前端变量命名规范化

### 现状问题

当前代码中大量使用过度简化的变量名：
```typescript
const n = useNavigate();           // navigate
const [gs, setGs] = useState();    // groups
const [ld, setLd] = useState();    // loading
const [er, setEr] = useState();    // error
const [sq, setSq] = useState();    // searchQuery
const [divs, setDivs] = useState(); // divisions
const [selDiv, setSelDiv] = useState(); // selectedDivision
const lg = async () => {};         // loadGroups
const ld2 = async () => {};        // loadDivisions
const fg = useMemo(() => {});      // filteredGroups
```

**问题**：
- 新人难以理解代码
- 容易拼错导致bug（`ld` vs `ld2`）
- IDE 自动补全不友好
- 代码审查困难

### 优化方案

#### 1. 命名规范

**变量命名原则**：
- Hook 类：使用完整单词（`useNavigate` → `navigate`）
- 状态变量：使用完整描述（`groups`, `loading`, `error`）
- 函数：动词开头，描述行为（`loadGroups`, `loadDivisions`, `filterGroups`）
- 计算值：使用完整描述（`filteredGroups`, `displayGroups`）

**命名对照表**：

| 旧名称 | 新名称 | 含义 |
|-------|-------|------|
| `n` | `navigate` | React Router 导航函数 |
| `gs` | `groups` | 实验室分组列表 |
| `ld` | `loading` | 加载中状态 |
| `er` | `error` | 错误信息 |
| `sq` | `searchQuery` | 搜索关键词 |
| `divs` | `divisions` | 部门列表 |
| `selDiv` | `selectedDivisionId` | 选中的部门ID |
| `lg` | `loadGroups` | 加载分组函数 |
| `ld2` | `loadDivisions` | 加载部门函数 |
| `fg` | `filteredGroups` | 过滤后的分组 |
| `ps` | `portalStyles` | 门户样式配置 |
| `r` | `response` | API响应 |
| `d` | `data` | 响应数据 |
| `q` | `query` | 查询字符串 |
| `m` | `countMap` | 计数映射 |

#### 2. 重构目标文件清单

**高优先级**（用户直接交互页面）：
1. `frontend/src/pages/WorkloadPortal.tsx` - 分析检测门户
2. `frontend/src/pages/SamplePortal.tsx` - 研发送样门户
3. `frontend/src/pages/SampleInfoPortal.tsx` - 样品信息登记门户
4. `frontend/src/pages/AdminRolesPage.tsx` - 角色管理页面

**中优先级**（管理页面）：
5. `frontend/src/pages/HomePage.tsx` - 首页
6. `frontend/src/pages/ManagePage.tsx` - 管理工作区

#### 3. 重构策略

**保守重构**：
- 一次重构一个文件
- 重构后立即编译测试
- 不改变任何逻辑和功能
- 保留原有注释

**重构步骤**：
1. 全局替换变量声明
2. 更新所有使用处
3. TypeScript 类型检查
4. 编译验证
5. 功能自测

#### 4. 示例重构对比

**重构前** (`WorkloadPortal.tsx`):
```typescript
const StandardWorkloadPortal: React.FC = () => {
  const n = useNavigate();
  const [gs, setGs] = useState<ProjectGroup[]>([]);
  const [ld, setLd] = useState(true);
  const [er, setEr] = useState('');
  const [sq, setSq] = useState('');
  
  const lg = async () => {
    setLd(true);
    setEr('');

      const r = await getGroups({ portal: 'work' });
      if (r.code === 0) setGs(r.data as ProjectGroup[]);

      setLd(false);

  if (ld) return <CircularProgress />;
```

**重构后**:
```typescript
const StandardWorkloadPortal: React.FC = () => {
  const navigate = useNavigate();
  const [groups, setGroups] = useState<ProjectGroup[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState('');
  const [searchQuery, setSearchQuery] = useState('');
  
  const loadGroups = async () => {
    setLoading(true);
    setError('');

      const response = await getGroups({ portal: 'work' });
      if (response.code === 0) {
        setGroups(response.data as ProjectGroup[]);

      setError('加载失败');

      setLoading(false);

  const filteredGroups = useMemo(() => {

        group.name.toLowerCase().includes(query)

```

**改进点**：
- 变量名自解释，无需注释
- IDE 自动补全更友好
- 代码审查更容易
- 新人上手更快

#### 5. 不重构的例外

**保留简短命名的场景**：
1. **循环索引**: `i`, `j`, `k` - 约定俗成
2. **临时变量**: `map` 函数中的 `item => item.id`
3. **坐标/数学**: `x`, `y`, `w`, `h` - 领域约定
4. **React 事件**: `e` 或 `event` 均可
5. **常量**: `R = '2px'` - 全局样式常量（但建议改为 `BORDER_RADIUS`）
