# v2.2.21 公告与在线更新实施方案

## 公告多位置

系统公告独立于人员变动通知，管理员使用现有 `manage:notifications` 权限维护。每条公告可多选显示位置：`home`、`sample_submission`、`analysis`、`sample_registration`、`notification_center`。首页使用弹窗，业务入口使用顶部公告条；用户确认状态按公告和用户保存，点击遮罩仅关闭本次展示。

后端新增 `system_announcements` 与 `system_announcement_reads`，公告只在已发布且处于开始/结束时间范围时返回。正文按纯文本渲染，第一版不引入富文本依赖；接口按 `position` 查询，前端统一使用 `AnnouncementSlot` 组件，避免各页面复制已读逻辑。

## 在线更新

在线更新只允许管理员触发。服务端读取 GitHub Release 的版本清单，比较当前 `CARGO_PKG_VERSION`，下载带 SHA-256 校验的升级包到临时目录，校验通过后执行现有热更新脚本；失败时保留当前版本并删除临时文件。Docker 版继续使用 `scripts/update-labflow.ps1` 的备份、拉取、健康检查和失败回滚流程。

更新接口返回 `current_version`、`latest_version`、`download_url`、`sha256` 和 `state`，不在应用进程内覆盖自身文件。版本目录、数据库迁移和安装包均使用 `2.2.21`，发布时同时生成 Windows 安装包、热更新包和 GHCR Docker 镜像。

## 验收

1. 管理员可创建、编辑、发布、撤回公告，并多选显示位置。
2. 首页弹窗和三个业务入口公告条按位置显示，确认后不重复出现。
3. 未登录用户不请求用户公告；无权限用户不能访问管理接口。
4. 在线更新校验版本与 SHA-256，升级失败可恢复，Docker 更新后健康检查通过。
