# 角色与权限用途说明（v2.2.18）

> 适用版本：LabFlow PostgreSQL v2.2.18  
> 更新日期：2026-09-12  
> 依据：`frontend/src/constants/permissions.ts`、后端权限校验和“管理 > 角色与权限”页面。

## 1. 先理解三层控制

系统权限不是“勾上就能看全部数据”。一个角色的最终能力由三部分共同决定：

1. **功能权限**：能否进入页面、执行创建/编辑/取样/导出等动作。
2. **业务数据范围**：这个角色能看到哪些部门、实验室、人员或记录。
3. **样品信息类型范围**：样品信息登记角色能看到哪些检测类型；没有勾选时不会自动获得跨类型权限。

管理员账号本身视为拥有 `*`（全部权限），不受单项勾选限制。普通角色必须同时满足功能权限和数据范围；只配置入口权限而没有相应范围，可能只能打开页面，不能看到业务数据。

## 2. “全部权限（* 通配）”

| 权限标识 | 用途 | 注意事项 |
|---|---|---|
| `*` | 授予当前及以后新增的全部权限，包括管理、业务、统计、导入导出和数据清理权限。 | 仅建议给核心系统管理员。它会绕过单项权限勾选，且未来新增权限也会自动获得。 |

## 3. 门户入口与业务操作

### 3.1 入口权限

| 权限标识 | 界面名称 | 具体用途 |
|---|---|---|
| `entry:sample` | 研发送样门户 | 显示并进入研发送样门户。通常给研发送样员、研发送样组长。 |
| `entry:workload` | 分析检测门户 | 显示并进入分析检测门户。通常给分析检测员、分析检测组长。 |
| `entry:sample-info` | 样品信息登记门户 | 显示并进入样品信息登记门户。是否能创建、编辑、处理，还要看下面的细分权限。 |
| `sample-info:create` | 创建送样记录 | 在样品信息登记门户新建一条样品信息登记记录。界面旧文案可能显示为“创建送样记录”，实际作用以权限标识为准。 |
| `records:work:portal-scoped` | 分析检测公共账号人员选择门户 | 公共分析检测账号登录后进入“选择实际检测人/人员范围”页面。该项属于内部兼容权限，角色编辑页不单独展示，但旧角色中可能仍保留。 |

### 3.2 分析检测对研发送样记录的操作

| 权限标识 | 界面名称 | 具体用途 |
|---|---|---|
| `sample:collect` | 取样（研发送样） | 对研发送样记录执行取样，将记录推进到检测流程。 |
| `sample:withdraw` | 撤回取样（研发送样） | 撤销已经执行的研发送样取样，通常用于误取样或需要退回处理的情况。 |
| `sample:return` | 退回（研发送样） | 将研发送样记录退回送样人，要求填写退回原因。 |
| `sample:complete` | 完成检测（研发送样） | 将研发送样记录标记为检测完成。 |

| 权限标识 | 界面名称 | 具体用途 |
|---|---|---|
| `sample-info:collect` | 取样（样品信息） | 对样品信息登记记录执行取样。 |
| `sample-info:complete` | 完成检测（样品信息） | 将样品信息登记记录标记为检测完成。 |

| `sample-info:edit-own` | 编辑本人记录 | 样品尚未取样或处于退回待修改状态时，编辑本人提交或本人作为业务送样人的记录。 |
| `sample-info:return-confirm` | 确认并处理退回 | 送样人确认退回，并进入处理/修改退回记录流程。 |

## 4. 数据范围权限

### 4.1 研发送样数据范围

| 权限标识 | 具体用途 | 与其他权限的关系 |
|---|---|---|
| `records:rd:view-all` | 查看全部实验室的研发送样记录。 | 跨实验室查看；不等于可以编辑或处理全部记录。 |
| `records:rd:view-lab` | 查看本人所属实验室的研发送样记录。 | 适合普通送样员；不授予跨实验室查看。 |
| `records:rd:portal-all-labs` | 在研发送样门户中选择并进入全部实验室。 | 主要给组长或跨实验室代提交人员；通常与 `records:rd:view-all` 配合。 |
| `records:rd:select-sender` | 创建/代提交研发送样时选择实际送样人。 | 账号操作者和实际送样人可以不同，常给研发送样组长。 |
| `records:rd:edit-created` | 编辑本人账号提交的研发送样记录。 | 按“提交账号”判断，不是按实际送样人判断。 |
| `records:rd:edit-subject` | 编辑本人作为实际送样人的研发送样记录。 | 按“实际送样人”判断；与上一项不同。 |
| `records:rd:return-confirm` | 确认并处理退回的研发送样记录。 | 送样人处理被检测人员退回的记录。 |
| `records:rd:return-delegate` | 代其他送样人确认并修改已退回记录。 | 适合组长代办；权限范围仍受角色数据范围限制。 |

### 4.2 分析检测数据范围

| 权限标识 | 具体用途 | 与部门范围的关系 |
|---|---|---|
| `records:work:portal-all-labs` | 分析检测门户允许选择全部实验室。 | 仅控制入口选择范围；实际业务数据仍受分析检测来源部门范围和其他权限控制。 |
| `records:work:select-detector` | 录入或提交分析检测工作量时选择实际检测人。 | 公共账号、组长代录入时通常必须配置。 |
| `records:work:view-scope` | 查看角色所配置范围内人员的分析检测工作量。 | 只看角色的分析检测来源部门范围，不自动扩大到全公司。 |
| `records:work:view-all` | 查看全公司的分析检测工作量。 | 高于“本范围”；仍建议只给分析检测组长或统计管理人员。 |

**分析检测来源部门范围**在角色权限弹窗底部单独勾选。它决定该角色可以进入哪些部门的分析检测业务，以及查看、录入、统计和导出哪些送样来源数据。分析检测用户的“主归属部门”只是组织归属，不代替这个角色范围。

当前 v2.2.18 没有单独的 `records:work:create`、`records:work:edit`、`records:work:delete` 权限。分析检测工作量记录的录入和修改由分析检测门户入口、实际检测人选择权限、状态流转权限及角色数据范围共同控制；旧版说明中的这三个键不应再创建或配置。

### 4.3 样品信息登记权限范围

角色编辑页中的“样品信息登记数据范围”按检测类型勾选。它控制该角色可以看到的样品信息登记类型、记录、详情、附件、统计和导出数据；与研发送样部门范围同时配置时按实际业务规则取交集。没有类型范围时，不应把空列表理解为“全部类型”。

## 9. 常用角色配置建议

### 研发送样员

建议：`entry:sample`、本人记录的查看/编辑权限、`records:rd:return-confirm`。数据范围选择本人实验室或业务要求的部门范围。

### 研发送样组长

在研发送样员基础上增加：`records:rd:select-sender`、`records:rd:return-delegate`，必要时增加 `records:rd:portal-all-labs`、`records:rd:view-all` 和 `feedback:personnel:edit`。

### 分析检测员

建议：`entry:workload`、需要的取样/完成/撤回/退回权限，并配置分析检测来源部门范围。普通人员不要授予 `records:work:view-all`。

### 分析检测组长或公共账号

公共账号通常需要 `entry:workload`、内部人员选择权限 `records:work:portal-scoped`、`records:work:select-detector`，再按实际工作流程增加取样、完成和查看范围权限。组长可根据管理范围增加 `records:work:view-scope` 或 `records:work:view-all`。

### 统计员

按门户分别配置 `stats:portal:*`、对应查看范围和需要的卡片/工作表权限；不需要导出的账号不要配置 `stats:workload:export`。

### 系统管理员

优先使用 `*` 的核心管理员数量应尽量少。分工管理员使用 `manage:*` 和对应统计/数据治理权限，避免把永久清理、备份恢复和全部数据查看同时授予普通管理人员。

## 10. 配置时最容易出现的误区

1. **只有入口，没有数据范围**：能打开页面，但列表为空或无法查询。
2. **把“查看全部”当成“可以编辑全部”**：查看权限不自动授予创建、修改、取样、退回或删除。
3. **把账号主归属部门当成分析检测数据范围**：分析检测范围由角色中的“分析检测数据来源部门”决定。
4. **把工作量系数和金额倍率混用**：工作量是数量 × 系数；金额才使用金额相关倍率/单价口径。
5. **只配置 `stats:workload:access`**：当前实际分析检测统计入口以 `stats:portal:workload` 为准。
6. **误把空的样品信息类型范围当成全部类型**：应按角色实际勾选检测类型。
7. **给普通用户数据治理永久清理权限**：该权限不可通过普通回收站流程恢复，必须严格限制。

## 11. 权限判断原则

- 前端勾选只负责配置体验；后端接口会再次校验权限。
- `*` 等于通配全部权限。
- 角色权限与数据范围分开保存，不能把部门/实验室 ID 拼进权限字符串。
- 用户拥有多个角色时，权限按合并后的有效权限判断；数据范围按系统对应业务规则计算。
- 2.2.18 已删除公共辅助工作录入入口；本文不包含该已删除功能的活动权限。历史兼容代码或旧数据不代表当前可用入口。
