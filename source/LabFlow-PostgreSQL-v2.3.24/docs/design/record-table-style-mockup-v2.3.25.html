①作用范围是本次设计的核心：先选对象，再改样式，避免"改了不知道改到哪"。
②冻结列：序号 + 送样编号固定，横向滚动时始终可见。
③列头灰底表示该列被选中，工具栏与面板同时指向"数量"列。
④橙字加粗来自条件格式"数量 ≥ 30"，不是手工上色。
⑤浅红整行来自条件格式"状态 = 待取样"，左侧色条用于超期提示。
⑥所有样式一处配置，界面与 Excel 导出同时生效。
样式来源优先级：个人视图覆盖 → 分组/角色模板 → 全局样式 → 系统默认 全局样式变更写入审计日志（含变更前后差异） 超过 200 行自动启用虚拟滚动，样式解析结果做缓存
屏 2｜条件格式规则编辑器推荐用规则替代"逐行手工上色"，既满足视觉需求，又不会随数据更新失效

设计要点：界面上"看起来像 Excel"，不等于"行为上完全等于 Excel"。本方案刻意不开放自由插入行列、自由公式与无限制逐格上色，因为这三项会直接破坏数据校验、统计口径与审计可追溯性。
性能边界：样式解析必须按「表 → 列 → 行 → 单元格」四层缓存。建议单页 ≤ 200 行直接渲染，超过后启用虚拟滚动；条件格式规则上限 20 条；禁止在单元格 render 内遍历规则数组。
