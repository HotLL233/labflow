# LabFlow v2.3.55 开发版本

当前开发版本为 `v2.3.55`，隔离自正式v2.3.54；当前正式版本仍为 `v2.3.54`，待本版发布及产物核验完成后更新。

样品信息取样工作量弹窗改为选择数据库全部有效标准方法，不再以当前计量项目的方法关联或样品入口的通用方法部门范围缩小方法库。未删除、启用且绑定仪器有效的方法可选，无绑定仪器的方法同样合法；停用或已删除的方法、失效绑定仪器不进入候选。类型和字段映射仍只影响推荐排序，最终选择真实标准方法ID后提交，不自动创建主数据、项目方法关联或数据库迁移。主流分析录入和研发送样的方法权限及项目关联规则保持。

方法和仪器的候选与已选项只显示真实名称，不拼接方法代码或仪器编号；编号等已有元数据仍可参与隐藏关键词搜索，不改库中名称或编码。标准部门、实验室、项目、仪器和方法选择及关键词搜索保留，仪器继续筛选方法且每个方法使用自身真实绑定仪器，不允许任意拼接方法与仪器。

研发送样和样品信息登记共用的工作量弹窗将来源信息直接以紧凑、对齐的字段区完整展示，不再默认折叠或重复显示摘要；长文字在字段内及手机窄屏换行。方法、仪器、数量、金额倍率、工作量日期时间、备注与当前实际录入账号保留，来源原文只读，展示调整不修改原登记内容或工作量快照。

已录入的样品工作量记录，即使方法未关联所选计量项目，也可在既有工作量编辑权限和数据范围内修改数量、工作量日期时间、金额倍率等原本支持的字段，前提是方法、项目、实验室等计量绑定未改变。涉及计量绑定变更仍使用原有主流校验，不将普通字段编辑放宽为跨范围或非法绑定编辑。

本版隔离自正式v2.3.54。样品入口方法选择范围按本次要求调整，其标准计量目标、来源准入、角色与数据范围、状态及来源累计数量仍在提交时校验；工作量与金额口径、真实操作账号归属、分类快照、统计导出和历史数据不重算。保留映射推荐、明确自定义、待关联草稿、源行锁内复核、近30天默认加载、按需历史、筛选分页、桌面一页全列、手机记录页及各项现有自定义配置；本轮不新增迁移或主数据关联。

验证：本版独立PostgreSQL后端全库206项通过、0失败，3项需专用备份环境的测试按原设置跳过；兼容层10项、前端69项通过。回归覆盖全库未关联方法预览与实际确认、真实名称和隐藏编号搜索、标准计量权限与源数量保护，以及绑定未变的样品工作量元数据编辑；主流录入与研发送样保留原方法关联及权限校验。Rust fmt/check、默认非console Release、前端类型检查/生产构建、gzip逐字节及九处版本核验通过。仅记录本版实际结果，不计入旧版本测试，不代替真实浏览器/手机及现场安装验收。

交付待完成：本地完整安装包与热更新包、GitHub源码和Release、GHCR 2.3.55/latest尚待构建、发布及资产核验；正式版本暂为v2.3.54。仅推GitHub，Gitee继续暂停。

## 开发续接与记忆惯例

- 开始开发或更换设备后，必须先阅读仓库根目录的 `PROJECT_MEMORY.md`。
- `PROJECT_MEMORY.md` 是项目唯一、跨版本、跨设备的长期记忆与开发惯例来源；后续确认的业务规则、技术决策、问题根因、环境约定和发布经验只更新该文件，并随 Git 提交。
- 不再新增或维护按日期记忆、`历史记忆_*.md`、`开发交接_*.md`、`续接提示词_*.md` 或 `HANDOFF.md`；旧版本目录中的同类文件只作历史归档，不得作为当前规则来源或复制到新版本。
- 版本 `更新说明.md` 和专项文档仍按用途维护，但不得复制一套长期记忆。规则冲突时以当前用户要求、当前源码与工作流、`PROJECT_MEMORY.md` 的顺序为准。

1. 当前开发源码目录：`source/LabFlow-PostgreSQL-v2.3.55/`，隔离基线及当前正式版本为 `v2.3.54`；本版开发、验证与交付状态见本版 `更新说明.md` 和根 `PROJECT_MEMORY.md`。
2. Gitee 源码仓库：`https://gitee.com/HotLL233/labflow`（自 v2.3.18 起暂停向 Gitee 推送，仅保留历史仓库）。
3. Docker 部署使用 `docker-compose.deploy.yml`，推荐执行 `scripts/pull-labflow-image.ps1`（Windows）或 `scripts/pull-labflow-image.sh`（Ubuntu）。
4. 脚本按 `LABFLOW_IMAGE_PRIORITY` 依次尝试已配置的镜像地址，成功后再启动 Compose；Gitee 镜像地址未配置时跳过，目前发布仅使用 GHCR。
5. v2.3.19 起 JWT 签名密钥由部署自动生成并保存在数据目录 `jwt_secret`；如需集中管理，可用环境变量 `JWT_SECRET` 覆盖（长度需 ≥16 位）。数据库会话时区跟随程序所在机器，容器部署默认 `TZ=Asia/Shanghai`。
6. 从 v2.3.18 升级到 v2.3.19 后所有已登录会话会失效一次，用户需重新登录，之后重启与升级不再失效。

本包不含任何生产数据库、附件、备份、实际服务器配置、登录凭据或用户本机数据。

打包口径（v2.3.13 起固化为发布规范）：

- 安装包文件名沿用 `LabFlow-v<版本>.exe`（完整服务器版）与 `LabFlow-v<版本>-HotUpdate.exe`（热更新升级包）。
- 发布流程根据 tag `v<版本>` 自动构建，并**自动提交到仓库根 `installers/` 目录**，同时上传 GitHub Release。
- 本地留档副本放在对应版本目录的 `installer/` 中；该目录被 `.gitignore` 忽略，不进入版本库。
- Docker 镜像由发布工作流推送到 GHCR（`ghcr.io/hotll233/labflow:<版本>` 与 `latest`）；向 Gitee registry 的同步自 v2.3.18 起暂停。
