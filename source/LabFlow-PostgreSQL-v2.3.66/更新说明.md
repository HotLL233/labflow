# LabFlow v2.3.66：修复检测类型卡片配色不生效

v2.3.65 恢复了管理后台「样品信息类型 → 颜色色值」的输入框，但**只恢复了入口、没接上渲染**：样品信息登记首页的检测类型卡片仍写死「样品信息登记」业务绿，读的是 `BUSINESS_COLORS.info` 而不是类型自身的 `color` 字段。结果就是后台改了色、保存成功、列表色块也变了，前台卡片颜色始终不变。本版补齐渲染，前端一处文件改动，Rust 后端零改动。

一、故障定位

- 写链路完好：`ManagePage.tsx` 的 `siTypeForm.color` → `createSampleInfoType / updateSampleInfoType` → 后端 `sample_info_type_repo.rs` 的 INSERT / UPDATE 都带 `color`；列表接口 `SELECT` 也返回 `color`，管理页表格的色块 `bgcolor: t.color` 正常显示新色。
- 读链路断裂：`SampleInfoHome.tsx` 的类型卡片在 v2.3.64 统一业务色时，把 `cat.color` 换成了 `BUSINESS_COLORS.info.main`，v2.3.65 恢复配置层时遗漏了这个消费点。全仓库检索确认，`sample_info_types.color` 在 v2.3.63 只有这一处消费，所以只影响首页类型卡片。

二、修复内容（`frontend/src/pages/SampleInfoHome.tsx`）

- 新增 `typeColor(cat)`：取 `cat.color`，经 `/^#[0-9a-fA-F]{6}$/` 校验为合法 6 位十六进制才使用，否则回落 `BUSINESS_COLORS.info.main`。卡片底色用 `${accent}1a` 拼透明度后缀，只有 6 位 hex 才拼得出合法值——校验的作用是避免后台填了 3 位缩写或色名时拼出非法 CSS、底色变透明，看起来仍像「不生效」。
- 卡片渲染改为使用 `accent`：底色渐变 `#ffffff → ${accent}1a`、边框 `2px solid ${accent}`、阴影 `0 8px 32px ${accent}1a`、悬停阴影 `${accent}33`、图标与标题色均取 `accent`。
- 页面标题「样品信息登记」与「查看统计」按钮仍用业务绿 `BUSINESS_COLORS.info.main`，属页面级导航色，不随单个检测类型变化。
- 卡片结构、间距、栅格、圆角、字号与 v2.3.65 完全一致，只替换颜色取值来源，未动排版。

三、渲染优先级（延续 v2.3.65 口径）

- 检测类型卡片：`sample_info_types.color`（合法 hex）优先，缺省或非法回落「样品信息登记」业务绿。
- 首页入口卡、统计卡：维持 v2.3.65 的自由色值 > 业务预设 > 内置兜底，本版未改。
- 业务预设色仍由 `constants/designTokens.ts` 的 `BUSINESS_COLORS` 唯一给出，没有新增第二套色源。

四、未改动项（隔离声明）

- 记录表排版、移动端结构、导航结构未动；`recordTableStyle.ts`、`recordTableLayout.ts`、`mobileCardStyles.ts`、`TableStyleBar.tsx`、`useRecordTableStyle.ts`、`Layout.tsx` 与 v2.3.65 逐字节一致。
- 检测类型颜色的对比度不做自动修正：后台填什么色就渲染什么色（与 v2.3.63 行为一致）。若填了极浅色（如 `#FFEB3B`），白底上的标题文字会偏淡，属使用者自行选择的配色结果，系统不静默改色。
- 版本隔离：从 v2.3.65 复制新建本目录，排除 `target`、`frontend/node_modules`、`installer`、旧 `backend/static`；junction 按既有方式手工建立（依赖池沿用 `65c5464…`，package-lock 未变故哈希一致、无需重装依赖）。

五、版本号同步（9 处 + 文档）
