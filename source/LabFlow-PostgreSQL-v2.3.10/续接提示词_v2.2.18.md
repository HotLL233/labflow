将以下内容作为新 Codex 会话的首条请求，并附上本交付包：

```text
请接手 LabFlow PostgreSQL 项目。工作目录是本交付包内的 source\LabFlow-PostgreSQL-v2.2.18。

先完整阅读：
1. 开发交接_v2.2.18.md
2. 历史记忆_v2.2.18.md
3. HANDOFF.md
4. 更新说明_v2.2.18.md

当前正式基线是 2.2.18，2.2.17 仅作历史对照，禁止直接修改历史版本。每次迭代必须新建以版本号命名的纯源码目录，只复制源码，不复制 target、node_modules、backend/static、安装包或业务数据。

已完成的功能是统一的 Excel 式导出模板编辑器，涉及分析检测、研发送样和样品信息登记三类导出。模板配置必须真实影响 Excel 导出；不要只修改前端。工作量只能按数量 x 系数，金额只能按数量 x 单价 x 单价倍率。

继续工作前先检查当前版本、交接文档、实际调用链和已有测试。修改后至少执行 cargo fmt、cargo check、相关 cargo test 与前端 typecheck。完成可测试功能后主动构建完整服务器安装包，并按交接文档校验版本和 SHA-256。

使用 ponytail 原则：优先复用现有代码和标准能力，不添加无关抽象、依赖或功能。除非需求明确，不修改本次方案以外的模块。
```

## Codex 工具与环境

- 推荐 Windows PowerShell 7。
- Rust 使用稳定版 MSVC 工具链，构建工具为 `cargo`。
- 前端使用 Node.js、npm、Vite 和 TypeScript；依赖以 `frontend/package-lock.json` 为准。
- 安装包使用 Inno Setup 6，默认位置：`C:\Program Files (x86)\Inno Setup 6\ISCC.exe`。
- 本交付包提供 `build-resources`，用于离线重建完整安装包所需的 PostgreSQL、PDF 预览和中文安装器语言资源。
- 需要互联网时可在 `frontend` 执行 `npm ci`；不应将生成的 `node_modules` 提交或复制入纯源码版本目录。

## 交付包目录

- `source`：干净的 2.2.18 源码和本交接文件。
- `installers`：已经验证版本的完整服务器安装包。
- `build-resources`：重建完整安装包所需运行时资源。
- `skills`：本次开发遵循的 `ponytail` 技能说明。
- `checksums`：安装包 SHA-256 校验文件。
