# LabFlow v2.3.75 更新说明

## 辅助事项稳定 ID 与独立工作量

- 辅助事项增加程序自动生成的只读“事项ID”（A-编号），现有事项包括软删除事项一次性回填。修改名称、区域、分类、系数、启停或备注时保留同一身份；删除、恢复和 Excel 回导不更换 ID。
- 辅助工作不分配到实验室、项目或仪器，不参与金额计算。事项选择不再依赖实验室；新录入和主动更换事项均不保存实验室归属，旧客户端附带实验室字段也不能改变此规则。
- 辅助工作仍按数量×保存的事项系数计入人员总工作量。金额与实验室汇总继续排除新、旧辅助来源；旧人员原始记录导出中的辅助行不再展示实验室、项目和送样部门分配。
- 人员沿用统一账号、实际工作人员主归属部门、普通账号本人及授权代录规则。权限仍按人员和部门校验，移除实验室选择不扩大记录阅读、编辑或统计权限。
- 历史记录的人员、部门、区域、分类和系数快照不重算；原实验室兼容字段保留，修改历史数量、日期或备注不回填当前配置，也不合并同名遗留事项。

## 主数据模板与导入导出

- “辅助工作”表移除“范围”和“所属实验室”，保留事项名称、系数、辅助分类、启用、排序、备注、区域名称、序号，末列增加只读“事项ID”。独立“辅助区域”表和每事项系数、自定义显示配置继续保留。
- 回导优先按事项 ID 定位，允许同一事项改名或修改配置；新建留空自动生成 ID，未知或重复 ID 阻止导入。旧模板无 ID 继续兼容名称识别，旧范围列仅用于定位遗留身份，无法唯一识别时提示使用新导出文件，不猜测或合并。
- 默认“更新/新增”保留未列数据及关联；“跳过已有”不修改既有系数；完整覆盖仍需核对删除数。缺少辅助表保留配置，存在的空辅助工作表在覆盖模式软删除事项，空辅助区域表停用区域，保留历史引用与快照。
- 下载模板文件名使用当前版本；修正字段字典的单检测类型及通用方法关联说明，方法系数、倍率、金额拒绝非有限数值。
- 本版承接 v2.3.71 独立辅助区域、v2.3.72 统一人员归属及 v2.3.73 稳定事项 ID，隔离自 v2.3.73，不修改旧版源码；不新增依赖。

新增 v2.3.73 事项 ID 数据库迁移。升级前备份数据库、附件和配置；回退旧程序必须恢复升级前数据库。验证和实际交付结果见本版《安装包说明.md》与根 PROJECT_MEMORY.md，未执行的项目不得记为通过。

## 干净环境交付修复

- 修正旧前端锁文件把 pify 2.3.0 错写成不存在的 2.3.1 的三处 npm 元数据，pnpm 锁文件同步；保留官方 2.3.0 原有完整性摘要，不增加或升级依赖。已安装的本机实际依赖就是 2.3.0，干净环境恢复相同依赖。
- 共享版本校验测试的 CRLF 夹具改为归一化换行，防止 Windows 检出后的 CRLF 被重复转换成 CRCRLF；应用版本解析和业务逻辑不放宽。
- v2.3.73 已推送的源码与标签保持不变；其应用本地回归及出包通过，首次远端 CI 暴露上述交付环境问题。本版完成修复后重新验证并正式发布。

## 完整检出环境的自动化兼容

- v2.3.74 已推送标签保持不变，Windows CI 暴露共享发布测试对 workflow 文件 CRLF 行尾的第二处错误假设。修正断言接受正常 CRLF，应用解析与版本约束保持严格；本轮在完整 LF 及 CRLF 工具副本执行全套回归后重新交付。
- Docker CI 进一步定位旧锁文件将 binary-extensions 2.3.0 写成不存在的 2.3.1；本机全局 npm 缓存曾掩盖错误。按官方原有完整性摘要恢复 2.3.0，npm/pnpm 锁同步，并核对所有依赖的官方元数据及使用全新 npm 缓存冷安装，保留原依赖内容。
- 全量核对同时修正 json5 与 picomatch 锁内版本标签，分别恢复为原下载地址及校验值对应的 2.2.3、2.3.2；parse-json 的子依赖范围恢复上游的 ^2.3.0，已选择的 json-parse-even-better-errors 2.3.1 保持不变。均为锁文件元数据修正，不升级实际依赖。
- 本版业务源码与数据库迁移承接 v2.3.74，不增加功能或依赖，不修改已发布历史版本。实际验证、安装包与远端发布结果见安装包说明及根 PROJECT_MEMORY.md。
