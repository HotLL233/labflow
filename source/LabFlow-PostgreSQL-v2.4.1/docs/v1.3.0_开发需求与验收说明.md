# LabFlow v1.3.0 开发需求与验收说明

## 1. 版本隔离

- 基线版本为 `v1.2.0-alpha.15`；仅在 `LabFlow-PostgreSQL-v1.3.0-personnel-notification-source` 实施本需求。
- 不修改旧人员反馈接口、旧数据库表、样品登记、送样、分析检测、统计、用户和角色业务逻辑。
- 人员变动通知不新增数据库迁移，不写 PostgreSQL 业务表、站内通知表或审计表；仅只读用户及用户关联实验室。

## 2. 权限与页面

| 角色 | 发起通知 | 近 7 天记录 | 汇总表查看/导出 | 汇总表导入 | 审批 |
| --- | --- | --- | --- | --- | --- |
| 系统管理员 | 是 | 全部 | 是 | 是 | 是 |
| 分析检测组长 | 否 | 全部 | 是 | 是 | 是 |
| 研发送样组长 | 是 | 本人 | 是 | 否 | 否 |
| 其他角色 | 否 | 否 | 否 | 否 | 否 |

- 审批只能由系统管理员或分析检测组长执行，且不得审批本人发起的通知。
- 所有权限均在后端校验；前端仅作界面引导。

## 3. 独立数据与审批

- 汇总表固定为 `项目及人员汇总表.xlsx`，工作表优先使用“当前实验室人员统计表”。
- 固定列为：`实验室`、`实验室负责人`、`实验人员`、`实验室项目代号`、`检测方法`。
- 通知记录写入独立 JSONL 台账；默认显示最近 7 天。通知发起后状态为“待审批”。
- 审批通过时更新独立 Excel 汇总表，先在 `personnel-change-data/summary-history` 自动备份审批前文件，再生成标准五列表格。驳回不更新汇总表。
- 以上文件均位于 `PERSONNEL_CHANGE_DATA_DIR`；未配置时位于既有应用数据目录下的 `personnel-change-data`，不写入程序数据库。

## 4. 通知表单规则

默认类型：`员工加入`、`员工离职`、`实验室内人员调动`、`跨实验室人员调动`、`实验室新增项目`、`实验室新增方法`。类型配置保存在独立 `change-types.json`；兼容早期“新员工加入”名称并显示为“员工加入”。

- 系统管理员可选全部有效实验室；研发送样组长只能选本人关联实验室。
- 员工加入、员工离职、两类人员调动必须填写人员；新增项目和新增方法的人员可留空。
- 实验室内人员调动的项目下拉必须显示所选实验室全部项目，不得按该人员既有项目过滤。通过后所选项目成为该人员在本实验室的项目集合。
- 跨实验室人员调动不显示目标实验室、目标项目。选择项目时仅取消这些项目的人员关联；项目留空时取消该人员在当前实验室的全部项目关联。
- “实验室新增项目”只填写项目代号、检测方法和高新信息，不再填写新增项目名称；选择高新项目时高新项目名称必填。
- “实验室新增方法”必须选择现有项目并填写一个或多个方法。
- 新增项目、方法及员工加入在审批前均只通知；审批通过后才写入独立汇总表。

## 5. 样品信息登记回归

本版必须完成样品信息登记的组织筛选回归：启用部门、实验室、项目候选可用；新建、编辑、附件提交/补传/删除、退回与重新提交不回归。修复仅限样品信息组织筛选链路。

## 6. 打包验收

1. 执行 Rust 格式检查、编译及人员变动和样品登记相关测试。
2. 执行前端类型检查与生产构建，确认静态产物更新。
3. 完整服务器安装包必须包含程序、前端静态资源、PDF 运行时、PostgreSQL 运行时和 Microsoft 签名的 VC++ x64 运行库。
4. 安装器应识别残缺 PostgreSQL 运行时并补齐，已存在合格 VC++ 运行库时跳过安装；缺失时安装后再继续。
5. 热更新包不代替完整服务器安装包；首次部署或运行时损坏时必须使用完整服务器安装包。
