# v2.2.18 功能与压力测试报告

测试日期：2026-09-11  
测试版本：`2.2.18`（`/api/version` 返回 `2.2.18`）  
测试方式：实际 HTTP 页面/业务流程 + 隔离 PostgreSQL 场景 + 代码单元测试；没有把接口测试结果当作全部功能结果。

## 结论

自动化回归与构建已通过，注册入口已移除，导出测试已按当前统一固定列契约修正并通过。随后又按实际页面导航走查了全部主要业务页和全部可路由管理页，并完成了一次真实数据库备份。仍有少数需要专用角色、附件文件或独立新机的业务链路缺少完整证据，不能把“页面可打开”等同于“所有业务功能已验收”。

压力测试显示：

- 无数据库探活：50、100、200 并发全部成功；500 并发 496/500 成功；1000 并发 882/1000 成功。探活不是业务容量，只能说明 HTTP 层在当前测试机上的连接表现。
- 管理员登录：当前修复实例 200、500 并发均 100% 成功；1000 并发 732/1000 成功，268 个连接失败。
- 已登录用户列表查询：20、50、100 并发均成功，但约为 3.5 秒、7.9 秒、22.2 秒，延迟随数据库排队明显上升。
- 真实分析检测业务提交：20、50、100、200、500 并发分别 100% 成功；1000 并发 843/1000 成功（157 个连接失败，约 79.7 次/秒）。该场景使用隔离数据库中的真实项目、实验室、方法和页面创建的业务关系。

因此不能给出脱离部署规格的固定“最高在线人数”。在当前服务配置、默认连接池 12 和隔离数据量下，**已验证的稳定业务并发上限为 500 个同时提交请求**；1000 个同时提交开始出现 15.7% 连接失败。登录会话则 500 并发验证通过，1000 并发仅 732 成功。这里的压力结论针对软件服务真实 HTTP/数据库链路，不是本地电脑硬件理论值；正式部署还应按 CPU、磁盘、数据库规格和数据量复测。

## 高风险问题

### 1. 自助注册功能已移除

后端公开路由、处理函数，前端 `/register` 路由、页面和注册 API 已删除；保留管理员在用户管理中创建账号的能力。隔离实例未登录访问 `/register` 已实际落到 404。

### 2. 导出测试已全绿

原测试仍断言旧版按类型动态展开的表头；当前实现是统一固定列。测试已改为验证固定列、公式和不再生成“辅助工作数量”旧表头。

### 3. 公共辅助工作功能已从 2.2.18 入口移除

入口、配置页、前端 API 和后端路由已删除；旧导出数据读取保留兼容。统一 SPA fallback 已增加 `/api/*` 未知路径 404 分支，避免旧辅助工作 API 被返回 HTML 200。新安装机验收仍需执行。

### 4. 业务并发容量受连接池限制

默认 `db_pool_max_size = 12`。当前压力证据只能给出测试条件下的稳定区间，不能给出理论最大在线人数。正式压测应固定：CPU、内存、数据库磁盘、网络、数据量、请求混合比例和错误率阈值，并以 95/99 分位延迟和错误率定义容量。
