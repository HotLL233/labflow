## 3. 不可混淆的业务规则

### 3.1 实验室和部门

~~~text
送样实验室：样品由哪个实验室送入系统。
检测实验室：实际完成分析检测的业务位置。
检测部门：实际录入工作量的分析人员所属部门快照。
送样部门：本次记录对应送样实验室所属部门快照。
项目归属部门：项目主数据登记的归属部门快照。
~~~

项目归属部门不等于送样部门，送样部门不等于检测部门。统计和导出要使用明确列，不能继续把执行部门当作模糊字段。

### 3.2 公共账号

公共账号只用于登录入口和操作审计，不是实际业务人员：

1. 公共账号进入分析检测后，展示其绑定部门下拥有分析检测员或分析检测组长角色的人员卡片。
2. 不显示实验室卡片，不选择部门。
3. 点击人员姓名后，进入原来的常规工作量录入页面。
4. 取样、工作量、检测统计归属被选择的实际人员。
5. 审计日志保留公共账号作为操作账号，同时记录实际业务人员。

### 3.3 权限

最终校验只认后端：

~~~text
功能权限
+ 正式角色的数据来源部门范围
+ 历史归属快照
+ 当前状态可否操作
= 最终允许结果
~~~

前端隐藏按钮只是体验，不是权限边界。旧部门角色不能再叠加授权。

## 4. 角色与权限模型

正式使用流程：

~~~text
选择内置角色模板
-> 创建自定义角色
-> 调整功能权限
-> 配置该角色的数据来源部门范围
-> 给用户绑定正式角色
~~~

示例：

~~~text
角色名称：动保一部分析员
来源模板：分析员
分析检测数据来源部门：动保一部
~~~

这个角色只能看动保一部作为送样部门的数据。实际检测人员在分析中心，不会让此角色看到其他送样部门数据。

旧部门角色仅保留用于历史迁移核对和权限审计：

- 不新增、不修改、不启停、不再分配旧部门角色。
- 旧部门角色不授予分析检测、研发送样或样品信息登记数据范围。
- 旧绑定需逐步迁移为正式角色。
- 普通角色未配置正式数据来源部门时，不得默认放开全公司数据。

常用权限中文含义：

| 权限 | 作用 |
| --- | --- |
| 进入分析检测 | 进入分析检测门户，不代表看全部记录 |
| 录入本人工作量 | 录入当前实际人员的工作量 |
| 查看本人工作量 | 只查看本人记录 |
| 查看角色范围工作量 | 查看角色数据来源部门范围内记录 |
| 查看全部工作量 | 公司级查看全部分析数据 |
| 导出分析检测统计 | 在有统计查看权限的前提下下载报表 |
| 进入样品信息登记 | 查看和处理授权范围内登记记录 |
| 新建样品信息登记 | 新建登记记录 |
| 编辑本人样品登记 | 编辑本人且状态允许的记录 |
| 上传或删除样品附件 | 在数据范围和状态允许时修改附件 |
| 取样 | 对待取样记录执行取样 |
| 撤回取样 | 未完成检测时恢复为待取样 |
| 退回样品信息登记 | 退回并填写原因 |
| 确认退回样品信息登记 | 确认退回结果并生成待修改记录 |
| 编辑退回待修改记录 | 修改本人被退回的待修改记录 |
| 代确认并修改已退回记录 | 明确授权后代他人处理退回记录 |
| 管理用户与角色 | 管理用户、角色、模板、数据范围 |
| 管理部门与实验室 | 管理组织主数据 |
| 查看权限审计 | 查看用户、角色、范围、历史映射 |

功能权限和数据范围是两件事。拥有入口权限不等于拥有所有部门数据。

## 5. 分析统计和导出规则

每条工作量记录应可追溯：

| 维度 | 正确来源 |
| --- | --- |
| 检测人员 | 实际登录或公共账号选择的人员 |
| 检测部门 | 检测人员所属部门快照 |
| 送样实验室 | 本次选择的送样实验室 |
| 送样部门 | 送样实验室所属部门快照 |
| 项目归属部门 | 项目主数据归属快照 |
| 方法、检测类型、单价、倍率 | 主数据或录入时快照 |

金额公式：

~~~text
数量 × 方法单价快照 × 实际倍率
~~~

管理系数只用于管理分值统计，不能混入检测金额。

导出筛选核心为：

~~~text
检测部门：多选
送样部门：多选，来自所选检测部门实际处理过的数据
检测人员：可选
送样实验室：可选
日期、项目、方法、检测类型、仪器：按报表筛选
~~~

送样部门候选项是：

~~~text
选中检测部门实际处理过的送样部门
交集
当前角色允许的数据来源部门
~~~

全部只表示当前账号权限范围内的全部。预览、统计、明细和 Excel 导出必须使用同一套筛选和权限校验。

Excel 可以按选择输出多个 Sheet：检测记录明细、检测部门和送样部门汇总、检测人员汇总、送样部门汇总、送样实验室汇总、项目/方法/检测类型/仪器汇总，以及送样实验室-项目-方法对应表。

## 6. 历史版本记忆

### alpha.1 - alpha.2

- 从内置模板创建自定义角色，角色可独立增减模板权限。
- 用户部门关系曾增加主归属部门与可承担业务部门，兼容旧模型。
- 用户导入模板兼容旧表头。

### alpha.3 - alpha.8

- 分析、研发送样、样品登记保存项目、执行、提交等归属快照。
- 历史无法可靠判断归属的数据进入待确认治理。
- 正式角色的数据来源部门范围成为唯一业务授权来源。
- 旧部门角色降级为审计和迁移用途。
- 分析统计和导出按角色范围过滤。

### alpha.9 - alpha.10

- 普通角色无正式范围时不再默认看到全公司。
- 公共账号进入分析检测后选择实际人员。
- 公共账号工作量和取样归属实际人员。
- 修复方法多检测类型造成的导出重复风险。
- 导出筛选状态改为当前事务，避免连接池复用旧筛选。
- 新增代确认并修改已退回研发送样记录权限，默认不自动授权。

### alpha.11 - alpha.14

- 记住密码和保持登录拆分。
- 分析检测员/组长可进入样品信息登记查看授权范围记录，但不因此获得新建权限。
- 支持撤回取样。
- 完整安装和热更新均部署 pdf-runtime。
- 主数据导出/模板有序号列，序号只用于定位，不参与导入匹配。
- 项目关联中的仪器编号只是同名方法实例兼容识别字段，不是第二次建立项目-仪器关系。

### alpha.15

- 旧 PDF/Word 附件存储名无扩展名或异常时，结合原始文件名和 MIME 类型恢复预览。
- 旧的类型暂不支持预览失败缓存可自动重试。
- 未取样、本人可编辑的提交记录可以补传和删除附件。
- 已取样、已退回、已确认退回的普通提交人不得修改附件。
- 退回待修改记录继承原记录的部门、实验室、项目，页面不可编辑这些组织字段。
- PostgreSQL 送样通知可空部门参数改为显式 BIGINT 转换，避免事件卡在 processing。

## 12. 开发约束

1. 用户要求只改相关功能时，不做无关重构、依赖升级或目录清理。
2. 每个测试版独立源码目录，构建产物只在当前版本目录生成。
3. 每版同时提供完整安装包和双击热更新包，除非用户明确不需要。
4. 数据库迁移必须幂等，不能删除附件、历史记录或旧权限数据。
5. 权限必须由后端最终校验。
6. 公共账号保存操作账号和实际业务人员，业务归属实际人员。
7. 送样实验室、检测实验室、检测部门、送样部门、项目归属部门不能混用。
8. 全部只代表当前用户授权范围。
9. 旧附件、旧角色、旧导入表头、旧字段优先保持兼容。
10. 改状态流转时，同时检查列表按钮、详情按钮、后端接口和通知事件。
