# LabFlow v2.2.5 权限体系梳理文档（最终修正版）

## 业务流程说明

### 核心概念
- **送样** = 提交样品检测需求（有两种形式）
- **取样** = 检测人员接收样品开始检测
- **完成检测** = 检测人员标记样品检测完毕

### 三大门户业务流程

#### 1. 研发送样门户 (`entry:sample`)
- **使用人员**: 研发人员
- **性质**: **第一种送样形式** - 研发项目送样
- **主要功能**: 提交研发项目样品检测申请，查看送样记录
- **操作流程**: 研发人员填写送样信息 → 提交 → 检测人员取样 → 完成检测

#### 2. 样品信息登记门户 (`entry:sample-info`)
- **使用人员**: 需要登记特殊样品信息的人员（也是送样人）
- **性质**: **第二种送样形式** - 特殊样品信息登记送样
- **主要功能**: 登记特殊样品基础信息并送检
- **操作流程**: 填写样品详细信息 → 提交 → 检测人员取样 → 完成检测

#### 3. 分析检测门户 (`entry:workload`)
- **使用人员**: 检测人员
- **性质**: **检测人员工作门户**
- **主要功能**: 查看待检测样品、取样、登记工作量、完成检测
- **操作对象**: 可以处理来自研发送样和样品信息登记的样品
- **操作流程**: 查看待检测样品 → 取样 → 登记工作量 → 完成检测

**关键理解**: 
- 研发送样 和 样品信息登记 都是**送样人提交样品**
- 分析检测门户是**检测人员处理样品**
- 检测人员的取样操作权限（`sample:*` 和 `sample-info:*`）用于处理这两种送样

---

## 权限命名规范

权限点采用 `领域:动作` 或 `领域:子领域:动作` 的命名格式：
- `entry:xxx` - 门户入口权限
- `sample:xxx` - **检测人员对研发送样记录的取样操作权限**
- `sample-info:xxx` - **样品信息登记相关权限**（送样人创建 + 检测人员取样）
- `records:xxx` - 数据查看范围权限
- `manage:xxx` - 系统管理权限
- `stats:xxx` - 统计功能权限

| 权限点 | 当前标签 | 建议标签 | 门户性质 | 使用人员 |

| 权限点 | 当前标签 | 建议标签 | 执行人 | 操作说明 |
|--------|---------|---------|-------|----------|
| `sample:collect` | 研发送样-取样操作 | **分析检测-对研发送样取样** | 检测人员 | 在研发送样记录上点击"取样"，接收样品 |

| `sample:return` | 研发送样-退回操作 | **分析检测-退回研发送样** | 检测人员 | 将不合格研发送样退回给送样人 |
| `sample:complete` | 研发送样-完成检测 | **分析检测-完成研发送样检测** | 检测人员 | 标记研发送样检测完成 |

## 典型角色权限配置建议

### 1. 研发人员（研发送样）
**门户**: 研发送样
**推荐权限**:
- `entry:sample` - 访问研发送样门户
- `records:rd:edit-subject` - 编辑送样人为自己的记录
- `records:rd:return-confirm` - 处理被检测人员退回的送样

**不需要**: `sample:*` 权限（那是检测人员的取样权限）

### 2. 需要登记样品信息的送样人
**门户**: 样品信息登记
**推荐权限**:
- `entry:sample-info` - 访问样品信息登记门户
- `sample-info:create` - 创建样品信息送样记录
- `sample-info:edit-own` - 编辑自己创建的样品信息
- `sample-info:return-confirm` - 处理被退回的样品信息

**不需要**: `sample-info:collect`, `sample-info:complete` 等取样权限（那是检测人员的）

### 3. 检测人员（分析检测）
**门户**: 分析检测 + 研发送样（查看） + 样品信息登记（查看）
**推荐权限**:
- `entry:workload` - 访问分析检测门户
- `entry:sample` - 访问研发送样门户查看送样记录
- `entry:sample-info` - 访问样品信息门户查看样品信息
- `sample:collect` - 对研发送样取样
- `sample:complete` - 完成研发送样检测
- `sample:return` - 退回研发送样
- `sample-info:collect` - 对样品信息取样
- `sample-info:complete` - 完成样品信息检测
- `sample-info:return` - 退回样品信息
- `records:work:view-scope` - 查看本实验室工作量

### 4. 实验室负责人
**门户**: 全部三个门户
**推荐权限**:
- 所有门户入口权限
- 送样权限（研发送样 + 样品信息）
- 取样权限（检测人员权限）
- 数据查看范围：本实验室
- 统计查看权限

### 5. 系统管理员
**门户**: 全部
**推荐权限**:
- `*` - 超级管理员通配权限

## 权限标签优化建议

### 核心原则
明确区分**送样人操作**和**检测人员操作**

### 优化方案：在标签中添加操作主体前缀

```rust
// 送样人操作
label: "研发送样-创建记录"
label: "研发送样-编辑本人提交的"
label: "样品信息-创建送样记录"
label: "样品信息-编辑本人创建的"

// 检测人员操作
label: "分析检测-对研发送样取样"
```

1. 一眼看出操作主体（送样人 vs 检测人员）
2. 避免歧义：明确"取样"是检测人员的操作
3. 兼容性好：仅修改标签，不改 key

## 权限命名规范

权限点采用 `领域:动作` 或 `领域:子领域:动作` 的命名格式：
- `entry:xxx` - 门户入口权限
- `sample:xxx` - **取样相关操作权限**（检测人员在研发送样门户的操作）
- `sample-info:xxx` - 样品信息登记操作权限
- `records:xxx` - 数据查看范围权限
- `manage:xxx` - 系统管理权限
- `stats:xxx` - 统计功能权限

### 分析检测门户 - 在研发送样记录上的操作权限
**说明**: 这些权限控制检测人员在研发送样门户查看送样记录时的操作

| 权限点 | 当前标签 | 建议标签 | 适用门户 | 操作说明 |
|--------|---------|---------|----------|----------|
| `sample:collect` | 研发送样-取样操作 | **分析检测-取样操作** | 研发送样（查看） | 检测人员点击"取样"按钮，接收样品开始检测 |
| `sample:withdraw` | 研发送样-撤回取样 | **分析检测-撤回取样** | 研发送样（查看） | 检测人员撤回已取样状态 |
| `sample:return` | 研发送样-退回操作 | **分析检测-退回送样** | 研发送样（查看） | 检测人员将不合格样品退回给送样人 |
| `sample:complete` | 研发送样-完成检测 | **分析检测-完成检测** | 研发送样（查看） | 检测人员标记样品检测完成 |

**重要说明**: 虽然这些操作在研发送样门户的记录上执行，但执行人是**检测人员**，不是研发人员！

## 典型角色权限配置建议

### 1. 研发人员（送样人）
**门户**: 研发送样
**推荐权限**:
- `entry:sample` - 访问研发送样门户
- `records:rd:edit-subject` - 编辑送样人为自己的记录
- `records:rd:return-confirm` - 处理被检测人员退回的送样

**不需要**: `sample:collect`, `sample:complete` 等取样权限（这些是检测人员的权限）

### 2. 检测人员（分析检测）
**门户**: 分析检测 + 研发送样（查看送样记录并取样）
**推荐权限**:
- `entry:workload` - 访问分析检测门户
- `entry:sample` - 访问研发送样门户查看送样记录
- `sample:collect` - 在研发送样记录上点击"取样"
- `sample:complete` - 在研发送样记录上点击"完成检测"
- `sample:return` - 将不合格样品退回给送样人
- `records:work:view-scope` - 查看本实验室工作量

### 3. 实验室负责人
**门户**: 研发送样 + 分析检测
**推荐权限**:
- `entry:sample` + `entry:workload`
- `records:rd:view-lab` - 查看本实验室送样
- `records:work:view-scope` - 查看本实验室工作量
- `stats:workload:access` - 分析检测统计
- `stats:rd:access` - 研发送样统计
- `sample:collect` + `sample:complete` - 协助取样和完成检测

### 4. 系统管理员
**门户**: 全部
**推荐权限**:
- `*` - 超级管理员通配权限

### 5. 样品信息登记员
**门户**: 样品信息登记
**推荐权限**:
- `entry:sample-info` - 访问样品信息门户
- `sample-info:create` - 创建样品信息
- `sample-info:edit-own` - 编辑自己的记录
- `sample-info:collect` - 取样操作
- `sample-info:complete` - 完成检测

## 权限命名优化建议

### 当前存在的问题
1. **部分权限名称不够直观**：如 `records:rd:edit-subject` 不如 `研发送样-编辑送样人为本人的记录`
2. **门户归属不清晰**：`sample:collect` 出现在"门户入口"分组，但实际是"研发送样门户"的操作权限
3. **重复定义**：`sample:collect` 在代码中定义了两次（line 143 和 line 515）

### 优化方案

#### 方案 A: 在权限标签中添加门户前缀（推荐）
```rust
// 修改前
label: "取样操作"

// 修改后
label: "研发送样门户-取样操作"
label: "分析检测门户-查看全部实验室"
label: "样品信息门户-新建并提交"
```

**优点**: 不改变权限点 key，仅优化显示标签，兼容性好

#### 方案 B: 调整分组名称
```rust
// 将门户操作权限独立分组
group: "研发送样门户"
group: "分析检测门户"
group: "样品信息门户"
```

**优点**: 分组更清晰，前端可按门户展开权限树
