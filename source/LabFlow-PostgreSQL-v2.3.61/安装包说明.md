# LabFlow v2.3.61 安装包说明

- 完整包：`LabFlow-v2.3.61.exe`，用于首次部署。
- 热更新包：`LabFlow-v2.3.61-HotUpdate.exe`，用于已有完整安装后的升级。
- Windows 产品／文件版本：2.3.61.0。
- 本地留档：本版 `installer/`；CI 正式包：根 `installers/` 及 GitHub Release。
- Docker：`ghcr.io/hotll233/labflow:2.3.61` 与 `latest`；使用根 `docker-compose.deploy.yml`，Gitee 继续暂停。

本版修复人员变动查看与维护范围、逐条汇总维护、导入差异确认、稳定提交身份、审批版本校验和通知投递。人员汇总仍是独立业务基线，不自动改动程序账号、项目或方法主数据，也不重算历史工作量。

升级会执行一次人员权限与通知队列迁移。普通分析和实验室角色获得汇总查看默认权限，分析组长获得维护默认权限；管理员后续撤销的权限不会在重启时恢复。自定义角色仍由管理员在角色权限管理内按需授权。

变动日期是业务记录日期，不代表定时执行；审批通过时才更新汇总。历史申请若缺少可靠的创建人审计或相关基线，需要核对后修订，不能凭当前同名账号猜测身份。旧 PERSONNEL_CHANGE_WEBHOOK_URL 不再同步直发，请在通知中心配置渠道与规则；界面会提示旧配置仍然存在。

同一人员数据目录只供一个 LabFlow 服务实例写入。请通过页面维护或导入预览更新汇总，不要在服务运行时直接编辑 XLSX、JSONL 或恢复日志。损坏台账会明确报错并阻止继续操作，须先备份并核对原始文件；不能删除损坏行来绕过已审批记录。

验证完成：前端117项测试、类型检查、生产构建及gzip逐字节一致性通过；独立PostgreSQL后端最终全量256项通过、0失败，3项既有专用备份恢复测试按原配置跳过，兼容层10项通过。Rust fmt/check、默认非console Release及隔离Release HTTP265项检查通过（人员专项164项、工作量与统计回归101项），覆盖权限范围、稳定身份、自审批与并发拒绝、汇总维护与导入、恢复日志、真实模拟渠道失败与补发，以及既有取样／系数／工作量归属／统计／Excel。不操作生产数据库或现场8000服务，不发送真实业务通知。

本版验证已完成；完整包、热更新包及GitHub/GHCR发布核验进行中，尚未标记正式发布。
