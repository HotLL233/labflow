# 分析数据导出与检测送样部门权限改造方案

## 1. 结论

当前分析数据导出把执行部门、项目归属部门、实验室和送样来源混在了一起。特别是现有“执行部门”由工作量记录选择的实验室分组写入；而实验室卡片在现行业务中表示送样实验室，因此该字段不能作为实际检测部门使用。

后续分析数据统一按两个维度统计：

```text
检测部门：实际执行检测的分析人员所属部门
送样部门：本次检测记录对应送样实验室所属部门
```

角色决定用户能操作哪些功能，以及能查看哪些送样部门的数据；检测部门是记录事实和统计筛选维度，两者不能混用。

## 2. 当前实现与问题

### 2.1 当前页面筛选

检测人记录和统计页面目前包含：日期、统计口径、部门筛选、历史数据、检测人等条件。

- 统计口径可选“执行部门”或“项目归属部门”。
- 部门筛选只能选择一个部门。
- 导出 Excel 默认生成整套报表，而非由用户选择需导出的报表。

### 2.2 当前数据含义问题

工作量记录当前把所选实验室分组及其部门写入 `execution_group_id`、`execution_division_id` 等字段。由于工作量门户中的卡片业务含义已经是送样实验室，现有“执行部门”实际可能是送样实验室所属部门，而不是检测人员真正所在的检测部门。

项目归属部门也不等于送样部门：项目可归属于一个部门，但实际送样实验室、协作部门和检测人员所属部门可能不同。因此不应再让用户在“执行部门 / 项目归属部门”之间切换来决定分析统计归属。

### 2.3 当前权限问题

现有分析数据范围会把角色数据范围与旧部门角色范围合并，容易产生范围扩大。旧逻辑在范围未配置时还会保留兼容性的不限范围行为。

后续应取消部门角色作为授权来源，只以正式角色配置的数据来源部门范围控制分析数据访问。

## 3. 分析记录的标准归属

每条分析工作量记录必须固化以下快照字段：

| 字段 | 取值规则 | 用途 |
| --- | --- | --- |
| 检测人员 | 实际录入工作量的分析人员 | 人员工作量统计 |
| 检测部门 | 实际检测人员的所属部门 | 检测部门筛选和统计 |
| 送样实验室 | 本次工作量对应的送样实验室 | 实验室统计 |
| 送样部门 | 送样实验室所属部门 | 部门工作量和检测成本统计 |
| 项目归属部门 | 项目主数据归属 | 项目管理辅助维度，不作为默认分析归属 |

规则如下：

1. 公共账号进入分析检测后，必须先选择实际分析人员。
2. 工作量记录归属该实际分析人员，不能归属公共账号。
3. 检测部门取该实际分析人员的所属部门快照。
4. 送样部门取本次选择送样实验室的所属部门快照。
5. 项目、方法、检测类型、单价、默认倍率均由主数据带出；实际倍率允许按实际情况修改，并保存到记录。
6. 检测金额统一为：`数量 × 方法单价快照 × 实际倍率`。
7. 管理系数如需保留，只用于管理分值类统计，不能和检测金额混算。

## 4. 新筛选规则

删除现有：

```text
统计口径：执行部门 / 项目归属部门
部门筛选：单选
```

替换为：

```text
检测部门：多选
送样部门：多选，随检测部门联动
检测人员：多选或单选
送样实验室：多选
项目、方法、检测类型、仪器：按报表需要提供
```

筛选逻辑：

```text
当前角色允许的送样部门范围
    -> 当前用户可查看的分析记录
    -> 从这些记录中生成检测部门候选项
    -> 选择一个或多个检测部门
    -> 列出这些检测部门处理过的送样部门
    -> 再选择一个或多个送样部门
    -> 预览或导出对应记录
```

“全部”永远表示当前用户有权查看的全部数据，不表示公司全部数据。

### 示例

分析中心人员处理过动保一部、研究院、动保二部的送样。

当用户选择：

```text
检测部门：分析中心
送样部门：动保一部、研究院
```

导出结果只包含分析中心人员为动保一部和研究院完成的检测记录。

## 5. 角色与导出权限

正式角色使用“模板创建角色 + 数据来源部门范围”的方式，例如：

```text
角色名称：动保一部分析员
来源模板：分析员
数据来源部门：动保一部
```

其中“数据来源部门”明确表示：该角色可以处理、查看、统计和导出的送样部门范围。

建议导出权限拆分为：

| 权限 | 可见数据 |
| --- | --- |
| 查看本人分析记录 | 仅本人录入的工作量记录 |
| 查看角色数据范围统计 | 角色数据来源部门内的分析记录 |
| 导出角色数据范围统计 | 下载角色数据范围内的报表 |
| 查看全部分析统计 | 公司级权限，可查看公司全部分析数据 |

服务端必须强制校验：

```text
记录的送样部门必须位于当前用户正式角色允许的数据来源部门内。
```

前端下拉框仅展示当前用户有权访问的候选项；后端仍必须重复校验，防止手工构造接口参数越权导出。

送样部门候选项规则：

```text
已选检测部门实际处理过的送样部门
交集
当前用户角色允许的数据来源部门
```

## 6. 导出内容改造

不再固定每次导出全部 11 张表。新增“导出内容”多选项：

| 导出表 | 内容 |
| --- | --- |
| 检测记录明细 | 检测部门、送样部门、送样实验室、项目、方法、数量、金额、检测人员 |
| 检测部门-送样部门汇总 | 哪个检测部门为哪个送样部门完成了多少检测、金额多少 |
| 检测人员汇总 | 人员在筛选范围内的数量、金额、管理分值 |
| 送样部门汇总 | 每个送样部门的检测数量、金额 |
| 送样实验室汇总 | 每个送样实验室的检测数量、金额 |
| 项目、方法、检测类型、仪器汇总 | 按相应维度汇总 |
| 送样实验室-项目-方法对应表 | 主数据与实际记录的对应核对表 |

导出规则：

1. 勾选一个报表，导出一个 Sheet。
2. 勾选多个报表，在同一个 Excel 中导出多个 Sheet。
3. 选择“全部报表”，导出全部已启用且有权限的报表。
4. 同一个 Excel 内所有 Sheet 必须使用同一套筛选条件。
5. 现有报表先保留并逐步按新归属模型重命名，避免历史使用习惯突然中断。

## 7. 页面设计

筛选栏调整为：

```text
[开始日期] [结束日期]
[检测部门：全部可见检测部门]
[送样部门：根据检测部门联动]
[检测人员：全部]
[更多筛选]
[重置]                                      [导出 Excel]
```

- 检测部门、送样部门使用可搜索的多选下拉框。
- 选择后的部门以可删除标签显示。
- 未选择检测部门时，送样部门默认仅展示当前有权查看的候选项；界面应提示优先选择检测部门，以保持统计范围清晰。
- 点击“导出 Excel”后弹出报表选择窗口，默认勾选“检测记录明细”和“检测部门-送样部门汇总”。

## 8. 历史数据迁移

历史 `work_records` 中的 `execution_division_id` 不能直接视为检测部门，因为它历史上来自实验室分组。

迁移规则：

| 历史记录情况 | 处理方式 |
| --- | --- |
| 可依据实际检测人员确定唯一所属部门 | 回填检测部门快照 |
| 可依据送样实验室确定部门 | 回填送样部门快照 |
| 人员或部门关系无法确认 | 标记为待确认历史记录 |

待确认历史记录默认不进入正式检测部门统计。管理员在数据治理页面确认后，记录才会纳入正式报表，避免历史推断错误污染数据。

## 9. 实施范围

- `frontend/src/pages/StatsPage.tsx`：替换筛选栏、增加检测部门与送样部门联动、增加导出内容选择。
- `src/api/export_handler.rs`：支持多选筛选条件和按报表选择导出。
- `src/api/export_preview_handler.rs`：预览查询与正式导出使用同一权限及筛选规则。
- `src/api/export_data.rs`：查询统一按检测部门和送样部门进行过滤、分组和汇总。
- `src/repo/record_repo.rs`：创建或修改分析记录时写入正确的检测部门、送样部门快照。
- `src/service/authz_service.rs`：移除旧部门角色对分析数据范围的叠加影响，仅以正式角色的数据来源部门范围授权。
- 数据库迁移：新增检测部门、送样部门快照字段以及历史确认状态。

## 10. 验收标准

1. 分析公共账号选择实际人员后，记录检测人员和检测部门均为被选择人员，不是公共账号。
2. 同一检测部门处理多个送样部门的数据时，可通过“检测部门 -> 送样部门”准确筛选。
3. 角色只勾选动保一部数据来源部门时，页面候选项、预览接口、Excel 导出均不得出现其他送样部门数据。
4. 可多选检测部门和送样部门，导出结果与页面预览数量、金额一致。
5. 选择一个报表只生成该 Sheet；选择全部报表生成全部已授权 Sheet。
6. 历史待确认记录不会混入正式检测部门统计。
