# LabFlow v2.3.65：恢复后台颜色自定义配置

本版在 v2.3.64「三类业务色统一」的基础上，**按用户要求恢复管理后台的颜色自定义配置**。v2.3.64 曾把三类业务卡片的自由拾色全部收进「业务分类」预设，本版重新放行自由色值，并明确优先级：**自由色值 > 业务预设 > 内置兜底**。记录表排版、移动端结构、导航结构均未改动；Rust 后端零改动。

一、恢复的三处颜色自定义（管理后台）

1. 首页入口卡片（管理 → 首页）
   - 恢复「渐变背景」「边框色」「标题色」三组配置（拾色器 + 十六进制输入），与 v2.3.63 的表单结构一致。
   - 「业务分类」下拉保留，定位改为**一键预设**：切换分类时把该业务的达标三色（渐变 `soft→line`、边框/标题取 main）填入上述三个字段，之后以手动色值为准。
   - 加载旧配置时自动补齐缺失色值（只存了 business 的 v2.3.64 配置按预设填满），保证表单可编辑、渲染不空。

2. 统计卡片样式（管理 → 统计）
   - 恢复每张卡的「颜色」（拾色器 + hex）与「渐变背景」输入。
   - `StatsCards.tsx` 的 `applyVariantCards` 改为**配置优先**：配置里填了色值就以配置为准，该字段留空才回落业务预设（工作量 = 分析检测色，研发送样 = 研发送样色）。
   - 顺带修正一处死配置：v2.3.63/v2.3.64 里 `applyVariantCards` 曾用内置值整体覆盖配置，导致管理页填的**显示名同样不生效**；本版起显示名也以配置为准，留空才回落内置名。

3. 样品信息类型（管理 → 样品信息）
   - 恢复「颜色色值」输入框（带色块预览）。DB 字段 `color` 与前后接口在 v2.3.64 期间一直保留，本版只是恢复前台入口，无数据迁移。

二、渲染优先级规则（唯一口径）

- 首页入口卡：`card.gradient / border / titleColor` 任一字段有值即优先使用；三个字段逐个独立判断，缺哪个回落哪个业务预设值（`HomePage.tsx`）。
- 统计卡：`stats-cards` 配置中 `color / gradient / label` 有值即优先；留空回落 `variantCards` 业务预设（`StatsCards.tsx`）。
- 业务预设色值仍由 `constants/designTokens.ts` 的 `BUSINESS_COLORS` 唯一给出，未新建第二套色源。

三、类型与注释同步

- `types/index.ts`：`HomeCard` 的 `gradient / border / titleColor` 注释从「兼容回退」改为「自由配色，优先于 business 预设」。
- `constants/designTokens.ts`：文件头注释改为「预设 + 自由色值并存，冲突时以自由色值为准」。
- `ManagePage.tsx` 新增模块级辅助 `homeCardPreset()` / `normalizeHomeCards()`，预设三色与 HomePage 兜底渲染同源，避免两处各写一份。

四、未改动项（隔离声明）

- `recordTableStyle.ts`、`recordTableLayout.ts`、`mobileCardStyles.ts`、`TableStyleBar.tsx`、`useRecordTableStyle.ts`、`Layout.tsx` 与 v2.3.64 逐字节一致，记录表排版与移动端未动。
- v2.3.64 移除的 `portal-styles` 死代码读取（无保存入口）未恢复。
- `#2e7d32` 品牌色/「已完成」状态色语义混用、品牌名「样品管理系统／知微」并存两项历史遗留未处理。
- 版本隔离：从 v2.3.64 复制新建本目录，排除 `target`、`frontend/node_modules`、`installer`、旧 `backend/static`；junction 按既有方式手工建立（依赖池沿用 v2.3.63/64 的 `65c5464…`，package-lock 未变故哈希一致、无需重装依赖）。
