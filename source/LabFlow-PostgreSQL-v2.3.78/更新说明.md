# LabFlow v2.3.78 更新说明

## 钉钉群内定向 @ 提醒

- “系统管理 → 通知中心”新增钉钉身份绑定面板，以本程序账号 ID 关联其钉钉绑定手机号；改名不影响关联，留空保存解除绑定。列表脱敏显示，有通知管理权限的账号可维护，普通用户接口不返回手机号；绑定更新与不含号码的审计记录在同一事务保存。
- 通知规则增加“不 @”“@ 指定人员”“跟随本规则实际站内接收人”三种方式，沿用实验室、项目、检测类型、事件的原匹配与优先级。指定名单须为已绑定且有效的账号；跟随模式继续使用原业务权限校验后的接收人，不改变站内通知或记录查看权限。
- 同一事件命中同一群渠道的有效规则，只发送一次并合并、去重 @ 名单；不同群分别计算。发送参数使用 atMobiles，正文附带对应标记，明确 isAtAll=false，不新增群发全员选项。
- 发送时按当前账号状态和手机号绑定解析；停用、删除或解除绑定的账号不再 @，业务群消息仍发送，发送记录说明未 @ 的账号。手机号不写入发送响应摘要或错误信息。不同账号绑定同一号码时按号码去重。
- 研发送样驳回仍只发群消息，不产生站内通知；可独立指定 @ 人员，不能跟随空的站内接收人。人员变动审批结果跟随模式保留原有发起人和详情权限边界。
- 新增手动“测试 @ 提醒”，明确选择渠道与人员后才发送；保留原无 @ 渠道测试。接口接受消息不代表现场成员实际收到提醒，需要管理员与群成员共同验收。

## 兼容与交付

旧规则迁移后默认不 @，未配置名单时发送载荷保持原样；原 Webhook、加签、模板、自定义字段、规则、站内通知、取样已读、租约及重试机制保留。成功渠道不因其他渠道失败而重复发送，也不自动补发历史已发送通知。

新增 2.3.78-dingtalk-mentions 迁移，只增加手机号关联表与两项规则配置，不修改业务记录和工作量、系数、金额。承接 v2.3.77 历史辅助关联及全部既有功能；不新增依赖，不修改已发布版本源码。

最终验证、构建产物与两类本地安装包以本版《安装包说明.md》及根 test-artifacts/v2.3.78/ 中的报告为准。开发阶段仅使用隔离测试库和本地模拟机器人，不发送真实群消息、不操作生产数据库或8000服务。升级前备份数据库、附件及配置，回退须恢复升级前数据库。
