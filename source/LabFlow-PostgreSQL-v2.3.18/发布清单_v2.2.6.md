## 主要更新内容

### 权限标签优化

**优化目标**: 明确权限所属门户和操作主体，提升权限管理界面可读性。

#### 1. 门户入口权限
- `entry:sample`: 研发送样 → **研发送样门户**
- `entry:workload`: 分析检测 → **分析检测门户**
- `entry:sample-info`: 样品信息登记 → **样品信息登记门户**

#### 2. 送样人操作权限
- `sample-info:create`: 样品信息登记-新建并提交 → **样品信息送样-创建送样记录**
- `sample-info:edit-own`: 样品信息登记-编辑本人记录 → **样品信息送样-编辑本人记录**
- `sample-info:return-confirm`: 确认并处理本人相关的样品登记退回 → **样品信息送样-确认并处理退回**
- `records:rd:edit-created`: 编辑本人提交的研发送样记录 → **研发送样-编辑本人提交的记录**
- `records:rd:edit-subject`: 编辑本人作为送样人的研发送样记录 → **研发送样-编辑本人作为送样人的记录**
- `records:rd:return-confirm`: 确认并处理本人相关的送样驳回 → **研发送样-确认并处理退回**

#### 3. 检测人员操作权限
- `sample:collect`: 研发送样-取样操作 → **分析检测-对研发送样取样**
- `sample:withdraw`: 研发送样-撤回取样 → **分析检测-撤回研发送样取样**
- `sample:return`: 研发送样-退回操作 → **分析检测-退回研发送样**
- `sample:complete`: 研发送样-完成检测 → **分析检测-完成研发送样检测**
- `sample-info:collect`: 样品信息-取样操作 → **分析检测-对样品信息取样**
- `sample-info:withdraw`: 样品信息-撤回取样 → **分析检测-撤回样品信息取样**
- `sample-info:return`: 样品信息-退回操作 → **分析检测-退回样品信息**
- `sample-info:complete`: 样品信息-完成检测 → **分析检测-完成样品信息检测**

### 代码优化
- 删除 `src/models/role.rs` 中重复的权限定义（`sample:collect/return/complete`）
- 前后端权限定义保持一致

## 优化效果

### 优化前
- 权限名称无法一眼看出所属门户
- `sample:*` 标签为"研发送样-XXX"，但实际是检测人员操作
- 容易混淆送样和检测操作

### 优化后
- 所有权限标签以门户名称开头
- 通过标签前缀即可判断操作主体：
  - `研发送样门户` / `研发送样-` → 送样人在研发送样门户
  - `样品信息送样-` → 送样人在样品信息登记门户
  - `分析检测-` → 检测人员在分析检测门户
- 业务流程清晰对应

## 升级步骤

### 使用热更新包升级（推荐 v2.2.x 用户）
1. 备份数据（可选但推荐）
2. 关闭正在运行的样品管理系统
3. 运行热更新包安装程序
4. 安装程序自动检测并升级到已安装目录
5. 启动系统验证

### 使用完整安装包升级
1. 备份数据（强烈推荐）
2. 关闭正在运行的样品管理系统
3. 运行完整安装包
4. 选择覆盖安装到现有目录
5. 启动系统验证

## 验证方法

### 显示验证
1. 打开 系统管理 → 角色管理
2. 查看权限矩阵中的权限标签
3. 确认标签格式为 `门户名称-操作说明`

### 功能验证
1. 创建测试角色并分配权限
2. 使用测试账号登录
3. 验证三个门户的访问权限
4. 验证送样、取样、检测操作权限
