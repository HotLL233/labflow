# 历史辅助关联迁移与系数复核方案

调查日期：2026-10-29。代码基线：已发布 v2.3.75。本文保留v2.3.75的只读调查依据，v2.3.77已据此实现迁移和诊断功能，实际开发验证见本版安装包说明。现场数据库尚未自动迁移、关联或重算，业务修改须管理员分别预览确认。

## 1. 问题与代码事实

| 问题 | 已确认机制 | 尚需核对的现场事实 |
| --- | --- | --- |
| 完整覆盖被旧辅助项目、方法引用阻止 | 完整覆盖会永久删除普通主数据中 Excel 未列的对象；历史 work_records、rd_work_records 等引用会阻止整批导入 | 每个遗漏实体的引用数量、状态、是否确属旧辅助 |
| 已新增独立辅助事项，旧记录未自动归入 | A-编号用于独立事项身份；现有迁移未建立旧方法记录到新事项的关联 | 每个旧方法或旧记录应关联哪个新事项，是否存在同名歧义 |
| 汇总仍显示系数20，修正预览为0条 | 汇总按历史快照显示；修正只检查 work_records 中关联未软删方法且系数不相等的行 | 原 method_id、绑定方法当前系数及删除状态，是否更新了同名的另一个方法 |

源码依据：

- `src/api/master_import_handler.rs:3293`：历史引用预检；`:4221`：遗漏普通实体的永久删除；`:4378`：方法稳定身份优先定位。
- `src/api/workload_report_handler.rs:340`：统一统计联合 work_records 与 auxiliary_work_records；`:353`：历史名称与系数快照。
- `src/api/export_data.rs:331`：明确来源链接去重；`:340`：旧辅助判定的快照及当前方法分类回退。
- `src/api/data_governance_handler.rs:115`：修正查询的 INNER JOIN 和过滤；`:659`：确认时的锁、指纹及事务。
- `src/api/rd_record_handler.rs:991`：取样生成 source_type=rd_sample 的 work_records，属于修正范围。

不能因为汇总显示“水分”就认定它与本次修改的方法是同一个对象。2026-10-08 位于截图查询范围2026-09-30至2026-10-29的中间，普通时区偏移不足以解释三条记录全部遗漏。

## 2. 现有版本可用的处理

1. 从当前系统导出，保留稳定识别字段，选择“更新/新增（保留未列数据）”。“仅新增（跳过已有）”不更新已有系数。
2. 旧辅助方法停用、旧辅助项目归档；旧实验室若不再用于其他业务，可关闭工作量、研发、样品三个门户显示。原主数据及历史外键保留。
3. 不删除业务历史、不清空 method_id/project_id/group_id、不把旧记录直接换成同名新对象来绕过保护。软删方法会使其退出现有系数预览，优先使用停用。
4. 无分类快照的旧辅助可能读取当前方法分类；退役时保留旧辅助分类及关联，避免改变历史统计类别。

完整覆盖的现行定义不能悄悄改成保留。若需要导入后退役遗漏，应另设明确的“更新并退役遗漏（保留历史）”，预览区分退役与永久删除；原完整覆盖保护继续保留。

## 3. 推荐关联迁移，保留原计量事实

增加历史辅助关联，以“来源表 + 原记录主键”为唯一身份，关联新辅助事项。旧方法身份用于生成候选，最终覆盖明确的原记录。程序内部携带精确事项身份，页面显示名称、区域、分类、系数及原业务号核对，不展示事项编号。

| 内容 | 规则 |
| --- | --- |
| 原记录和引用 | 保留原行、主键、业务号、外键；关联成功不能用于永久删除仍被引用的旧字典 |
| 人员、部门、时间、数量、系数 | 保留原值，不按今天账号归属或当前事项系数回填 |
| 新事项 | 显式关联，不按名称自动合并；多候选及缺失身份进入待核对清单 |
| 区域和分类 | 标明为本次关联归类，未知历史不由当前配置冒充当时快照 |
| 来源链 | 保留 source_type/source_record_id，尤其 rd_sample 链和累计数量约束 |
| 计量 | 原事实行只计一次，不复制第二份 auxiliary_work_records |
| 维护 | 初期关联历史只读，跳回原入口，沿用原权限和仓储校验 |
| 审计和撤销 | 保存批次、原行指纹、关联前后值、依据、操作人时间；撤销本批关联，不覆盖后续编辑 |

同一送样父记录可能分批生成多条工作量。rd_work_records 是送样台账，不能按方法名字再生成辅助工作量。须核对明确的 rd_sample 子记录，不能按姓名、日期、数量相似推断重复。

管理员流程：选择旧辅助范围 → 核对原记录与推荐事项 → 确认歧义 → 预览人员和日期的数量及原工作量 → 提交选定批次 → 留存对账和撤销入口。提交锁定核验指纹，同批冲突整体拒绝；唯一来源键保证重跑不重复，已关联其他事项不能静默覆盖。

## 4. 统计、金额及权限

- 人员汇总继续读原记录“数量 × 原系数”，确认关联后归入新事项键，保留原来源追溯。
- 新旧辅助均不分配实验室、项目、仪器或金额。原归属和金额依据只作追溯；旧报表若曾计入辅助金额，口径修正应单列差异，不能声称所有旧维度总数完全不变。
- 分析工作量汇总已排除旧辅助的实验室／金额分配；`rd_export_data.rs:444`、`:495` 的研发金额分支仍需补齐确认旧辅助的排除，不能按同名普通检测方法扩大排除范围。
- 页面、各 Excel、分类钻取和辅助记录页共用关联判定，避免页面和导出分成两个事项。
- 原 work_records 和独立辅助的部门授权回退不同，关联不能扩大原查看、编辑和导出范围；未知历史部门不按今天归属猜测。
- 无分类快照且方法有多分类的旧记录，部分原始导出会 JOIN 展开；对账应以原事实记录为基线，不能只依赖一张可能展开的旧导出。

## 5. 系数预览遗漏的诊断与修正

现有预览按原 method_id 连接方法，排除已软删记录、已软删方法、明确独立辅助来源和系数相等的行。仅方法停用、门户隐藏、项目解绑或仪器停用不会单独被该查询排除。

这里对辅助的排除仅检查 `source_type='auxiliary_work'`。以前借用普通方法录入的旧辅助，若仍关联有效方法且有系数差异，也可能进入当前普通方法修正清单。因此应先确认旧辅助身份，再分流复核，不能把“全选普通方法差异”当作旧辅助迁移；新诊断需统一采用显式关联和旧辅助判定。

截图三条先只读核对：method_id 是否为空；绑定方法是否存在／软删；该对象当前系数是否仍为20；是否调整了同名另一方法；原工作量日期及快照值。空方法身份可能是自定义，也可能是旧数据未关联，不能一律称为自定义。

若同一有效工作记录的未软删绑定方法系数已非20，快照仍为20，且处于截图时间范围、关键词为空，现SQL应计入差异。未经上述数据核对，不能认定修正接口失效。

最小新增能力是“全扫描诊断”，与“可修正差异”分开：

| 状态 | 处理 |
| --- | --- |
| 有效关联且系数不同 | 进入现有选择、原因和确认修正 |
| 有效关联且相等 | 显示一致结果，不计入差异 |
| 方法停用 | 显示状态，仍按明确关联核对差异 |
| 方法软删或失联 | 显示排除原因，管理员核对后另行处理 |
| 明确自定义 | 保留快照，不按名称强制匹配 |
| 未关联且身份未知 | 管理员选择精确目标，单独预览并审计关联变化 |
| 独立辅助／已关联旧辅助 | 按事项身份单列，不混用普通方法系数 |
| 系数或日期异常 | 列异常清单，禁止错误值批量写入 |

关联修正和系数修正分开。先确定身份，再显示“原系数 → 当前系数”和工作量差额，由管理员选定确认。参数调整可能只应影响以后，不能自动套到所有历史日期。

有效标准方法差异复用现有10分钟管理员签名、行锁、完整指纹、每批最多100条事务和逐条审计。后续批失败时已成功批保留，不承诺跨批全体回滚；结果不确定须重新预览，不自动重试。需补偿时根据原审计并核验后续修改生成反向差异，不直接以旧备份覆盖新业务。

## 6. 验收与执行顺序

1. 隔离库恢复备份，先生成只读诊断和映射候选，不操作生产服务。
2. 对账原记录数、数量及人员／日期的“数量 × 原系数”，关联时保持一致；辅助金额／实验室口径调整另列差异。
3. 验证一源多次取样、跨表同主键、同名不同身份、零系数、未知部门、删除恢复和普通账号范围。
4. 验证重复提交、指纹变化、批次撤销与后续编辑冲突。
5. 核对页面、分类钻取和各类 Excel 无重复或权限扩大，再单独预览系数修正。
6. 现场执行前备份数据库、附件和配置，留存批次结果，保留原记录和原主数据身份。

## v2.3.77 已实现的执行入口

1. 管理员进入“系统管理 → 业务数据管理”，分别查看“历史辅助关联迁移”和“历史系数全量诊断”。
2. 旧辅助选择日期及关键词查询，明确选择独立事项，跨页每批最多100条；预览数量、原系数与工作量对账，填写原因后确认。
3. 批次列表可预览撤销，源记录变动或后续关联冲突时拒绝撤销；撤销保留原计量与旧辅助证据，避免退回检测金额。
4. 辅助历史列表显示已关联原记录，仅“查看原记录”；按原实验室、人员及部门授权精确定位，不附带默认今日限制。不在新辅助表复制或覆盖这些历史行。
5. 系数诊断区分所有排除原因，必要时先选择标准方法并预览确认关联。关联预览还显示旧/新单价、原倍率及预计金额差额，缺失显示未知；方法维度和金额报表可能变化，不能把工作量快照保持等同于所有金额不变。
6. 关联完成重新诊断，再用原“历史工作量系数修正”预览和确认选中的系数。诊断与差异预览统一时区日期范围，不对辅助或自定义自动套方法系数。

当前只对work_records计量事实建立关联，rd_work_records保留为送样来源，不新增父行计量。原方法/项目/实验室引用继续保留，完整覆盖无法借关联解除删除保护。可选的新导入模式未新增，现有merge加停用/归档即可保留历史。
