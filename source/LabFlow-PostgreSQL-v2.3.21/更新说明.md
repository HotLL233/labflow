# LabFlow v2.3.21 更新说明

发布日期：2026-09-23

## 一、本次修复：研发送样记录列宽被压到 20~30px（v2.3.20 引入的缺陷）

### 现象

安装 v2.3.20 后，研发送样记录表的所有列被压缩到 20~30px：表头文字逐字竖排
（「序号」「送样人」「检测类型」各占一列宽），行高被内容撑到数百像素，
一屏只能看到一条记录，并出现了本不该有的横向滚动条。

### 根因（两处叠加）

1. `useContainerWidth` 用 `useEffect(..., [])` 读取 `ref.current`。研发送样页在加载态会
   提前 `return <CircularProgress/>`，此时表格尚未渲染 → 首次读到 `null` →
   该 effect 直接退出且**之后永远不会重新绑定** → 容器宽度恒为 0。
   列宽引擎因此走「无容器宽度」分支，按自然宽比例输出百分比；而自然宽被长文本列的
   上限（注意事项 / 方法 / 批号 240px）拉高，短列的占比被摊薄到约 2.5%
   （1360px × 2.5% ≈ 27px），于是表头逐字竖排。
2. 表头的选择列是硬编码 `width: 40`，未纳入列宽引擎，使
   `Σ列宽百分比 = 100%` 之外再叠加 40px，产生横向滚动条。

### 修复

- `useContainerWidth` 改为 **callback ref**：元素挂载 / 卸载时重新绑定，
  页面从加载态切到表格后立即测量到真实宽度。
- 列宽引擎在容器宽度未知时，用视口宽度估算（`max(720, innerWidth - 320)`）作为兜底，
  不再退化成「按自然宽比例」的极端分配。
- 研发送样记录的选择列纳入列宽引擎（`_select`，固定 40px），
  让百分比总和覆盖全部列，消除额外 40px 溢出。

### 影响范围

仅前端 3 个文件：

- `frontend/src/components/recordTable/columnLayoutHooks.tsx`
- `frontend/src/utils/recordTableLayout.ts`
- `frontend/src/pages/RdRecordsPage.tsx`

后端与数据库无改动。v2.3.20 的迁移（`2.3.20-column-width-mode`）不受影响，
已升级过的库不需要重复迁移。

## 二、v2.3.20 内容回顾

v2.3.20 的记录表列宽改版仍然有效，本版只修正上述渲染缺陷：

- 列宽四级模型：④ 本机覆盖（拖拽，localStorage）＞ ③ 管理员 `custom` 固定宽
  ＞ ② 内容测量 ＞ ① 系统默认区间；
- 长文本列改为最多两行展示，去掉单元格内嵌滚动条；
- 操作列收纳（受 `record_table_action_mode` 控制）；
- 表格配置三项接通记录表（`row_height` / `seq_column_width` / `checkbox_column_width`）。

## 三、验证结果

- 前端 `npm run build`（`tsc` + `vite build`）：通过，产物写入 `backend/static`
  （仅既有的大 chunk 警告）。
- 后端与 v2.3.20 完全一致（本版未改动），沿用 v2.3.20 的
  `cargo check --locked` 与 `cargo build --release --locked` 通过结果。
- `cargo test --locked --lib` 仍因本机未配置 `WORKLOAD_TEST_DATABASE_URL` 无法运行
  （与 v2.3.19 / v2.3.20 同环境行为一致）。
