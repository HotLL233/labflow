# LabFlow v2.3.33 更新说明

发布日期：2026-10-01

## 一、本次修复：记录页卡顿

### 排查结论

卡顿不是接口慢，也不是样式计算慢，而是**页面上有几棵「隐藏但仍在完整渲染」的重树**。
CSS 的 `display: none` 只是不显示，React 依然会把里面每条记录、每个单元格、每个按钮
完整创建一遍，MUI 也照样为它们计算样式。记录页刷新时这是最大的一笔无谓开销。

### 1. 样品信息登记页：底部历史记录表

- 文件：`frontend/src/pages/SampleInfoEntry.tsx`
- 现象：页面底部那张「登记记录」表长期 `display: none`，但每次渲染都会把
  当前页全部记录 × 全部列完整构建一遍（含展开行、附件、分页）。
- 处理：改用 `LEGACY_RECORD_TABLE_ENABLED = false` 控制，直接不渲染（代码保留，
  需要回看历史实现时把开关打开即可）。

### 2. 研发送样登记页：桌面录入表

- 文件：`frontend/src/pages/SampleEntryPage.tsx`
- 同样的隐藏重树，处理方式同上（`LEGACY_ENTRY_TABLE_ENABLED`）。

### 3. 研发送样记录页：窄屏卡片列表

- 文件：`frontend/src/pages/RdRecordsPage.tsx`
- 现象：卡片列表用 `display: { xs: 'grid', lg: 'none' }` 隐藏，但桌面端仍在渲染，
  里面每个字段还带筛选按钮（Tooltip + IconButton + Menu），一页 20 条 × 十余字段
  就是上千个组件。
- 处理：改用 `useMediaQuery` 判断，只有窄屏才渲染（与 v2.3.31 样品信息登记记录页改法一致）。

### 4. 每进入一次记录页就多一次整页重渲染

- 文件：`frontend/src/components/recordTable/useRecordTableStyle.ts`
- 现象：样式控制器里有一个「全局样式是否加载完成」的状态，接口返回后必然触发一次
  状态更新，于是整页（含所有记录行）被多渲染一遍；而绝大多数环境根本没有配置全局样式。
- 处理：去掉这个状态，样式来源直接由规格推断。没有全局配置时回落到默认对象的同一个引用，
  React 直接跳过重渲染。

### 5. 顺带修掉一个每页行数不生效的问题

- 文件：`frontend/src/pages/RdRecordsPage.tsx`
- 现象：`loadRecords` 的依赖里漏了 `pageSize`，导致在「表格样式 → 分页」里改了每页行数后，
  请求仍按旧的条数发出（要等排序变化才会生效）。
- 处理：把 `pageSize` 加进依赖。

## 二、安装包

- 完整安装包：`installer/LabFlow-v2.3.33.exe`
- 热更新包：`installer/LabFlow-v2.3.33-HotUpdate.exe`

安装后需要重启服务（热更新包会停止服务，重启托盘或服务即可）。

## 三、如果仍然觉得卡

本次已经摘掉了明确的浪费，剩下的开销主要来自「单元格数量 × MUI 组件数量」这个基数。
若仍不理想，下一步可以按顺序做：

1. 把记录行抽成 `React.memo` 组件，避免无关状态变化时整表重渲染；
2. 表格容器加 `scrollbar-gutter: stable`，避免滚动条出现/消失导致列宽反复重算；
3. 单页行数调小（如 20），或对超长列表启用虚拟滚动。

另外，若方便的话，用浏览器 F12 → Performance 录一段「点取样 → 响应」的火焰图，
可以直接定位到具体是哪个组件在耗时，比继续推测更准。
